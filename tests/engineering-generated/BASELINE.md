## ★ C1 根因（已确认 · 闭式判据）

`calcs/riser.js:109` 的 `modOk = Mr_act >= Mr_need*0.99` 作用在**已取整的 D** 上。
对 cyl/sphere/square（hd=1），记 `x = 6·Mc·f`、`n = ⌊x⌋`、`t = x − n`：

```
modOk ⟺ round(x) ≥ 0.99x  ⟺  { t ≥ 0.5 } ∪ { t ≤ n/99 }
```
⇒ 接受与否是**小数部分 t 的抽签**；输了就在死区里让 `f` 一直 `+0.05` 走到 t 越过 0.5。
**走多少步 = (0.5 − t₀)/frac(0.3·Mc)**，是 Mc 的近奇异函数 ⇒ `D` 与其非单调。
锯齿消失阈值 **Mc ≥ 50/6.6 = 7.5758**（这解析地解释并修正了 V2.0-09 经验观察的「Mc < 7.58」）。

- 复现：Mc 3.37 → D=47（走 25 步）；Mc 3.38 → D=37（走 15 步）。

- **材料完全无影响**（5 种材料逐位相同）—— 迭代式只用形状函数，不含材料量。

## ★★ 本阶段确立的两条工程规则

### 规则 1：**状态 ≠ 归因** —— 新增状态字段时必须显式导出，不得让消费方从归因反推

V2.0-15 之前，`runRiser` **不导出 `converged`**，而未收敛的唯一信号是 `bind === 'limit'`。
`bind` 回答的是「**搜索为什么必须前进**」，是**归因**；「这是不是收敛解」是**状态**。
所有消费方都在**用一个归因标签反推状态** ⇒ 一处措辞错（原文案称"模数也不满足"，实际 89% 是满足的）就四处错。

**做法**：`calcs/riser.js` 导出 `converged: boolean`（= 循环里那个局部变量的原值，**不新增计算**）；

### 规则 2：**新增字段必须假设消费方拿到的是旧对象**

`typeof r.converged === 'boolean' ? r.converged : r.bind !== 'limit'`
—— **缺字段时回退到既有推断**。禁止写 `if (!r.converged)`（旧结果 `undefined` 落入 falsy 会**误判为未收敛**）。
既无 `converged` 又无 `bind` 时（测试构造的假数据）⇔ **保持沉默**，不凭空下结论。

## ★★ 三条从此适用的规则

### 规则 1：**两条判据口径不同 —— 体积判据没有 `0.99`**

```
modOk ⟺ Mr_act ≥ Mr_need × 0.99     ← 有 1% 松弛
volOk ⟺ effV   ≥ needVol            ← **无松弛**
```
**反证已入库**（脚本 A3）：构造 `effV/needVol = 0.3996` 时 `volOk === false`。
⇒ **`D_req` 推导中不得引入 `0.99`**，也不得把 `modOk` 的松弛习惯平移过来。

### 规则 2：**`cw = 0` 是"结构性短路"，不是"算术上恰好成立"**

`riser.js:193` `const volOk = cw > 0 ? effV >= needVol : true;`
—— `cw>0` 为假时 **直接把 `volOk` 钉成 `true`**，而不是让 `effV >= 0` 自然为真。
**两者在 `cw < 0` 时行为完全不同**：负重量会让整条体积判据**静默消失**（见规则 3）。
⇒ `D_req` 在 `cw=0` 时必须返回**「不适用」**（沿用 `yieldPct` 的 `null` 先例），**不得返回 0**。

### 规则 3：★ **`D_req` 应走"精确整数扫描"，而非直接用闭式**

程序的 `D` 是**整数**、`H = round(D·hd)`（且 `sphere_head` 还会把 `H` 夹到 `≥ r`）。
闭式 `D_req = ∛(needVol/(eff·k))` 假设 `H = hd·D` 是实数关系。
**96 组对照**：`D_req_int == ceil(D_req)` **89 组** · `== ceil−1` **7 组** · **`>` 的 0 组**。
⇒ **闭式从不低估需求（安全方向），但会差 1mm** ⇒ 只能作参考，`value` 应给整数扫描结果。

### 规则 2：**`if (!obj[key])` 不是存在性判定 —— 打表要先 `hasOwnProperty`**

### 规则 3：**"守卫写在下一行"等于没写 —— 先看上一行有没有把它架空**

**报告**：`docs/PHASE_V2.0-19_DREQ.md` ｜ **命令文件**：`新建 文本文档 (130).txt`

**测试基线**：**800/1 → 823/1**（`823 = 800 + 23`，**引入失败 0**），退出码仍 **1**（唯一失败是历史 `phase24 T5`）。

> **D_req 是满足当前算法体积约束所需的理论直径，不是保证实际铸件不产生缩孔或缩松的工程保证。**

## ★ 模块回答什么问题（以及**不**回答什么）

体积约束逐字为（`calcs/riser.js:213-216`）：
`Vc = cw × 1e6 / rhoUsed` · `volOk ⟺ Vr × eff ≥ Vc × shrink`。
★ **式子里没有 Mc** ⇒ `D_req` 与热节模数无关，模块**不接收** `mc`/`mc_mode`（传了也忽略，`F3` 断言）。
★ `cw ≤ 0` 时那条 `cw > 0 ? … : true` 是**结构性短路** ⇒ 返回 **`not_applicable`**，
**绝不**返回一个"看起来满足"的小直径。

## ★★ 最关键的裁决：由整数 D 求 H 取**哪一条**规则

`calcs/riser.js` 里有**两条**"由直径得高度"的规则，**不是同一个函数**：

| | 位置 | 表达式 | H 的来源 |
|---|---|---|---|
| ① 主路径 | `:189-190` | `d = round(raw); h = round(raw × hdR)` | **连续** raw |
| ② 升档路径 | `:196`（V2.0-13 C′） | `d += 1; h = round(d × hdR)` | **整数** d |

**探针实测**（`_probe19_geom.mjs` P4，120 个收敛样本）：`ΔH ∈ {−1, 0, +1}`，分布 `−1:12 / 0:103 / +1:5`。
**本模块取 ②**，因为 ① 依赖 `raw = sd.DfromM(Mr, hd)` ⇒ **依赖 Mc**，而 D_req 的定义里没有 Mc；
② 是现有代码里**唯一**"由整数直径求 H"的规则，也是项目**已经采纳**的口径。
★ 后果已实测（`E3`）：384 组里 runRiser 采纳的 D 在 ② 口径下**不满足**体积约束的 **0 个**。

## ★ 单调性：`V(D)` 对整数 D **不减**（二分路径的唯一依赖）

- `sphere`：`πD³/6`，平凡。`cyl`：`(π/4)·D²·round(D·hd)`，两个非负非减因子之积 ⇒ 非减。`square` 同。
- `sphere_head`：分三情形（`H ≤ r` / `H > r 且 H' ≤ r'` / 其余）。第三情形
  `V(D+1) − V(D) ≥ π[r²/2 − 1/24] ≥ 0 ⟺ D ≥ 1`。证明见报告 §6.1。
- **实测**：168,000 点（4 形状 × 14 hd × D=1..3000），**0 违反**；另有模块前的探针 120,000 点，0 违反。

## ★ 搜索上界必须**有依据**（§4.3.6 禁止"未经说明的工程上限"）

`sphere π/6` · `sphere_head ≥ πD³/12`（**无条件**，Hc ≤ 0 时恰为半球）·
`cyl/square`：`D·hd ≥ 0.5 ⇒ round(D·hd) ≥ 1 ⇒ V ≥ πD²/4`（或 `D²`）。
⇒ `D_hi` 见报告 §5.2。**实测** 728 个 `(形状, hd, A)` 组合：`V(D_hi) ≥ A` **0 例外**。
★ 上界可能极大（`hd=1e-6 ⇒ 5e5`），但**二分只需 ~19 步** —— 这就是二分路径存在的理由。
`scan` 与 `bisect` 两条路径**只影响速度，不影响结果**，且都要过同一组终检（`satisfies(D) && !satisfies(D−1)`）。

## ★ 「连续解向上取整」**不是**可靠做法 —— 实测证据

120 组样本：`ceil(continuous) == D_req` 的 **115（95.8%）**，**4 组偏大、1 组偏小**（`gap` 最小 −0.316 / 最大 +1.081）。
