> 建立于 PHASE V2.0-16（`docs/PHASE_V2.0-16_BOUNDARY_AND_BENCHMARK.md`）。
> 目的：为「冒口计算结果是否具有真实工程适用性」积累**可追溯的真实案例**。

## 0. 先说清楚：这是什么，不是什么

| | |
|---|---|
| ✅ 这是 | 一张**空的记录表** —— 用来把**已经发生的**真实生产/试制案例登记下来 |

## 1. 文件

| 文件 | 用途 |
|---|---|
| `cases.csv` | 记录表本体，一行 = 一个案例。UTF-8 **带 BOM**，Excel 双击可直接正确显示中文 |

## 2. 字段总表

「必填」列的含义：`必` = 没有它这条记录没有意义；`空` = 允许留空（留空时请在 `missing_data` 里写明缺什么）。

### A. 案例身份

| 字段 | 必填 | 单位/取值 | 说明 |
|---|---|---|---|
| `case_id` | 必 | 文本 | 唯一编号。建议 `YYYYMMDD-序号`，如 `20260315-01` |
| `casting_name` | 必 | 文本 | 铸件名称/图号/产品代号，能对上图纸或工艺卡 |
| `material` | 必 | 文本 | 牌号，如 `QT500-7`。**写牌号，不要只写"球铁"** |
| `source` | 必 | 文本 | 数据出处：工艺卡号 / 检验单号 / 试制报告文件名。**能查到原件** |
| `date` | 必 | `YYYY-MM-DD` | 生产或验证日期（不是录入日期） |
| `data_quality` | 空 | `A`/`B`/`C` | 字段完整度，见 §4 |

### B. 铸件信息

| 字段 | 必填 | 单位/取值 | 说明 |
|---|---|---|---|
| `casting_mass_kg` | 必 | kg | **铸件净重**（不含浇冒口）。软件里 `cast_wt` 用的是这个 |
| `Mc_mm` | 必 | mm | 热节模数 |
| `Mc_source` | 必 | 文本 | **Mc 是怎么来的**：`软件计算` / `模数法手算` / `图纸壁厚÷2` / `经验估算`。**必须写，否则 Mc 无法复现** |
| `geometry_notes` | 空 | 文本 | 关键几何与热节位置：最厚壁厚、热节在哪、有无冷铁/内浇口位置影响 |

### C. 实际冒口与工艺（**生产实际用的**，不是软件算的）

| 字段 | 必填 | 单位/取值 | 说明 |
|---|---|---|---|
| `riser_shape` | 必 | 见下 | `圆柱形` / `球顶圆柱` / `球形` / `正方柱` / `其他:说明` |
| `actual_D_mm` | 必 | mm | **实际**冒口直径（图纸或现场实测）。未知留空 |
| `actual_H_mm` | 必 | mm | **实际**冒口高度 |
| `actual_hd` | 空 | 数值 | `actual_H_mm / actual_D_mm`；可留空由前两列计算 |
| `riser_type` | 空 | 文本 | `明冒口` / `暗冒口` / `发热保温` / `保温` / `大气压力` 等 |
| `process_notes` | 空 | 文本 | 造型方式（砂型/金属型/覆砂）、浇注温度、冷铁、砂芯 |
| `gating_or_feeding_notes` | 空 | 文本 | 浇注系统与补缩通道：内浇口位置/尺寸、冒口颈、是否侧冒口 |

> **`actual_*` 与 `calculated_*` 是两组不同的东西，任何时候都不要互相顶替填写。**
> 如果生产实际就是照软件结果开的模，请在 `comparison_notes` 里写明「实际尺寸取自软件输出」，
> `actual_*` 仍照实填。

### D. 生产结果（**真实世界发生了什么**）

| 字段 | 必填 | 单位/取值 | 说明 |
|---|---|---|---|
| `production_status` | 必 | 见下 | `已生产` / `试制` / `未生产` / `仅方案` |
| `shrinkage_evidence` | 必 | 见下 | `有:说明` / `未发现:检测方式` / `未检测` / `未知` |
| `inspection_method` | 空 | 文本 | `X光` / `UT` / `解剖` / `加工后目视` / `无` |
| `inspection_result` | 空 | 文本 | 检测的**原文结论**，不要加工成"合格/不合格"了事 |
| `process_changes` | 空 | 文本 | 生产中是否改过工艺（改了什么、为什么） |
| `repeatability` | 空 | 见下 | `单件` / `重复N批一致` / `重复N批不一致:说明` |

> `shrinkage_evidence` **必须区分"查过没有"和"没查"**：
> `未发现:解剖3件均无` 与 `未检测` 是完全不同的两件事。**严禁把"没检测"写成"未发现"。**

| `modOk` | 空 | `是`/`否` | **算法内部**模数约束是否通过 |
| `volOk` | 空 | `是`/`否` | **算法内部**体积约束是否通过 |
| `bind` | 空 | `start`/`modulus`/`volume`/`both`/`limit` | **归因**：尺寸被哪条约束顶上去的。`limit` = 撞上限未收敛 |

## 3. `input_parameters` 写法

分号分隔的 `键=值`，键用软件内部的参数名：

```
mc_mode=direct;mc=5.2;shape=cyl;mat=球铁;cast_wt=77.56;hd_ratio=1.0
```

### 3.1 全部 12 个入参（**逐项对照 `calcs/riser.js` 实测**，PHASE V2.0-21 补齐）

冒口计算实际接受 **12 个**输入键。下表是**完整**清单 —— 少登记一个，那条案例就复现不出来。

| 键 | 单位 | 含义 | 何时需要 | 未提供时 | 非法时 |
|---|---|---|---|---|---|
| `mc_mode` | 枚举 | Mc 的输入方式：`direct` / `hot_spot` / `wall` / `volume` | **必填** | 算不出冒口 | 未知取值同"未提供" |
| `mc` | mm | 热节模数 Mc（`mc_mode=direct` 时直接给） | `mc_mode=direct` 时必填 | 算不出冒口 | 见 §3.3 |
| `hot_d` | mm | 热节圆直径 d，`Mc = d / 2` | `mc_mode=hot_spot` 时必填 | 算不出冒口 | 见 §3.3 |
| `wall_t` | mm | 壁厚 t（板状），`Mc = t / 2` | `mc_mode=wall` 时必填 | 算不出冒口 | 见 §3.3 |
| `cast_v` | mm³ | 热节处体积 V，`Mc = V / A` | `mc_mode=volume` 时必填（与 `cast_a` 成对） | 算不出冒口 | 见 §3.3 |
| `cast_a` | mm² | 热节处表面积 A | 同上 | 算不出冒口 | 见 §3.3 |
| `mat` | 枚举 | 材料键：`灰铁` / `球铁` / `铸钢` / `铝合金` / `铜合金` | 可选 | 回退 `球铁`，并在结果里标 `mdFellBack` | 同"未提供"（回退并标记，**不**拒算） |
| `shape` | 枚举 | 冒口形状：`cyl` / `sphere_head` / `sphere` / `square` | **必填** | 算不出冒口 | 算不出冒口 |
| `hd_ratio` | 无量纲 | 冒口高径比 H/D（界面选项 0.8 / 1.0 / 1.2 / 1.5） | 可选 | **1.0** | 见 §3.3 |
| `eff` | % | 冒口补缩效率（**百分数**，如 `25` 表示 25%） | 可选 | 按 `shape` 取表值，见 §3.2 | 见 §3.3 |
| `cast_wt` | kg | **铸件净重**（体积校核的对象；与 B 组 `casting_mass_kg` 应一致） | 可选 | **0 ⇒ 体积校核不启用** | 见 §3.3 |
| `rho` | g/cm³ | **固态密度**（不是液态密度） | 可选 | 按 `mat` 取表值：灰铁 7.0 / 球铁 7.1 / 铸钢 7.8 / 铝合金 2.7 / 铜合金 8.4 | 见 §3.3 |

> "**算不出冒口**" = `runRiser` 返回 `null`，界面显示"输入无效 / — 未计算"。
> **这一类案例没有 `calculated_*` 可填，不要为了凑字段编一个数。**

> ⚠ **`rho` 与 `eff` 是"可选但会影响结果"的两个键。**
> 只写 `mat` 而不写 `rho`，复现时用的是**材料表值**；若当时在项目里手改过固态密度，
> **不写 `rho` 就复现不出来**（设计中心只在用户覆盖过固态密度时才传 `rho`）。

### 3.2 `eff` 的缺省值按**形状**取（不是按材料）

| 冒口形状 | `shape` 键 | 取的效率项 | 表值 |
|---|---|---|---|
| 圆柱形 | `cyl` | `eff_open` 明顶圆柱/方柱 | **14 %** |
| 正方柱 | `square` | `eff_open` 明顶圆柱/方柱 | **14 %** |
| 球形 | `sphere` | `eff_blind` 暗侧圆柱 | **20 %** |
| 球顶圆柱 | `sphere_head` | `eff_sph` 球顶柱暗冒口 | **25 %** |

- 另一个表值 `eff_heat`（发热保温，35%）**不是任何形状的缺省**，只能靠显式 `eff=` 覆盖。
- 独立计算器界面有**四个**效率输入框，但**只有与当前 `shape` 对应的那一个会进入计算**。
  改别的框不影响结果 —— 记案例时别把"界面上的数字"当成"实际用的数字"。

### 3.3 三态：**未提供 / 非法 / 合法**，以及一处**宽松解析**

`calcs/riser.js`（PHASE V2.0-18 起）对输入是**三态**的，不是"空就用默认值"这么简单：

| 状态 | 判定 | 效果 |
|---|---|---|
| **未提供** | `undefined` / `null` / **空串** | 有默认值的用默认值；没有的（`mc_mode`/`shape`/`mc` 一族）**算不出冒口** |
| **非法** | `±Infinity` / 非空非数值字符串 / 越界数值 | **算不出冒口**（绝不悄悄换成默认值） |
| **合法** | 有限数值且在区间内 | 参与计算 |

★ **一处必须知道的例外 —— `mc` 一族走的是"宽松"解析**：

- `mc` / `hot_d` / `wall_t` / `cast_v` / `cast_a` 由 `calcMc` 用 `parseFloat` 读取。
  `parseFloat` **会忽略尾部垃圾**：`mc=12mm` 会被读成 **12**；`mc=abc` 读成 0（算不出冒口）；
  **空串也读成 0（算不出冒口），不是"未提供"**。
- 其余键（`hd_ratio` / `eff` / `cast_wt` / `rho`）用**严格**解析：`12mm` 直接判非法。
  **空串算"未提供"**（用默认值）。

⇒ **记录时一律写纯数字，不要带单位。** `mc=5.2` 而不是 `mc=5.2mm`。

★ **`cast_wt` 的 `NaN` 不算"未提供"**（它会**拒算**），这是有意的：
`cast_wt` 的缺省值本身就会关掉整条体积校核，若把 `NaN` 也算"未提供"，
等于绕个弯把"意外关闭体积校核"重新放进来。 ⇒ **写 `cast_wt=0` 才是明确的"不做体积校核"。**

★ **`mat` 写错不拒算，只回退**（回退球铁 + 标记 `mdFellBack`）。
如果一条案例的材料写错了，**它是能算出数来的**，但那个数用的是球铁的密度和收缩率 —— 记案例时留意。

### 3.4 三个入口**实际送进来的键不一样**（记案例前先看这一条）

| 入口 | 实际入参 | 备注 |
|---|---|---|
| **设计中心**（`calc/calcManifest.js`） | `mat, cast_wt, mc_mode='direct', mc, shape, hd_ratio=1.0, eff=undefined, rho?` | `hd_ratio` **硬编码 1.0**；`eff` 恒缺省；`rho` 仅在用户覆盖过固态密度时传 |
| **独立计算器**（`views/riserView.js`） | 12 个键里除 `rho` 外的 11 个 | `eff` **总是显式传**（读界面上对应形状的那个框） |
| **向导**（`views/wizard.js`） | `mat, cast_wt, mc_mode='direct', mc, shape, hd_ratio, eff=undefined` | 三种 Mc 方式在**界面内先换算成 `mc`**，再统一按 `direct` 传 ⇒ **`hot_d` / `wall_t` 不会出现在入参里** |

> ⚠ **记 `input_parameters` 时要写"实际送进 `runRiser` 的那一组"，不是"界面上填过的那一组"。**
> 典型误记：向导里选了"热节圆直径 d = 24"，实际入参应是 `mc_mode=direct;mc=12`。
> 复现时若照着界面写 `hot_d=24`，算出来一样 —— 但**记录与实现就对不上了**，
> 将来换版本会让复现失败而找不到原因。

## 4. 可信度与证据等级

### 4.1 等级速览（**先看这张表**）

| 等级 | 一句话 | 必备 |
|---|---|---|
| **L1** | 关键输入 + 实际冒口尺寸 + 生产记录 + **可靠检测结果**，四样齐全 | 有检测报告 / 解剖记录（X光、UT、切片照片、探伤单），且 `source` 能查到原件 |
| **L2** | 有**部分真实工艺数据**，但**缺检测结果或其他关键证据** | 有生产文件（工艺卡 / 检验单 / 合格证 / 台账），无专门缺陷检测 |
| **L3** | **参考性历史资料或不完整数据** | 口述、现场回忆、师傅判断，无书面原件 |
| （L4） | **推测** —— 允许录入，但**只能当线索**，不能支持任何工程结论 | 内容明确写成 `推测:` |

> 下面是**操作性定义**，填表时以它为准。L1 的**四样缺任何一样就降级**：
> 缺检测结果 ⇒ L2；只记得"当时用的 ⌀120，没缩孔"这种片段 ⇒ L3；凭经验觉得没问题 ⇒ L4。

### 4.2 四条硬规则（PHASE V2.0-21 追加）

1. **人工参数扫描和模拟数据不得计入真实铸件验证数量。**
   本表只登记**已经发生的**真实生产 / 试制案例。软件内部跑出来的参数组合
   （4 形状 × 若干 hd × 若干 cw × 若干 Mc —— 哪怕几千组）是**实验**，不是**案例**：
   **不进这张表，也不进任何"已验证案例数"**。
   内部实验的出处是 `tests/experiments/`，与本表**分开统计，不得相加**。

2. **同一铸件的多个热结不能未经区分地视为多个独立铸件案例。**
   一个件有 3 个热结 ⇒ 它是 **1 个**铸件案例。若确需分热结记录，必须在 `case_id` 上
   体现同源（如 `20260315-01a` / `-01b`）并在 `missing_data` 写明，
   **不得**让统计口径把一个件算成 3 件。

3. **缺陷位置是事实记录，不是缺陷原因结论。**
   `shrinkage_evidence` 里写"缩孔在冒口颈下方 / 在法兰根部"是**观察**；
   写"因为冒口太小所以缩孔"是**判断**。判断必须写成 `推测:<内容>` 并标 `evidence_level=L4`。

4. **只有满足相应证据要求的案例才能支持对应级别的工程结论。**
   只有 `L1` 能用于回答"冒口是否真的够用"；`L2` 只能说明"生产出来了"；
   `L3`/`L4` 只能作为线索。**用低等级案例去支持高等级结论，是这张表最容易被误用的方式。**

---

**`data_quality`（这张表填得全不全）**

| 值 | 含义 |
|---|---|
| `A` | A~F 组关键字段齐全，`source` 可追溯到原件 |
| `B` | 案例身份 + 铸件信息 + 实际冒口齐全，生产结果或软件结果有一块缺失 |
| `C` | 仅有零星字段（例如只记得"当时用的 ⌀120 冒口，没缩孔"） |

**`evidence_level`（这条记录有多少真实成分）**

| 值 | 含义 |
|---|---|
| `L1` | **四样齐全**：① 关键输入（`Mc_mm` + `Mc_source` + `casting_mass_kg`）② 实际冒口尺寸（`actual_D_mm` / `actual_H_mm`）③ 生产记录（`production_status` + `source` 可查到原件）④ **可靠检测结果**（X光 / UT / 切片照片 / 探伤单）。**缺任何一样降到 L2** |
| `L2` | 有**部分真实工艺数据**（生产文件：工艺卡、检验单、合格证、生产台账），但**缺检测结果或其他关键证据** |
| `L3` | **参考性历史资料或不完整数据** —— **口述或经验记录**（现场回忆、师傅判断），无书面原件 |
| `L4` | **推测**（"按经验应该没问题"）—— 允许录入，但内容须写成 `推测:<内容>` 且必须标 L4 |

> **只有 `L1` 能用于回答"冒口是否真的够用"。**
> `L2` 只能说明"生产出来了"，`L3`/`L4` 只能作为线索。
> ⚠ PHASE V2.0-21 把 `L1` 从"有检测报告"**收紧**为"四样齐全"——
> 只有检测结论、却不知道当时用的 `Mc` 或实际冒口尺寸的，**不算 L1**（降到 L2）。

## 5. 填写硬规则

1. **实际 ≠ 计算。** `actual_*` 填现场/图纸真实值，`calculated_*` 填软件输出值。两者相同也要各填一遍。
2. **检测结果 ≠ 软件判定。** `inspection_result` 是检测报告怎么说；`modOk`/`volOk` 是软件怎么判。**不得用后者代替前者。**
3. **"没检测" ≠ "没缺陷"。** 没做过检测就填 `未检测`，不要填 `未发现`。
4. **"生产成功" ≠ "软件算法正确"。** 生产出来了可能因为：工艺余量、冷铁、浇温高、运气。请在 `validation_notes` 里说明你**排除了哪些其他解释**，排除不了的就写"无法区分"。
5. **分清事实与推测。** 推测内容统一写成 `推测:<内容>`，并标 `evidence_level=L4`。
6. **不要编。** 记不清的字段**留空**，在 `missing_data` 写明。**宁可一行只有 5 个字段，也不要凑数。**
7. **不要删列、不要改列名。** 需要新字段时加到最后一列，并在本文件 §2 登记。
8. **不要合并单元格。** 一行一案例，CSV 不支持合并。

## 7. Excel / 文本编辑器注意事项

- **Excel 保存时选「CSV UTF-8（逗号分隔）」**。若选成普通「CSV（逗号分隔）」，中文会被存成 GBK，
  其他工具读出来是乱码。本文件已带 BOM，是为此准备的。
- 单元格内容里**含逗号、分号、换行**时，Excel 会自动用双引号包起来 —— 这是正常的，不用手工处理。
  但**不要手工删引号**。
- 内容里的双引号请写成两个（`""`），这是 CSV 的转义方式。
- 只想用文本编辑器也行：**一行一案例，列之间用英文逗号**，别用制表符或中文逗号。
- **改完跑一遍校验脚本**（PHASE V2.0-21 新增，只读，不写任何文件）：

```bash
node scripts/validate_benchmark.mjs
```

它做三件事：① 核对 §3 的 12 个键与 `calcs/riser.js` **实际入参**是否逐项吻合
（键名集合、单位列非空、正则有自测）；② 用 **80 条行为探针**实测
「未提供 / 非法 / 合法」三态，确认本文档的说法与代码一致；
③ 校验 `cases.csv` 的列结构、BOM、必填列、`case_id` 去重、`evidence_level` 取值。

> ⚠ **别再用 `split(',')` 那种一行命令数列数。** Excel 在单元格内容含**逗号**时
> 会自动加引号（§7 上一条就是这么写的），`split(',')` 会把 `"壁厚 8, 热节在下部"`
> 拆成两格 ⇒ **列数算出来是错的，而它看起来"只是多了一列"**。
> 校验脚本用的是**能处理引号的 CSV 解析**，真实案例一进来也不会误报。
> 它同时是 `tests/phasev2021_test.mjs` 的被测对象 —— 会随全量回归一起跑。

## 8. 拿到第一条记录之后做什么

1. 先看 `evidence_level`：只有 `L1` 才能进入"验证"讨论，`L2`~`L4` 只作线索。
2. 把 `actual_D_mm` 与 `calculated_D_mm` 摆在一起 —— 这是唯一的客观对照点。
3. **不要**因为几件没缩孔就宣布算法正确（见 §5 规则 4）。
   要回答 U-1，需要的是**反向案例**：真实缩孔件 + 软件的 `modOk/volOk` 判定，看两者是否矛盾。
4. 真正有信息量的是**矛盾样本**：
   - 软件说"够"（`modOk`+`volOk` 都过）但**实际缩孔** ⇒ 说明模型偏乐观；
   - 软件说"不够"（`limit`）但**实际没问题** ⇒ 说明模型偏保守。
   两类都要记，两类都同样有价值。
