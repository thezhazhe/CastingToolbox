# 内浇口流速问题分析与自动优化方案（讨论稿）

> 用途：供咨询专业铸造工程师。问题由内浇口流速超标准触发（用户观察到流速"变大"，以灰铁为例），
> 需要确认标准口径与自动优化方案的工程合理性。数据基于 Casting Toolbox 当前实现实测。

---

## 一、结论摘要（先看这 3 条）

1. **内浇口流速不是"算错了变大"，而是奥赞-伯努利体系的固有理论值**：
   当内浇口截面积恰好等于参考（阻流）面积时，流速恒等于 `√(2gHp)×fv ≈ 0.14×fv×√Hp`（Hp 单位 mm），
   **与浇注重量 G、浇注时间 t、材料密度无关**（数据验证：47.txt 改公式前后 v 几乎不变，1.62→1.55 m/s）。
   顶注 Hp≈240~290mm 时理论流速 1.74~1.91 m/s——这本身超过企业审核上限 1.5 m/s。

2. **超限工况集中在"顶注 + 封闭式"**（实测 23/72 工况超限，全部为顶注；中注/底注理论流速
   0.8~1.3 m/s 不超）。原因：顶注 fv=0.8 且 Hp 最高 → 理论流速最大。

3. **你提出的"自动放大内浇口来控速"在物理上是自洽的正确方向**：放大内浇口不改变阻流处（直浇道）
   的流量，浇注时间不变、无死循环；内浇口角色从"阻流控制"变为"控速"，系统自然向半开放漂移。
   但需要先确定**标准流速表**（材料 × 目标值 × 单位）与**校核参照面**两个口径。

## 二、内浇口流速的计算公式（现状实现）

### 2.1 直接公式（`calcs/gating.js calc_v`）

```
v = 10 × G / (t × ρ × F / 100)     [m/s]
```

| 符号 | 含义 | 单位 |
|---|---|---|
| G | 浇注重量 = 单件毛重 × 一模件数 ÷ 出品率 | kg |
| t | 浇注时间（PHASE 47 材料分派公式算出） | s |
| ρ | 液态金属密度（灰铁 7.0 等，企业经验值） | kg/dm³ |
| F | **内浇口实际总截面积** = 厚度 × 长度 × 个数（方形）或 πD²/4 × 个数（圆形） | mm² |

**推导**（确认单位换算无误）：
- 金属流量 Q = G/ρ [dm³/s] = G/(ρ×1000) [m³/s]
- Q = v × F，F [m²] = F[mm²]/10⁶
- → v = Q/F = G×10⁶/(ρ×t×F×1000) = **1000·G/(ρ·t·F)** = 代码的 10·G/(t·ρ·F/100) ✓

### 2.2 面积从哪来（奥赞，`calc_A`，= 企业 Excel 22.6 式）

```
A = 71.47 × G / (ρ × t × fv × √Hp) × 100    [mm²]   （阻流参考面积）
```

内浇道参考面积 A_gt = A × (S内 / S直:S横:S内 中最小比值)。方形内浇道：
实际 F = 厚度(用户) × 长度 × 个数，长度 = round(A_gt/(厚度×个数)/5)×5（5mm 步长取整，最小 5mm）。

### 2.3 关键推论：理论流速与 G、t 无关

把 F = A_gt（面积恰好精确时）代入 2.1：

```
v = 1000·G/(ρ·t·A_gt) = 1000·fv·√Hp/(71.47×100) = 0.1399·fv·√Hp ≈ √(2g·Hp[mm]/1000)·fv   [m/s]
```

即：**内浇口流速 = 静压头 Hp 下自由落体速度 × 流速系数 fv**（伯努利）。
- 顶注：Hp≈242mm、fv=0.8 → v≈1.74 m/s
- 中注：Hp≈198mm、fv=0.6 → v≈1.18 m/s
- 底注：Hp≈175mm、fv=0.45 → v≈0.83 m/s

实际 v 在理论值 ±30% 内波动，来自 F 的 5mm 取整误差（F/A_gt 实测 0.70~1.32）。

## 五、自动优化方案（你的思路：超限自动放大内浇口）

### 5.1 物理自洽性（先说结论：方案成立）

放大内浇口只增大内浇口处截面积 → 内浇口流速按 `F_req` 反算下降；
**总流量仍由阻流处（直浇道）控制 → 浇注时间 t 不变 → 无"放大→t 变→再算"死循环**。

### 5.2 控制算法（拟）

```
v_std = 材料标准流速表[mat]          // 待确认：灰铁 0.5 / 球铁 1.0 / 铝 0.4 / 铸钢? / 铜?
v = 当前内浇口实际流速（2.1 式）

if v ≤ v_std:     保持现状
else:
    F_req = 1000·G/(t·ρ·v_std)       // 控速所需内浇口总截面积
    内浇口按 F_req 重算（方形: 长度/厚度；圆形: 直径），
    输出标注："内浇口已按控速放大 ×k（参考面积 A_gt 的 m 倍），实际比例 S直:S横:S内 变为 …"
    校核口径切换：内浇口流速 ✓（=v_std）；同时提示瓶颈位置已不在内浇口
```

### 5.3 实现影响面（小）

- `gating.js`：加 v_std 材料表、F_req 分支、输出 k 与"控速放大"标记
- `gatingView.js`：超限时的建议文案从"❌ 需增大内浇道"改为自动应用 + 结果行注明
- 比例行与瓶颈标注随之更新；是否改写用户的"个数/厚度"输入需定策略（建议：改**长度/直径**等自动量，不碰用户手填的个数与厚度）
- 规则归属：`v ≤ v_std` 为设计达标线；R7 1.5/1.0 保留为硬审核上限（放大后仍超 → 提示加内浇口数/加大厚度并人工复核）

### 5.4 需要专业意见的两个设计点

1. **放大后浇注时间变不变**：按 5.1 不变（总流量由直浇道定）。但若企业习惯"控速大内浇口 + 开放比例"，
   实际流量由直浇道底阻流决定——直浇道 A 仍由奥赞 t 反算 ✓ 自洽。请确认直浇道/横浇道保持奥赞面积不动、只动内浇口，是否符合企业做法。
2. **t 与 v 冲突时听谁的**：奥赞把面积压小（= 高流速快浇），控速要求面积放大（= 平缓慢浇）。
   两者目标天然冲突。本方案"只放大内浇口"化解冲突但不改变总时间；若专业意见要求"整体慢浇"，则需回到
   "选择浇注时间"输入（D2 议题）让面积整体按更长 t 放大——两条路线需定一条。

## 六、为什么现在会出现"流速大"（对你问题的直接回答）

1. 内浇口面积由"参考面积 → 5mm 取整 → 用户给的厚度"链生成，顶注 + 封闭式时参考面积对应理论流速
   1.7~1.9 m/s > 任何 ≤1.5 的标准 → 必然报超；
2. F 取整偏小（F/A_gt 可低至 0.70）会把 v 再顶高 30~40%（例：30kg/30mm 顶注 v=2.48 的原因）；
3. 47.txt 不是成因（3.2 表：新旧公式下 v 几乎不变）。
