## 3. 实现逻辑

### 3.1 输入模型（94.txt §二 / §三）

```
浇注系统检测
  直浇道  [选择 STL]   ← 每个类别只能导入 1 个文件
  横浇道  [选择 STL]
  内浇口  [选择 STL]
  [ 开始检测 ]
```

- **一个类别的数量 = 该文件里独立连通实体的个数**，不是文件数（§二 逐字要求）。
  复用 `triangleComponents`（共享边并查集 + 零面积三角形剔除），不新写 parser。
- **允许只导入一个或两个类别**（§三）；未导入的类别显示「未导入」，不报错，检测照常部分运行。
- 导入任何一边 → 上一次的结论立即作废，必须重新点「开始检测」（与冒口检测同一条纪律）。

### 3.2 每个单元算出来的东西（94.txt §四）

编号 / 是否闭合 / 包围盒 / **轴向长度** / **截面类型** / **截面尺寸** / **有效截面积** / 体积（闭合才给）。

- 轴向长度 = 沿该单元**自身主轴**的投影长度（不是包围盒对角线）。
- 主轴 = 体积加权主轴（PHASE 88 既有实现，PHASE 94 修了它的一个 bug，见 §3.5）。

### 3.3 ★ 截面积口径（本阶段的核心，94.txt §五 / §六 / §七）

**程序不假设圆形、不固定 X/Y/Z、不拿 bbox 冒充。**

切法（§六）：沿单元**自身主轴**取中段 20%~80% 共 21 刀，每刀算闭合环面积，
取**中位值**作为该单元的代表截面 —— 两端是与其他单元相接处、截面会畸变，中段对局部起伏不敏感。
一刀切出 ≥2 个独立闭合环 → 该方向没有唯一截面 → **如实拒绝**。

形状判定（§五，全部在 `js/model/sectionShape.js`，阈值集中在 `SHAPE_GATE`）：

| 类型 | 判据（可复算） | 面积口径（§五 原文） |
|---|---|---|
| 圆形 | 圆度 `4πA/P²` ≥ 0.90 **且** 径向均匀度 `(Rmax−Rmin)/Rmean` ≤ 0.10 | `A = πD²/4`，D = 2√(A实测/π) |
| 矩形 | 四个角点围成的四边形解释率 ≥ 0.95 **且** 矩形填充率 `A实测/(W×H)` ≥ 0.97 | `A = W × H` |
| 梯形 | 同上四边形闸门 **且** 存在一对夹角 ≤8° 的平行对边 **且** 公式值与实测偏差 ≤5% | `A = (a+b)h/2` |
| 不规则 | 以上都不成立 | **实测截面几何面积本身**（§五D 指定的做法） |

**"不强行归类"落在两处可验证的地方**：
① 每个公式都必须先通过"公式值 vs 实测面积"的一致性闸门，过不了就降级为 irregular；
② 平板件（扇形/喇叭口这类薄片）**在形状判定之前**就被拦下 —— 见 §3.4。

### 3.4 ★ 平板件：方向本身不唯一，所以不给数（§六末段 / §十三.5）

实测发现（这是本阶段一个**重要的诚实边界**）：
一片 40 长 × 48 宽 × 8 厚的**扇形内浇口**，主轴取的是**平面内最长的方向**（宽 48），
垂直于它切出来的是"长 × 厚"；而真正的**有效流通截面**是"宽 × 厚"（垂直于充型方向）。

> 两者差好几倍 —— 给哪个都是"看似精确但实际错误的数字"。
> 要算对必须先知道**充型方向**，那是 94.txt §一 明确停掉的自动识别。

判据（`axisAmbiguous`，两个条件同时成立才算平板）：

```
λ3/λ2 < 0.15   （第三个方向明显比第二个薄）
λ2/λ1 > 0.50   （两个大方向尺度相当，不是一根细长杆）
```

实测区分度：`⌀12×20 圆柱 → 0.99/1.00`（不是平板）、`80×20×15 方管 → 0.56/0.06`（不是）、
`40×48×8 扇形 → 0.04/0.69`（**是**）。

命中后：**截面积留空 + `ambiguous_axis` 原因码**，但三维尺寸、体积、长度照给 ——
拒绝的是截面积，不是整个单元。

### 3.5 ★ 修了一个潜伏的真 bug：`principalAxis` 用 `|det|`（PHASE 88 起就在）

```js
const w = Math.abs(det) / 6;   // ← 原实现
```

散度定理那套四面体求矩公式**只有带符号体积才成立**：

- 原点在实体**内部**（且实体相对原点是星形）时，所有四面体同号，`|det| == |有符号|` → **碰巧对**；
- 原点在实体**外面**时，四面体必然有正有负，`|det|` 把负的翻成正的 → 二阶矩被"离原点多远"污染，
  **主轴会算成完全错误的方向**。

**实测（同一份几何，只改位置）**：20 个 ⌀12×20 内浇口排成一排 ——
位于原点的那个主轴正确（截面 113mm²），其余的被算成横切方向（截面 **229mm²，差 2 倍**）。
一个浇注系统里的流道几乎不可能都以原点为中心，所以这对本阶段是**致命**的。

顺带说明：`|det|` 对"缠绕方向不一致"其实**帮不上忙** ——
方向不一致的三角形无论用哪种权重都会各错 `2|V|`。改成有符号后，
整体法向朝内的网格依然正确（质心 `μ1/μ0`、协方差 `M/μ0`，符号自动抵消）。

修完实测：`⌀8/⌀12/⌀16/⌀10` 四个圆柱的等效直径分别量出 `8.0/12.0/16.0/10.0`（解析值 8/12/16/10）。

### 3.6 汇总、比例、占比（94.txt §七 / §八）

```
直浇道  数量 3   总截面积 761.0 mm²
横浇道  数量 2   总截面积 600.0 mm²
内浇口  数量 4   总截面积 312.7 mm²
────────────────────────────────
总截面积  1673.7 mm²
比例   直浇道 : 横浇道 : 内浇口 = 1 : 0.79 : 0.41
占比   直浇道 45.5% · 横浇道 35.8% · 内浇口 18.7%
```

- **"总截面积"的工程定义**（§七 要求必须明确）：某类总截面积 = 该类**每个单元有效截面积逐个相加**（ΣAi）。
  **不是**平均面积 × 数量 —— 两者只在等截面时数值巧合一致。
- **缺类别不伪造**（§八）：只导入横浇道 + 内浇口时，比例就是"横 : 内"，
  归一化基准取**第一个已导入且有值的类别**；**不会**把直浇道当 0 补成"直:横:内 = 0:X:Y"。
- **占比**只在已导入且有值的类别之间算，总和 = 100%。
- **有单元量不出时**，该类总和标 `partial`，UI 写「N 个未计入」，
  并在汇总里出一条 WARNING「总截面积 = 已测得截面积的单元之和…不是全部单元之和」——
  **不让部分和看起来像总和**。

### 3.7 不做工程判断（94.txt §九）

本阶段**只回答**："你的 STL 几何上到底有多少个单元，它们分别多大，总截面积是多少，三者比例是多少。"

- **不输出 PASS / FAIL** —— `summarizeGatingAreas` 只产出 INFO / WARNING，**永远不产出 PASS**（测试 94-M 直接断言）。
- **不判断**"比例合理 / 设计正确 / 内浇口太小 / 横浇道应该多大"。
- **不计算**流速 / 流量 / 压头 / 充型时间 / 湍流 / 雷诺数 / 压力损失 / 浇注时间。

这三条都是**源码级**测试（94-P）在守，不是靠自觉。

### 5.2.1 ★ 截图抓到、断言没抓到的一个真 bug：`[hidden]` 被 CSS 盖掉

**现象**：切到「浇注系统检测」后，冒口模块的「检测结果」卡片**仍然显示**在页面上 ——
两个模块的结果同时铺开，页面比设计的长一倍。

**根因**：`hidden` 属性本身没有样式，浏览器给的默认规则是 `[hidden] { display: none }`，
**元素选择器权重**；而 `.card.section-card` 之类的类选择器权重更高，
于是 `display` 把它们又显示了出来。
`.pi-panel` 当时写了 `.pi-panel[hidden] { display: none }` 所以没事，
**结果区块漏写了这一条**，而且最初连 `data-pi-panel="riser"` 都忘了加在 `#pi_resultSec` 上。

**为什么 86 条断言全都没发现**：它们查的是"区块**里有没有**该有的内容"（`#pi_gres .pi-grow` 有几行、
`#pi_result .pi-rcard` 有几张）—— 内容在不在，跟**显不显示**是两回事。这正是"截图看不出来、
断言也看不出来、只有对着真实排版看才看得出来"的那一类问题。

**修法**：① 给 `#pi_resultSec` 补上 `data-pi-panel="riser"`；
② CSS 加 `[data-pi-panel][hidden] { display: none !important; }` 并写明为什么必须显式写；
③ **补两条按 `getComputedStyle` 核验的断言**（上面标 ★ 的两条）——
以后任何"模块区块串台"都会被这两条挡住。

## 7. 当前明确限制（94.txt §十七 的 8 问，逐条回答）

| 94.txt §十七 的问题 | 本阶段答案 |
|---|---|
| 1. 一个 STL 能否正确拆出多个实际单元？ | **能**。连通分量拆分是 PHASE 89 起就有的既有能力，本阶段直接复用。实测 20 个实体一个不差。 |
| 2. 单元数量是否可靠？ | **可靠**，但**前提是实体之间不接触**。两个实体只在一点相触时按"共享整条边"判连通（这是刻意设计），仍是两个单元；**真正相交或共面缝合**的两个浇道会并成一个 —— 那在几何上本来就是一个实体，不是漏检。 |
| 3. 圆形/方形/梯形面积是否正确？ | **正确**。实测偏差 δ 全部 <0.1%（矩形 300.0 / 圆 ⌀24 / 梯形 224.88 vs 225）。圆形的 D 是**等效直径** 2√(A/π)，与实测面积自洽。 |
| 4. 异形内浇口是否能够诚实处理？ | **分两种情况**：① 截面唯一但不规则（六边形、圆角矩形、渐变截面）→ 给**实测截面几何面积**；② **平板件**（扇形、喇叭口这类薄片）→ **明确拒绝**，给 `ambiguous_axis` 原因码。理由见 §3.4。 |
| 5. 总截面积是否符合工程直觉？ | **符合**，且能对上手工算的账：三类逐单元求和，主界面同时给出"数量 + 总截面积 + 比例 + 占比"。**但"有效截面积"的口径是"中段中位截面"，对锥形直浇道不是最小截面也不是入口截面** —— 这一点已写进页面底部说明，`详细信息` 里可逐个核对。 |
| 6. 三类比例是否一眼能看懂？ | **能**。`直浇道 : 横浇道 : 内浇口 = 1 : 0.79 : 0.41` 一行，下面跟占比百分比。缺类别时只列存在的类别。 |
| 7. 页面是否足够简单？ | **是**。主界面 5 行数字 + 比例 + 占比；单件明细全部在默认折叠的「详细信息」里；没有筛选器、没有新增参数。 |
| 8. 详细信息是否足够支撑工程核查？ | **够**。逐单元一行：截面类型 / 截面尺寸 / 截面积 / 长度 / 体积 / 闭合状态 / 截面可靠性（不可靠的写清原因）/ 文件名。点行可在 3D 里定位到该组件。 |

### 7.1 其余已知限制

1. **只做几何测量**。不算流速 / 流量 / 充型时间 / 分流比例 / 压头 / 湍流（94.txt §九 与 §十七 明确推迟）。
2. **不做工程判断**。不判断比例是否合理、不判断内浇口小不小。这是 §九 的要求，不是遗漏。
3. **"有效截面积"是中段中位截面**。对锥形直浇道（本阶段实测的典型形状）既不是最小截面也不是入口截面 ——
   这是刻意选的"代表值"口径（两端截面会畸变），已在页面说明里写明。
4. **平板件拒绝给截面**。扇形/喇叭口这类薄片需要知道充型方向才能算对，本阶段不做自动识别，故如实拒绝。
5. **程序生成的测试件网格都不干净**（实测：MC 在网格点恰好落在等值面上时产出零面积三角形，
   被退化过滤剔除后邻居丢边 → 组件被判"不闭合"）。这**不是产品逻辑问题** ——
   产品遇到不闭合本来就该拒绝给面积 —— 但会让测试夹具需要微调网格对齐（本次用 0.0173mm 平移躲开）。
6. **`.pi-gtable` 在窄屏会横向滚动**（`min-width: 720px`）。这是刻意选择：
   9 列表格在 390px 上拆行会彻底读不懂；移动端的主结果（数量/面积/比例）不依赖这张表。

## 8. 真实 STL 验证方法（94.txt §十七 要求）

**本阶段到此停止，不进 PHASE 95。** 请拿真实的三个文件来验：

1. 打开 `#/inspection` → 点模块行的「浇注系统检测」。

3. 点「开始检测」，对照下面 5 条看：
   - **数量**：文件里有几个独立实体？（在 CAD 里数一下）实际会显示几个？

   - **总截面积**：手工按"每个单元截面积逐个相加"算一遍，对不对得上？
   - **比例与占比**：是不是你想问的那个比例？

① 网格不闭合（在 CAD 里检查导出的是实体不是曲面）；
② 该单元是平板件（需要充型方向，本阶段刻意不做）；
③ 单元之间有相交/共面缝合（几何上本就是一个实体）。
