## 1. 调查结论摘要

**C1 根因：已确认（不是部分确认）。** 完整因果链为：

> **`modOk = Mr_act ≥ Mr_need × 0.99` 这个判据，作用在"已经取整的 D"上，使它在 `x = 6·Mc·f` 的小数部分上退化成一场抽签**；
> 输了抽签的候选被拒绝后，`f` 继续 `+0.05` 前进（每个 Mc 前进量固定），**直到小数部分恰好越过 0.5 才被接受** ——
> 于是最终 D 由"要走多少步"决定，而"要走多少步"是 Mc 的近奇异函数。

**闭式判据【解析 + 逐行实测】**
对 `cyl`/`sphere`/`square`（hd=1）：`Mr_act = round(x)/6`，记 `x = 6·Mc·f`、`n = ⌊x⌋`、`t = x − n`

```
modOk ⟺ round(x) ≥ 0.99x
  t ≥ 0.5 → round(x)=n+1 → 1 + 0.01n ≥ 0.99t，对 t<1 恒成立   ⇒ 恒通过
  t < 0.5 → round(x)=n   → n ≥ 0.99(n+t) ⟺ n ≥ 99t ⟺ t ≤ n/99
⇒ 接受窗口 = { t ≥ 0.5 } ∪ { t ≤ n/99 }
```
**153 行逐行核对，失配 0 行。**

**三条直接推论（均实测验证）**

| 推论 | 内容 | 验证 |
|---|---|---|
| **① 阈值** | `n/99 ≥ 0.5 ⟺ n ≥ 50`。`x` 的起点是 `6.6·Mc`，故 **`Mc ≥ 50/6.6 = 7.5758` 时 f=1.10 必然立即接受，锯齿彻底消失** | 实测 Mc 7.60~12.00 共 441 点，**f≠1.10 的点数 = 0** ✓。这解析地解释并修正了 V2.0-09 经验观察到的「Mc < 7.58」 |
| **② 局部斜率** | 每步 `f+0.05` 使 `x` 增加 `0.3·Mc`，故 `ΔD/步 ≈ −0.3·Mc + 6Mc·0.05·(步长)`。细化扫描实测 **dD/dMc ≈ −1000 mm/mm** | Mc 3.377→3.400，D 从 40 **随 Mc 上升而净下降 14 mm** ✓ |
| **③ 与材料无关** | 迭代式只用 `sd.DfromM / sd.M`，**不含任何材料量**。材料只进 `neck_k`（颈）与 `shrink/rho`（体积校核） | 5 种材料 × 4 形状扫描，**跳变数、非单调数、D 范围逐位相同** ✓ |

**★ 顺带查出比 C1 更严重的第二处缺陷（本阶段新发现，与 C1 独立）**
`f` 搜索上限 `f_max = 1.10 + 49×0.05 = 3.55` ⇒ 可达最大 `D = round(21.3·Mc)`。当体积约束要求更大的冒口时，**迭代撞上限、返回的不是收敛解，且该解 100% 违反补缩体积约束**：

- 沙箱全域 26525 个采样点中 `bind='limit'` 共 **1104 个，其中 `volOk=false` 的也是 1104 个（100%）**；
- 用真实工程重量 `cw=77.56 kg`（现有测试夹具取值）：**1068 / 2202 = 48.5% 的 Mc 输入落在这一区**，Mc 覆盖 1.00~6.73；
- 边界与解析式吻合：所需 `D_req = 143.91 mm`，可达 ⟺ `Mc ≥ 6.756`，实测上界 **6.73** ✓。

**推荐方案：C′（取整后不足则升一档）** —— 详见 §7/§8。**本阶段不实施，等待裁决。**

### §三 特别要求查明的机制 A~D

**A. `modOk` 的 0.99 容差**
- 作用对象：`:109` `Mr_act >= Mr_need * 0.99`，即"**取整后的实际模数**不低于**需求模数的 99%**"。
- 注释自述：`:109` `// 取整误差允许1%` ⇒ **它自称是数值容差，不是工程裕度**（工程裕度由 f 起点 1.10 承担）。
- 是否会使临界候选突然可接受：**是，而且这正是全部异常的来源**。§1 的闭式判据表明，容差把判据变成 `round(x) ≥ 0.99x`，其真值在小数部分上跳变。
- **去掉容差会产生什么（实测，不是推测）**：见 §7 方案 B —— **灾难性**。

**B. f 的离散搜索**
- 取值序列：`1.10, 1.15, …, 3.55`（50 档，步长 0.05，单向递增，无回溯）。
- **为什么 Mc 3.37→3.38 时 f 从 2.30 跳到 1.80**：不是"跳"，是**步数从 25 变成 15**。每步 `x` 增加 `0.3·Mc`：
  - Mc=3.37 ⇒ 每步 t 增加 `frac(1.011) = 0.011`，从 t₀=0.242 走到 0.5 需 ~24 步 ✓
  - Mc=3.38 ⇒ 每步 t 增加 `frac(1.014) = 0.014`，从 t₀=0.308 走到 0.5 需 ~14 步 ✓
  - `D = 6·Mc·(1.10+0.05k)` ⇒ **k 差 10 步 ⇒ ΔD ≈ 0.5·Mc·6 = 10 mm**，与实测完全吻合。
- 是否存在其他满足约束但更稳定的候选：**存在**。Mc=3.37 时 `f=1.80 → D=36` 只差 **1.09%**（容差 1%，差 0.09 个百分点）；而真正"够格的最小解"是 `D=23`（f=1.10 的 `round(22.242)`，升一档后 `Mr_act=3.8333 ≥ 3.670` ✓）。**当前算法两者都没选。**
- **当前选择规则**：第一个同时满足两条约束的候选（= 最小 f = 最小尺寸）。**§7 方案 A 实测：改成"体积最小"结果逐位相同 ⇒ 选择规则不是问题所在。**

**C. 取整位置**
- 发生在**搜索过程中、校核之前**（`:99-100`，在 `:105-109` 之前）。
- **是否使不同候选具有相同实际尺寸**：是，而且是结构性的 —— `round` 把连续区间 `[n−0.5, n+0.5)` 折叠成一个整数 D，`Mr_act` 因此是 `x` 的**阶梯函数**（步高 1/6 mm）。
- **是否出现"连续中间量经取整后突然跨边界"**：**正是本案**。`x` 从 46.4959（f=2.25）连续增到 46.5060（f=2.30），t 跨过 0.5，`round` 由 45 变 47，`Mr_act/Mr_need` 由 0.98949 跳到 1.01064 ⇒ 判据翻转。

**D. 约束之间的关系**
- **本案例确实由模数约束主导**：Mc=3.37 的 24 条被拒候选，`nRejModOnly = 24`，`nRejVolOnly = 0`；Mc=3.38 为 14 / 0。
- **体积约束完全不参与**：`cw=0` ⇒ `riser.js:110` `volOk` 恒 `true`，`:113` 分支不执行。
- **modOk 与 volOk 是否可能接受不同候选**：迭代内**不会**（`:115` 要求同时成立）；但最终报告值 `:144-145` 是**用最后一次迭代的 Mr_need/effV 重算的**，因此在 `bind='limit'` 时会出现"迭代从未通过、最终字段却可能显示 modOk=true"的组合（见 §6）。
- **最终输出是否始终对应一个满足现有约束的候选**：**否**。`bind='limit'` 时返回的 D/H 不满足（至少）体积约束 —— 1104/1104。

## 6. 不同材料、形状和约束组合的对比

**【实测·生产】** 5 材料 × 4 形状 × Mc 1.00~12.00（步长 0.01），共 22,020 点。

### 6.1 材料：**完全无影响**

五种材料（灰铁 / 球铁 / 铸钢 / 铝合金 / 铜合金）在同一形状下给出**逐位相同**的跳变数、非单调数、最大跌幅与 D 范围：

```

球铁/cyl   突变 134  非单调 40  跌幅-10mm@3.37  非单调≤Mc6.90  D 7~79
铸钢/cyl   突变 134  非单调 40  跌幅-10mm@3.37  非单调≤Mc6.90  D 7~79
铝合金/cyl 突变 134  非单调 40  跌幅-10mm@3.37  非单调≤Mc6.90  D 7~79
铜合金/cyl 突变 134  非单调 40  跌幅-10mm@3.37  非单调≤Mc6.90  D 7~79
```

**根因【源码】**：`riser.js:96-118` 的迭代只使用 `sd.DfromM` 与 `sd.M`，**不含任何材料量**。材料仅通过 `neck_k`（`:137-139`、只影响颈）与 `shrink`/`rho`（`:112-113`、只在 `cw>0` 时生效）进入。**这是一条独立的结构性事实，值得单独记录。**

### 6.2 形状：**四种形状只有两套行为**

| 形状 | `DfromM` 是否等价 | 表现 |
|---|---|---|
| `cyl`（hd=1） | `Mr·6` ⇒ `Mr_act = D/6` | 基准 |
| `square`（hd=1） | 同上，**逐字相同** | 与 cyl **逐位相同** |
| `sphere` | `Mr·6`，`M=D/6` | 与 cyl **逐位相同** |
| `sphere_head` | `(Mr·6)/0.92` 后 20 次牛顿迭代 + `H<r` 修正 | 非单调上界 7.51（其余 6.90），跳变数 135 vs 134 |

⇒ 形状维度上**只有 `sphere_head` 因迭代+修正而略偏**，量级相同。

### 6.3 约束类型：**体积主导是另一套病，且更重**

| 约束组合 | 非单调 | 最大跌幅 | `limit` | 说明 |
|---|---|---|---|---|
| **模数主导**（cw=0） | 40 | −10 mm | 0 | C1 本尊；阈值 Mc 7.58 |
| 交界（cw=0.5 kg，球铁） | 40 | −10 mm | **25**（cyl）/ 11（sphere_head） | 体积约束开始介入，出现不收敛 |
| **体积主导**（cw=77.56 kg，球铁） | 31 | −3 mm | **574 / 1101 = 52.1%** | ★ 过半输入返回**违反补缩体积约束**的解 |

**`bind='limit'` 的严重性【实测·生产】**

```
26525 个采样点中 bind='limit' 1104 个
  其中 volOk=false : 1104  ← 100%
  其中 modOk=false : 50
  其中两条都 false : 50

样例：Mc=1.00  cw=0.5  → D=21  f=3.55  modOk=false volOk=false  Mr_act/Mr_need=0.9859
      Mc=3.00  cw=77.56→ D=64  f=3.55  modOk=true  volOk=false  （补缩体积不够）
      Mc=5.92  cw=77.56→ D=126 f=3.55  modOk=true  volOk=false  effV=327,300 vs needVol=327,700（差 0.1%）
```

**边界与解析式吻合**：`f_max=3.55` ⇒ `D_max = round(21.3·Mc)`；`cw=77.56` 所需 `D_req = (4·needVol/eff/π)^(1/3) = 143.91 mm` ⇒ 可达 ⟺ `Mc ≥ 6.756`；**实测 limit&volOk=false 的 Mc 上界 = 6.73** ✓

**★ 必须区分清楚**：`limit` 是**搜索范围不足**（f 只到 3.55），**不是 C1 的取整抽签**。**任何针对 C1 的修复都不会修好它**（§7 实测：C′ 下 `limit` 仍为 574/1101）。它另有 UI 披露（`resultsCenter.js:100-101`：「⚠️ 迭代已达上限（f = {f}）仍未同时满足模数与体积校核：当前 D/H **不是收敛解**，请按「体积校核」一行判断。」）—— **即已披露，但量级（52%）可能未被充分认识。**

### 6.4 未适用组合

`eff` 由形状自动决定（`RISER_EFF[sd.effKey]`），manifest 侧恒传 `eff: undefined` ⇒ **无法从产品入口构造"自定义效率"组合**，故未测；`hd_ratio` 同理恒为 1.0（`calcManifest.js:280`）。这两项在实验中**未替换默认值**，而是标记为不适用。

## 7. 四类候选修复方案的优缺点

**【实测·沙箱】** 五个变体在 `tests/experiments/phasev2012_c1_sweep.mjs::variant()` 内实现，**只调用生产导出的形状函数，未接入任何生产调用路径**。

### 7.0 对照基线（生产现行）

| 场景 | 非单调 | 最大跌幅 | 未收敛 | f=1.10 占比 | 与生产不同的点 |
|---|---|---|---|---|---|
| 模数主导 Mc 1~12 | 40 | −10 mm | 0 | 87.4% | — |
| 体积主导 cw=77.56 | 31 | −3 mm | 574 | 0.0% | — |

### 7.1 方案 A —— 调整候选解选择规则：**❌ 无效（实测否决）**

- **当前规则**：第一个同时满足两条约束的候选（`:115`）。
- **候选规则**：扫描全部 50 档，收集所有可行解，取**体积最小**者。
- **实测结果**：**与生产逐位相同 —— 1101 点中 0 点不同**（模数主导全域 0 点不同）。
- **原因**：`f` 单调递增 ⇒ `D` 单调递增 ⇒ `Vr` 单调递增 ⇒ **第一个可行解本来就是最小体积解**。
- **结论**：**问题不在选择规则。这是一条重要的否定证据** —— 它把"改选择策略"这条路彻底排除，避免了一次无效改动。

### 7.2 方案 B —— 调整 `modOk` 容差：**❌ 灾难性（实测否决）**

- **容差有无工程依据**：**无**。`:109` 自述 `// 取整误差允许1%`，是**数值容差**，工程裕度由 `f` 起点 1.10 承担。
- **naive 形式（0.99 → 1.00）实测**：

| 场景 | 非单调 | 最大跌幅 | 未收敛(D=null) | 与生产不同 |
|---|---|---|---|---|
| 模数主导 Mc 1~12 | **148**（3.7×恶化） | **−59 mm** | **7** | 450 |

- **为什么必然如此【解析】**：`Mr_act ≥ Mr_need` ⟺ `round(x) ≥ x`，而 `round(x) ≥ x` **只在 `x` 为整数时取等**，否则恒为假 ⇒ **绝大多数输入会跑满 50 轮且永远不接受**，直接返回非收敛解。
- **结论**：**122.txt §五「不得直接将 0.99 改为 1.00」被实测证实为正确的禁令** —— 该改动会让算法在某些输入下**彻底无解**（实测 7 个 `D=null`）。

### 7.3 方案 B′ —— 把相对容差换成**绝对取整容差**：⚠️ 可行但语义有亏

- 形式：`modOk = Mr_act ≥ Mr_need − 0.5/6`（容忍"取整最多丢掉半个直径步"）。
- **这才是 0.99 容差**想表达的意思 —— 现行 1% 相对容差在 `Mr_need < 8.33` 时**不足以**吸收最坏取整损失（0.5/6=0.0833 mm），在 `Mr_need > 8.33` 时又**过松**。
- **实测**：模数主导非单调 **0**、未收敛 0；与生产不同 139 / 1101（12.6%），平均 |ΔD| 2.06 mm，最大 25 mm；**体积主导 0 点不同**。
- **亏损**：它**允许 D 比需求小最多 0.0833 mm 模数**（Mc=3.37 时给出 D=22，`Mr_act/Mr_need = 0.9891`）—— 即**保留了"实际冒口模数低于需求"这一状态**，只是把它从"随机发生"改成"确定性发生"。
- **副作用**：`bind` 归因中 `modulus` / `both` 分支变为不可达（这是**正确**的——模数不再驱动行走，但信息量下降）。

### 7.4 方案 C —— 取整与搜索的先后关系：✅ 有效，但改动面偏大；**C′ 是其改进形式**

- **C 形式**：`D = Math.ceil(D_raw)`（而非 `round`）。
- **C′ 形式（本报告推荐）**：**判据一字不改**，只把"取整后不足"改成"升一档再看"：
  ```js
  D = Math.round(D_raw);
  if (!(sd.M(D, H) >= Mr_need * 0.99)) { D += 1; /* 重算 H */ }
  ```
  语义 = **现行 1% 容差原样保留**，但不再让"取整丢失"把 `f` 推着走。升一档后必然满足：`round(x)+1 ≥ x ≥ 0.99x`。

| 方案 | 场景 | 非单调 | 最大跌幅 | 未收敛 | 与生产不同点 | 平均\|ΔD\| | 最大\|ΔD\| |
|---|---|---|---|---|---|---|---|
| **C** | 模数主导(全域) | 0 | 0 | 0 | 481 (43.7%) | 1.15 | 24 |
| **C** | 体积主导 | 31 | −3 | 572 | 285 (25.9%) | 1.33 | 3 |
| **C′** | 模数主导(全域) | **0** | **0** | **0** | **73 (6.6%)** | 2.01 | 24 |
| **C′** | 体积主导 | 31 | −3 | 574 | **0 (0%)** | — | 0 |

- **C′ 的两条决定性性质【实测】**
  1. **只缩不涨**：1101 Mc × 4 形状 = 4404 点中，**变大 0 点、变小 293 点、相同 4111 点**。C′ **永远不会输出比现在更大的冒口** ⇒ 不会引入新的"冒口偏大"风险。
  2. **单调性彻底恢复**：Mc 3.30~5.30、步长 **0.0005**（4001 点），`cyl` 与 `sphere_head` 的**非单调点数均为 0**。
- **原始异常点**：Mc=3.37 → C′=23（原 47）；Mc=3.38 → C′=23（原 37）。**两点相等，单调** ✓
  （D=23 是最小可行整数解：`Mr_act=23/6=3.8333 ≥ 0.99×3.37×1.10 = 3.670` ✓；D=22 为 3.6667 ✗）
- **副作用（必须记录）**：
  - 模数主导场景下 `final_f` 恒为 1.10（原可走到 2.30）→ 结果卡上"f"这一显示的**含义恢复为设计系数**；
  - `bind` 归因中 `modulus` / `both` 在模数主导场景变为不可达（与 B′ 同）；
  - `dModOnly`（`riser.js:134`，独立按 `Mc×1.10` 算的只读展示值）在需要升档的点会比实际 `D` 小 1 mm ⇒ **显示口径需同步，否则出现"仅按模数需要 ⌀22 而实际给 ⌀23"的小矛盾**；
  - `sphere_head` 的 `H<r` 修正分支也需同步升档（本实验已按同口径处理）。

### 7.5 方案 D —— 增加稳定性检查或异常提示：⚠️ 只能作临时保护，且本场景**技术上不可行**

- **可行性问题【源码】**：C1 是**跨调用**的性质（同一 Mc 邻域内 D 不单调）。`runRiser` 是纯函数、无状态，**单次调用内无法察觉"上一个 Mc 给了多大冒口"**。要检测必须引入跨调用状态（上一次输入/输出缓存），**这正是 122.txt §二禁止的"引入新状态机"的同类风险**，且会污染 `calcManifest` 的纯计算语义。
- **退而求其次的可行形式**：在**结果卡**上标注"本尺寸处于模数约束的**取整敏感区**"（判据可用 §1 的闭式律：`t = frac(6·Mc·f)` 落在死区 `(n/99, 0.5)` 即提示）。这是**纯展示**改动，不引入状态。
- **必须遵守的边界（122.txt §五 明令）**：① 提示只是临时保护，**不能冒充算法修复**；② **不能把所有非单调一概判为错误** —— 实测 87.4% 的输入在 f=1.10 立即收敛、完全正常；③ **不得通过扩大 BLOCK/WARNING 范围掩盖真正的数值缺陷**。本调查认为 **D 类不应作为 C1 的解决方案**，只能作为 C′ 落地前的过渡提示。

## 8. 推荐方案及其工程依据

### 推荐：**方案 C′**（取整后不足则升一档）

**理由（按重要性排序）**

1. **它是唯一同时满足"消除抽签"与"最小改动"的选项**。C′ 只动 6.6% 的模数主导点、**体积主导区 0 点**；C（ceil）动 43.7% / 25.9%，改动面大 4~6 倍。
2. **它不改变任何判据的含义**。`0.99` 容差、`f` 起点 1.10、`f` 步长 0.05、形状公式、材料参数**全部原样**。C′ 只回答一个本该由工程语义回答的问题：「取整后的这个实际冒口，够不够？」 —— 不够就买大一档，而不是把安全系数从 1.10 推到 2.30。
3. **它只缩不涨**（实测 4404 点中变大 0 点）。⇒ **不可能加剧 PHASE V2.0-01 记录的"冒口偏大"问题**，只会缓解它。
4. **单调性彻底恢复**（0.0005 步长下 4001 点非单调 0 处）。
5. **它顺带修好一个更隐蔽的错**：现行算法在死区里会输出 `Mr_act/Mr_need = 1.0106`（超设计系数）的冒口，看起来"更安全"。C′ 输出 1.1375 安全系数（D=23 时），**仍然 ≥ 1.10 的设计意图**，只是不再随机暴走到 2.30。

**不选其他方案的理由**

| 方案 | 不选的理由 |
|---|---|
| A | **实测与生产逐位相同** —— 不解决任何问题 |
| B | **实测更糟**（非单调 3.7×、7 点彻底无解）；`round(x) ≥ x` 只在整数点成立，是**结构性错误** |
| B′ | 可行且改动更小，但**允许实际模数低于需求 1.1%**（`Mr_act/Mr_need = 0.9891`）。工程上"冒口实际模数不足"是个不该被固化的状态；且体积主导区与 C′ 同为 0 变化，**没有换取到额外收益**。**若裁决者认为"允许最多 0.0833 mm 模数亏欠是可接受的取整现实"，B′ 是可选的更保守替代。** |
| D | 只提示不修复；且纯函数内不可行（需跨调用状态），仅可作展示层过渡 |

**推荐不变量（供下一阶段作为验收判据）**
```
① Mc 单调不减 ⇒ D 单调不减（步长 0.0005 下非单调点 = 0）
② D_C′ ≤ D_生产（只缩不涨）
③ Mr_act ≥ Mr_need × 0.99（现行判据一字不改地成立）
④ 体积主导区输出逐位不变（cw>0 时 cw=77.56 的 2202 点全部不变）
⑤ f 起点/步长/上限、形状公式、材料参数、颈公式全部不变
```
