## 3. 当前拓扑模型（§三）

```
Graph {
  nodes: [ {id, kind:'connection'|'junction'|'terminal', point, r, jkind, edgeIds[]} ]
  edges: [ {id:'E1', startNode, endNode, connectionId, depth, parentId,
            path[], leadIn?, samples[], series[], lengthMm, areaMin, areaMax,
            endReason, branchKind, branchArms[], jumps[], label} ]
}
```

- `edges` 与 PHASE 90/91 的 `segments` **是同一个数组**（两个名字都留着，免得把下游全改一遍）
- 每条边是**有向**的：从 `startNode` 沿 `endNode` 方向追踪
- 节点按位置合并（容差 = 两侧半径较小者 × 0.6）

**主夹具（§六 / §二十一 那个模型）实测产出**：

```
C1 (-29.94,10.29) ──E1(内浇口 ⌀12, 110.4~112.2)──> J1 (-30.27,54.70)
J1 ──E3(横浇道 ⌀16, 198.6)──> J3 (0.01,55.00)
J1 ──E4(横浇道 ⌀16, 198.5~198.7)──> T1 (-57.81,55.01)     横浇道末端
J3 ──E7(直浇道 ⌀22, 377.2~377.8)──> T3 (0.04,114.27)      直浇道顶端

C2 ( 29.87,10.28) ──E2(内浇口 ⌀12, 110.4~113.1)──> J2 ( 29.94,54.71)
J2 ──E5(横浇道 ⌀16)──> T2 (59.83,55.32)
J2 ──E6(横浇道 ⌀16)──> J3
```

**7 条边 / 8 个节点 / 3 个交汇 / 3 个末端**，⌀12 −2.4%、⌀16 −1.2%、⌀22 −0.8%。
**C1 → Junction ✓　C2 → Junction ✓　Junction → Sprue ✓**，
没有 C1→C2、没有"C1 跑到直浇道下方/上方"、没有"横浇道末端回头"、没有错误横向支路。

## 4. Junction 如何识别（§四/§五/§九/§十三）

**五条判据，全部是可复核的几何事实**：

| # | 判据 | 出处 |
|---|---|---|
| ① | 只有 1 个闭合环（多环走 `isFork` 那条路） | §十 |
| ② | **板状**：截面在平面内长宽比 ≥ 2 | §五 B |
| ③ | 面积比上一刀涨 ≥ 1.5 倍 —— **辅助证据** | §十三（不能单独作为依据） |
| ④ | ★ **预测点落在这一刀里面**（`|center2|×2 ≤ extent`） | **§九 空间连续性** |
| ⑤ | ★ 板状沿原方向**很快消失**（半个横向跨度内） | §五「不要因为面积变大就判 Junction」 |

**④ 为什么零新阈值**：`sliceArea` 的平面坐标原点**就是这一刀的预测点**（我们自己轴线上的点）。
"预测点落在截面内" ⇔ "是我们走进了它"；反过来，切面顺带切到旁边另一条互不相干的流道时，
预测点在人家包围盒外面 → 直接否掉。这正是 §九「禁止从 A 点跳到空间上较远但面积相似的 B 点」。

**★ 与 PHASE 90/91 的关键差别**：那时这个判据**只在"这一刀切成功了"之后才跑**。
现在它**逐档试探都跑**（`probeFactors` 的每一档），并且**在记录样本之前跑**：
交汇那一刀的截面（802mm²）根本不是本流道的截面，记进序列会直接污染这条边的 `areaMax`
（实测旧代码 max=2127，该夹具真值上限 707）。

## 5. Branch 如何生成（§九/§十）

**候选方向只有三类，每一类都一句话说得清出处**：

1. **平面内长轴的两个方向** —— 这不是经验规则：拿垂直于自身轴线的平面去切一根**横穿**的管子，
   得到的正是"沿那根管轴的长方形"，它的长轴方向**就是那根管子的轴向**。
2. **原方向 D** —— 4 路交叉 / 十字路口直行时它才是对的通道。保留与否由探针决定，不靠预先假设。

**筛选（§九：空间连续性 + 方向连续性优先）**：

- 不回头：与来向夹角 > 180°−60° 的方向丢掉（§十）
- 起点探针**从交汇点小步向外走**，取第一刀"干净通道截面"；起点取**截面形心**
  （它落在横穿通道的轴线上，方向不会被带偏 —— PHASE 90 在这里踩过 1782mm² 的假截面）
- ★ **一旦某一刀切到 0 个环就立刻停**（§九 空间连续性）：真实通道是连续的，
  我们正走在里面，每一站都该有截面；断了就不许再往前。
- ★ **探针点本身必须落在这一刀里面**（与判据④同一条原则）

**交汇点 = 我们这条通道的轴线 与 横穿通道轴线的交点**（用支路起步点在我们轴线上的投影求）。
为什么不能直接用"检测到的那一刀的位置"：那个位置取决于**步长**。
实测：横浇道穿过直浇道时，从左来的那段在 x=−11.4 判出交汇、从右来的那段在 x=+11.4 判出 ——
同一个物理交汇被记成**两个节点**，直浇道被生成两遍，其中一个还成了走不通的死胡同。

## 6. Graph 数据结构与"不重复"的两张表（§十七 Q/R）

| 表 | 作用 |
|---|---|
| **节点表** | 同一个交汇被两条来路各发现一次时**合并成一个节点**（§十 的 merge） |
| **已走访点表**（空间哈希） | 一条支路的起步点落在**已经走过的几何**上时，根本不生成它 |

第二条是实测补的：没有它时，网络里会出现 `J2→J3` 与 `J3→J2` **两条重复的边**。
另外还在入队时**预订**支路起步点 —— 同一个交汇的两条来路会各自生出一条"往上走"的同名支路，
它们先后入队、此时谁都还没走，光靠"已走访点"挡不住（实测：直浇道上出现两条并行边）。

**★ 到位优先于新建交汇**：走到已有节点 / 已走过的几何上就算**汇合**，不该再开一个新节点。
踩过的坑：横浇道从直浇道往右走，撞上另一条内浇口的 T 口时，交汇判据先生效 →
建出一个**度为 1 的死胡同节点**，而"往下接回 C2"那条腿因为几何已被走过被丢掉 —— 网络在这里断了。

## 7. A(s) 如何挂到 Edge（§十二）

- `sliceArea` / 连续性闸门 / `headlineStats` / 突变检测 **一行都没重写**（§十五 明令复用）
- 每条边携带 `samples[]`（逐刀 `{distance, area, centroid, valid, reason, confidence}`）
- **UI 里每一条边各自挂一条 A(s) 曲线**（不再是"整条路径画一张图"）
- **端面判定从"最后一刀"推广到"面积连续下降的收尾段"**：
  圆头 / 半球端盖会被连续几刀切出越来越小的环。实测 ⌀16 圆头端给出 `199 → 143 → 78 → 13.6`，
  只摘最后一刀的话"最小截面积"变成 **78.3**（真值 201，−61%），
  而且过不过关还**取决于采样相位**（两个镜像斜臂一个过一个不过）。判据必须对相位不敏感。

## 14. 已知限制

1. **★ 交汇处会"吞掉"约一个步长的通道。** 相邻两个交汇之间如果只有不到一个步长（实测：
   横浇道末端离内浇口只有 5mm），那一段量不出来，不会单独成边 ——
   但**连通关系不受影响**（两端仍然通过节点连在一起），而且不会给出错误的数。
2. **端面收尾段的判定用"面积连续下降"**：一条**整段都在单调收缩**的流道（如锥形浇口）
   末尾几刀会被一律标成端面、不进 headline。极端情况下 `headlineStats` 会整体回退
   （有多少给多少，并标"可靠度低"），**不会把序列掏空、也不会编数**。
3. **交汇点的位置是"两条轴线最近点"的近似**：交汇处几何占比很大时（横浇道几乎吞掉内浇口），
   交汇点会偏离理想的轴线交点几个 mm。实测主夹具 3 个交汇的位置都在 ±6mm 内。
4. **`spurious_branches` / `duplicate_branches` / `self_loops_dropped` 三个计数会如实报出**，
   但 UI 上只作为 WARNING 文案出现，没有逐条列出被丢的方向（要看细节得开 `?flowDebug=1`）。
5. 沿用 PHASE 91：产品网格不水密时"在不在产品内部"的判定依据会变弱（会如实报 `product_not_closed`）。
6. 沿用 PHASE 88：侧栏一级导航**仍未加**工艺检验中心入口（会撞 `browser_test` 的 `navItems === 4` 硬断言）。
