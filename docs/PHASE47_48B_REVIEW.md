# PHASE 47 + PHASE 48-B 改动回顾报告（供专业人士评审）

> 对象：浇注系统计算器（gating）最近两次改动
> 1. PHASE 47（47.txt）：浇注时间 T 公式改为材料分派模型
> 2. PHASE 48-B（49.txt FINAL）：内浇口速度从"错误式报警"改为"设计校核 + 自动推荐面积"
> 目的：说清"改了什么、为什么改"，并把实现者识别出的工程疑点列出，请专业人士裁断。

---

## 一、背景（两条改动各自的动因）

**P47 动因**：原工具所有材料共用一条 Dietert 扩展式 `t=f(√G+∛(wG/5))·2/3`（出自《铸造手册》）。
对照企业 Excel 后确认：企业"理论浇注时间"用另一套（K11 = f·(√F3+∛(σF3/5))·2/3，F3=铸件毛重×件数），
且行业通行做法是"灰铁/球铁/铸钢各有针对性经验公式"。用户提供了 47.txt 指定三套经典教材公式，要求替换灰铁/球铁/铸钢，铝/铜保持原模型，不增加任何用户输入。

**P48-B 动因**：用户实测发现大量"内浇口流速过高"报警（顶注尤其严重）。诊断（PHASE 48-A）证实：
内浇口流速的理论值 = fv·√(2gHp)，当内浇口面积=奥赞参考面积时**与重量、浇注时间、材料无关**（数学抵消），
顶注 Hp 最大 × fv=0.8 → 理论 1.74~1.91 m/s，必然超过企业 R7 审核上限 1.5。
即：报警不是 bug，是"奥赞体系内浇口流速特征值 > 审核上限"的结构性冲突。
49.txt 的裁决：不修改任何基础物理公式，把"速度超差"从硬错误改为"设计校核状态"，并按材料目标速度自动反算推荐内浇口总面积。

## 二、PHASE 47 具体改了什么

### 2.1 改动内容

| 材料 | 旧模型 | 新模型（47.txt 指定） |
|---|---|---|
| 灰铁 | Dietert 扩展式（f=1.0） | W≤450kg：T=0.70(1.41+t/14.59)·√W<br>W>450kg：T=0.70(1.236+t/16.65)·∛W |
| 球铁 | 同上（f=0.85） | T=K₁·√W；K₁ 按壁厚**严格分档**：t<10→2.080 / 10≤t≤25→2.670 / t>25→2.970 |
| 铸钢 | 同上（f=0.80） | T=(2.4335−0.3953·log₁₀W)·√W（不依赖壁厚） |
| 铝/铜 | Dietert 扩展式 | **不变**（f=1.20/0.90） |

实现位置：`calcs/gating.js calc_t`（唯一权威入口，runGating 单点调用），输出/UI 公式说明文字同步。
任务书同时要求：不加输入、不改 UI 结构、不动阻流面积公式（奥赞 A 不动）。

### 2.2 关键实现决策（每一处都标注了口径）

1. **W 取"浇注重量 G = 单件毛重×一模件数÷出品率"**，而非 47.txt 字面的"产品重量"。
   理由：①与奥赞阻流公式、流速公式中的 G 同口径（物理自洽：t 应对应型腔总金属量）；
   ②与企业查表时间口径一致（Excel 查表按"浇注重量"K22=毛重×件数+浇道重+冒口重）；
   ③不动现有调用链。
   ⚠️ 注意：企业 Excel 的"理论浇注时间"K11 实际用的是 **F3=毛重×件数（不含冒口/浇道）**——即企业自己两处重量口径不同（理论时间用毛重、查表/阻流用浇注重量）。我们统一用浇注重量，比企业理论时间的 W 大约 √(120.22/93.6)≈13%（案例），t 系统性偏大 13%、A 偏小 13%（偏保守方向）。
2. **分档严格不连续化**：球铁 10/25mm、灰铁 450kg 分界点按任务书硬切，不做插值（跳变是模型的固有属性，见 §四疑点 2）。
3. **公式常数为 47.txt 字面直译**（0.70/1.41/14.59/1.236/16.65/2.4335/0.3953/2.080/2.670/2.970），出处为经典教材体系（形制与欧美教材 Dietert 一脉相符，中文《铸造手册》收录相近公式）。

### 2.3 为什么这么改

- "对于有可靠经典经验公式支持的材料，用材料针对性成熟公式；无依据的保持现状"（47.txt 最终原则）。
- 灰铁/球铁/铸钢的冶金行为不同（石墨化膨胀、缩松倾向、充型氧化敏感性），共用一条公式是过度简化；
  尤其球铁壁厚敏感（薄壁急冷），分档 K₁ 比连续壁厚项更贴近教材做法。
- 铝/铜无企业级替换依据（企业主产品为铁系），不动是保守正确。

## 三、PHASE 48-B 具体改了什么

### 3.1 目标速度表（49.txt 定案，Casting Toolbox 工程设计目标）

| 材料 | 目标 v_target | 判定 |
|---|---|---|
| 灰铁 | 1.00 m/s | ≤1.00 推荐；>1.00 偏高 |
| 球铁 | 0.45（推荐 0.40~0.50） | 区间内推荐；<0.40 偏低（可保留不报错）；>0.50 偏高 |
| 铝 | 0.45（推荐 0.40~0.50） | 同上 |
| 铸钢/铜 | **无目标** | 不设限、不自动调整，仅显示（超 R7 提示参考） |

### 3.2 计算链（实现）

```
Q = G/(ρ·t)                   充型流量（G=浇注重量 kg，ρ=液态密度，t=47 模型时间）
A_target = Q/v_target = 1000·G/(ρ·t·v_target)   目标速度所需内浇口总面积
A_rec = max(A_gt 奥赞参考, A_target)             只放大、不缩小
几何：方形 L=ceil(A_rec/(个数×厚度)/5)×5；圆形 D=ceil(√(4A_rec/(π·个数)))
     （有目标且放大时用 ceil 宁大勿小；无目标材料保持原 round，行为零变化）
v_final = Q/A_rec（= Q/Fg 实际）   ← 用户看到的"推荐平均内浇口速度"
v_theory = fv·√(2gHp)              ← 保留为内部诊断值，不删除、不被覆盖
状态：rec/high/low/none；R7（V_LIMIT 1.5/1.0）保留为红线提示（r7Exceed）
```

### 3.3 UI/输出变化

- 取消 `❌ 流速超差`、`❌ 计算错误` 文案；速度行显示"平均流速 + ✅推荐/⚠️偏高/ℹ️偏低/—"
- 新增"🧮 推荐内浇口总面积"行（超目标时显示放大倍数，几何已自动应用）
- v_theory 显示在"中间计算"区（标注内部诊断值）
- 综合判定 allOk 不再因速度失败（速度=优化提示）；排气等硬项保留

### 3.4 为什么这么改（设计意图）

1. **程序既然自动设计了浇注系统，就不该只报"流速过高请增大内浇口"，而应自动给出达标方案**（49.txt 核心）。
2. **不修物理公式**：奥赞系数/fv/Hp/密度/t 全部不动——速度高不是公式错，是"内浇口=阻流"的封闭体系特征值超目标，正确解法是放大内浇口让阻流迁移（向半开放漂移），这正是行业"阻流控流量、内浇口控速度"的分工。
3. **只放大内浇口不碰直浇道/横浇道**：阻流处流量不变 → 浇注时间 t 的假设不被破坏（名义上），无迭代死锁。
4. **不加未确认几何硬限制**（49.txt §六：60mm/2×/8 个/F70 均不采纳），"优先增加内浇口数量"以提示形式给出。

## 四、实现者自审：识别出的"不完美点"（请专家重点裁断）

### A. 属于 PHASE 47 的疑点

1. **W 口径三层不一致**：47.txt 说"W=产品重量"；我们取浇注重量 G；企业理论时间用毛重×件数。
   三处口径差 ~4%~13%，直接影响 t 与 A 的绝对值。专家需裁定：该公式体系里的 W 到底应取"铸件毛重（含冒口前）"还是"浇注重量（含冒口/浇道）"？我们取 G 的理由是下游自洽，但若教材公式回归时用的是毛重，则系统性偏保守 13%。
2. **灰铁 450kg 跳变**：450.0kg→T=36.2s（√W 式），450.1kg→T=11.5s（∛W 式），**−68%**，A 同步放大 3 倍。
   同一零件 0.1kg 毛重波动（很常见）导致整个浇注系统设计突变。这是两段式的固有属性（任务书要求不连续化），
   但 450kg 附近的真实零件会踩悬崖——是否应在该区间给分段提示，或接受？
3. **球铁 10/25mm 档跳变**：壁厚 9.9→10.0mm → K₁ 2.080→2.670（**+28%**）。壁厚"主体/代表性"的取法若与教材口径不同，选档会系统性漂移（我们 UI 只有单一"产品壁厚"字段，用户可能填最大壁厚而非主体壁厚）。
4. **fc（材质系数）结构性残留**：灰铁/球铁/铸钢已不用 fc，但 MATERIALS 表与"材质系数 f"行仍显示（铝/铜在用）——不算错，但表结构上灰铁等的 fc 成死数据，后续易误导。

### B. 属于 PHASE 48-B 的疑点（"说不出的不完美"最可能在这些）

5. **名义流速与"阻流是否迁移"的边界条件（表述已按 50.txt §六修正）**：
   准确表述：**增大内浇口面积主要用于降低内浇口处的平均流速；只要阻流截面仍控制系统流量，
   它并不会自动改变原设计的名义流量和浇注时间**（阻流处未放大 → 名义 Q=G/t 不变）。
   需要专家裁断的边界条件是：当 A_rec 放大到超过直浇道参考面积 A_sp（封闭式 1:2:0.85 时
   A_sp≈1.18×A_gt；放大案例 A_rec 常见 1.7~3.9×A_gt 会超过）——此时**系统最小截面不再是内浇口**，
   一阶模型的"名义流量不变"假设的适用前提（阻流仍在原处）不再严格成立，真实系统流量将由新的最小截面
   （直浇道）约束，实际充型时间会偏离设计 t。一阶设计层面是否接受该偏差、或需标注"阻流位置已迁移
   （内浇口不再是最小截面）"，请专家定夺。
   → 疑点：v_final 是"名义平均流速"（按设计 t 与放大后 Fg），是否应同步展示真实最小截面位置？
       后者更诚实，但一阶口径下"放大内浇口 = 名义上不改变浇注时间"（50.txt §六）仍作为主口径。
6. **放大无几何可行性检查**：极端案例（铝 0.45 顶注，理论 1.74→目标 0.45）放大 ~3.9×，
   单口长度可达 150mm+（40kg 铝案例 Fg 3658mm² ÷ 2口×12mm 厚 = 152mm/口）——一个内浇口 150mm 长在实际产品上往往不现实
   （受铸件入口边宽限制、清理打磨成本）。49.txt 说"优先增加个数不无限放大单口"但未给任何数值规则，
   我们实现为纯提示（不放数值限制）。专家需给"合理的个数优先策略"或几何约束的工程依据。
7. **目标速度表两次输入不一致**：用户早前口述"灰铁 0.4~0.5、球铁 1.0、铝 0.4"；49.txt 定案为
   "灰铁 ≤1.0、球铁 0.45、铝 0.45"——两套数值方向相反（灰铁从严还是球铁从严？）。
   我们按 49.txt 执行。请专家确认目标表本身的合理性（灰铁允许 1.0 而球铁只要 0.45，同是铁基，依据是什么？
   若依据是铁水氧化膜特性，铸钢/铜为何不设？）。
8. **R7 角色降级后"硬信号"消失**：速度不再是红色错误后，sugs 里"内浇道偏大/偏小"警告也因
   Fg≥A_rec≥A_gt 的结构几乎不再触发（内浇道尺寸警告被屏蔽，见代码 `vState!=='rec'` 条件）。
   结果：有目标材料的工况几乎永远"✅ 推荐"——用户失去对"浇注系统是否过设计"的显性感知。
   是否有必要保留一个"放大倍数过大（如 >2×）→ 建议改浇注方式/增加个数"的显性黄色提示？
9. **"偏低/偏高"状态几乎不可达**：自动几何保证 v_final≤目标（偏高只在防御分支），
   偏低仅在小件 5mm 粒度向上超调时出现——状态机大部分时间只输出"✅ 推荐"，其诊断价值有限。
   这符合 49.txt 意图（不报错），但专家可评估是否合理。
10. **目标速度的物理含义**：v_target（0.45~1.0 m/s）针对的是"内浇口平均速度"。
    文献（Campbell 等）常讨论的内浇口临界速度 ~0.5 m/s 指"防止卷气/氧化膜折叠"的入口速度；
    我们计算的是"流量/总面积"的平均值，且基于**名义时间**。两者概念是否一致、目标值是否应区分
    "平均"与"最大"（狭缝入口处流速不均），请专家界定。
