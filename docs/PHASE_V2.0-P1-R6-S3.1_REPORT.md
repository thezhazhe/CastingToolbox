## 3. P0：冒口尺寸与工程约束核查

### 3.1 真实调用链

```
CALC_MANIFEST.riser.calculate()
  → 选取 Mc / 形状 / 净重
  → runRiser({ mc_mode:'direct', mc, shape, hd_ratio:1.0, eff:undefined, rho })
  → sizeAt(Mr_target = Mc × MODULUS_TARGET_RATIO = 1.2×Mc, hd=1.0)
  → D = round(DfromM(Mr_target)) → 上探/下探到最小整数档
  → Mr_act = sd.M(D,H)（必须 ≥ Mr_target）
  → Vr = sd.V(D,H)；effV = Vr × 形状效率；volOk 仅诊断
```

- `MODULUS_TARGET_RATIO = 1.2`（`calcs/riser.js:32`，唯一常量）。
- 设计中心 `calcManifest.js:280` 确实传 `hd_ratio: 1.0`、`shape` 来自 `process.riserShape`。
- `calcManifest` 真实入口逐形状复算 `shapeKey` = 用户选择值（探针 D 组），**形状参数没有丢失**。

### 3.2 四形状代表数据（球铁 / 净重 77.56 kg / Mc=11.43 / hd=1.0）

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---|---|
| 圆柱 | 83 | 83 | 13.716 | 13.833 | 1.2103 | 449.1 | 14% | 62.9 | 327.7 | 否 | 是 |
| 球顶圆柱 | 83 | 83 | 13.716 | 13.833 | 1.2103 | 374.2 | 25% | 93.6 | 327.7 | 否 | 是 |
| 球形 | 83 | 83 | 13.716 | 13.833 | 1.2103 | 299.4 | 20% | 59.9 | 327.7 | 否 | 是 |
| 正方柱 | 83 | 83 | 13.716 | 13.833 | 1.2103 | 571.8 | 14% | 80.1 | 327.7 | 否 | 是 |

> 探针：`node scripts/audit_s31_probe.mjs`。

### 3.3 为什么四种形状 D/H 完全相同

- `hd = H/D = 1` 时：
  - 圆柱/正方柱：`M = D×H/(2D+4H) = D/6`
  - 球顶柱：`M = V/A`，在该几何下同样化简为 `D/6`
  - 球形：定义即 `M = D/6`
- 因此 `DfromM(Mr_target, 1.0)` 对四形状给出同一个 D；H 由 `round(D×hd)` 得出同一个 H。
- 这是**几何公式的必然结果 + 固定 H/D 的结果**，不是“形状参数未正确传入”。
- 换形状真正改变的是 `Vr` 与 `eff`，从而改变可补缩量；结果页已把两者放在可见核心卡，
  并在详细信息说明该结论只适用于当前 `hd=1.0` 口径。

### 3.4 目标模数/体积约束的实际执行

- **目标模数**：`Mr_target = 1.2×Mc`；最终整数尺寸必须 `Mr_act ≥ Mr_target`，否则 `runRiser`
  返回 `null`。代表案例 `Mr_act = 13.833 ≥ 13.716`，`modOk = true`。
- **尺寸是否被额外放大**：最终 D=83，仅按模数连续解取整 `dModOnly=82`；差 **+1 mm**，
  是最小整数档/取整复核的结果，不是整件净重或体积约束推动。
- **体积约束**：`volOk` 是旧模型诊断值（按整件净重折算补缩需求），**不参与尺寸搜索**；
  `bind` 恒为 `'modulus'`。代表案例四形状 `volOk=false`（62.9~93.6 < 327.7 cm³），
  说明“目标模数达标 ≠ 补缩能力已被证明”。本阶段没有把它伪装成通过；结果页 P1 风险条、
  冒口核心卡状态和报告都会明示。
- **哪些参数会放大尺寸**：只有 `Mc`、`hd`、形状（通过 Vr/eff）与整数取整会改变 D/H；
  改变整件净重 **不会**改变 D/H/Vr（实测 0.001~20000 kg 逐位相同），只会改变 `volOk`。

### 3.5 球形等形状的展示

- 结果页 `riserDimensions()` 对球形只输出 **冒口球径 D**，不再把 H 当第二尺寸；
- 详细信息不再显示无意义的 `H/D`，改为“球形由球径唯一确定：H ≡ D”；
- 独立冒口计算器切到球形时 **隐藏 H/D 选择器**并说明原因；导出报告同样不重复 H；
- 圆柱/球顶柱/正方柱仍按各自几何显示 D/H/球顶半径 R/边长，全部取自 `RISER_SHAPES.label()`。

## 4. P0：出品率缺陷的最终结论与决策材料

### 4.1 一模 1/2/4 件（球铁 / 单件毛坯 20 kg / 预估出品率 65% / Mc=8）

| 型腔数 | W_c = 单件×n (kg) | G (kg) | `gating.ya` | `yield.castWt` | `yield.pourWt` | `yield.runnerWt` | `yield.riserWt` | 旧页面“铸件÷G” |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 20 | 30.77 | 65% | 20 | 30.77 | 10.77 | 1.088 | 65% |
| 2 | 40 | 61.54 | 65% | 20 | 61.54 | 41.54 | 1.088 | **32.5%** |
| 4 | 80 | 123.08 | 65% | 20 | 123.08 | 103.08 | 1.088 | **16.25%** |

### 4.2 口径问题（沿用 S3 结论并再次核实）

- `gating.ya = pw×cav/G×100 ≡ 输入的预估出品率`，**不是**实重统计；
- `yield.castWt` 是**单件**毛坯重（不是整模）；
- `yield.runnerWt = G − 单件`：未乘型腔数、未扣冒口，且把冒口包含在“浇注系统重”里；
- `yield.riserWt` 是**单套**（多热结时是该件全部冒口之和），未乘型腔数；
- 旧 yield 页把“单件 / 整模 G”当最终出品率 ⇒ 2 腔 32.5%、4 腔 16.25%；
- 结果页/报告现在改用 `buildYieldLedger()` 的整模账目，**不展示**最终实重出品率；
- G 本身由预估出品率反推，因此“铸件 ÷ G”永远只是设计口径。

### 4.3 独立计算器与设计中心是否一致

- **独立“出品率与铁水重量”计算器**要求用户输入**现场实测出品率**，再按
  `单件 ÷ 实测出品率 × 一模件数` 计算整模铁液与“非铸件金属重量”，口径是完整的。
- **设计中心**没有“实测浇注重量/独立浇道实重”，只有**设计预估出品率**，因此不能给出
  最终实重出品率。两者不是同一输入，不能强行对齐数值；本阶段在 UI/报告明确区分。
- **独立浇注系统计算器**已显示“设计出品率（按输入预估反推）”，没有把它标成实重。

### 4.4 结果页与报告是否同一数据

- 两者都调用 `resultFacts.gatingFacts()` → `buildYieldLedger()`；
- 测试 `S3.1-C1` 验证报告与 `gatingFacts` 的 G、直浇道直径、整模账目逐项一致；
- 报告不再出现旧的 32.5% / 16.25%。

### 4.5 冻结核心最小解冻方案（仅提案，本阶段未改）

建议在 `calcs/calcManifest.js` 的 `yield.calculate` 增加**新字段**而不是改旧字段语义：

| 建议字段 | 公式口径 | 兼容影响 |
|---|---|---|
| `castingMass` | `blankWeightKg × cavities` | 新增，不影响旧消费方 |
| `riserWtTotal` | `riserWt × cavities`（假设每腔一套） | 新增 |
| `gatingWtResidual` | `G − castingMass − riserWtTotal` | 只能是“反推残差”，不是实称浇道重 |
| `finalYield` | **保持 null**，除非有实测浇注重量/独立浇道实重 | 明确不可给 |
| `runnerWt` | 保留旧字段，但 UI 标注“G − 单件（含冒口，兼容字段）” | 不破坏旧测试/报告 |

必须补的实测数据：独立浇道实重（或浇注重量实测）与最终铸件实重。测试案例：
1/2/4 腔 × 有无冒口 × 单件/整模账目，另加“冒口不重复计入”的守恒断言。
**本阶段不得解冻核心。**

## 5. P0：RH 参数归属与状态

### 5.1 物理定义

> **RH = 冒口顶面相对于铸件顶面的高度差（沿浇注方向）**，不是冒口自身总高 H。
> 浇注系统使用 `C = ph + RH` 与平均静压头 `Hp`。

- 顶冒口直接坐在铸件顶面时，RH 才等于冒口总高 H；
- 侧冒口、冒口座、错位接入必须按实际高度差指定；
- 底注时现有公式的 `Hp` **不随 RH 变化**（如实披露，不假装有影响）。

### 5.2 存储与状态

- 唯一权威存储：`process.riserHeight`（没有第二份）。
- **不再由 riser 自动回写**：`runAnalysis` 已删除 `proj.setResult('process.riserHeight', r.H)`。
- 参考值：面板显示“本次冒口计算 H 参考”，只有用户点“采用此参考值”才进入草稿；
  保存前项目数据不变。
- 旧项目迁移：`migrateProject()` 遇到 `CALC_RESULT` 来源的 `process.riserHeight` 时清零
  （它是旧版冒口总高自动值，不是用户 RH）；`USER_INPUT/USER_OVERRIDE` 原样保留。
- 换 STL：`clearStlBoundData()` 保留两类用户来源；导入完成 toast 明确提示复核；
  自动来源清除。
- 冒口方案变化：如果用户已指定 RH，且冒口 H 发生变化，分析完成 toast 明确提示
  “冒口高度已由 X 变为 Y：请复核 RH=Z 是否仍适用”；`autoRecompute` 的完成提示不会覆盖它。

### 5.3 RH 对 Hp/阻流面积的真实影响（球铁 20kg / 65% / 壁厚 10 / Ho=150 / ph=100）

| 浇注方向 | RH=0：Hp / A / ⌀S | RH=200：Hp / A / ⌀S | RH=400：Hp / A / ⌀S | 结论 |
|---|---|---|---|---|
| 顶注 | 250.0 / 211 / 17 | 183.3 / 246.4 / 18 | 90.0 / 351.7 / 22 | Hp 下降、A 上升 |
| 中注 | 237.5 / 288.7 / 20 | 45.8 / 657.1 / 29 | **−172.5 / 0 / 5** | 过大 RH 可导致 Hp≤0 |
| 底注 | 175.0 / 448.4 / 24 | 175.0 / 448.4 / 24 | 175.0 / 448.4 / 24 | 现有公式不随 RH 变化 |

- **Hp ≤ 0 / A ≤ 0 是物理不可用结果**：`gatingValidity()` 判 P0，`runAnalysis` 将其记为
  “分析未完成”，旧结果保留但标记过期，不冒充有效。
- 中注 RH=400 是实测触发案例；UI 失败原因逐字显示“Hp ≤ 0……请减小 RH 或核对 ph / Ho”。

### 5.4 UI

- RH 在“浇注系统设计”中紧跟 `ph`，同一参数网格；
- 徽标只有“用户指定 / 未指定”，不再显示“冒口计算自动值”；
