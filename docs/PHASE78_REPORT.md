## B. 交互 Bug 根因（78.txt 四）：旧持久化项目缺字段 → `proj.set()` 静默失败

**症状**：点击热结 H1 → 弹窗 → 确定 → 勾选框不打勾；`process.hsPick` 始终为空。

**排查过程**（探针脚本实测，非推断）：

1. 干净 profile 下复现：**不能复现**，勾选正常 → 说明与"项目状态"有关。
2. 构造"旧版本存档"（有 `process` 但缺 `hsPick`）→ 重载后 `get('process.hsPick')` 返回 **NULL**，`set(...)` 返回 **false** → **稳定复现**。

**根因**：`CastingProject` 加载时用的是**顶层浅合并**：

```js
project = migrateProject({ ...defaultProject(), ...JSON.parse(localStorage.getItem(KEY) || 'null') });
```

存档里的 `process` / `production` 子对象会**整体替换**默认值。于是**版本升级后新增的参数字段**（`process.hsPick`、`process.gateThk`、`production.ingateN` …）在任何"升级前就存在的项目"上根本不存在 → `get()` 返回 null → `set()` 第一行 `if (!p) return false;` **静默失败**：UI 写不进去、勾选框不打勾、内浇道厚度改了没反应。

**为什么此前没发现**：所有验收脚本都使用**全新浏览器 profile**（每次都 `rm -rf`），永远走"默认项目"分支；只有真实用户带着历史 localStorage 才会命中。

**修复**（`js/model/CastingProject.js`）：

- 新增 `mergeDeep(base, saved)`：以默认骨架为底，持久化值覆盖；两侧同为**普通对象**才递归，**参数对象（含 `v`）与数组整体覆盖**（保护参数语义）。
- 加载改为 `migrateProject(mergeDeep(defaultProject(), saved))`。
- 防御：`saved` 为 `null/undefined`（首次运行）必须回落默认骨架；`migrateProject(null)` 也返回默认骨架。
  - ⚠️ 首版写法 `saved === undefined ? base : saved` 让首次运行得到 `project = null` → **全站静默失效**，被本轮浏览器验收当场抓出（fresh profile 下所有 `set` 返回 false），已修并加单测。

**影响面**：同时修复了 `production.ingateN`、`process.gateThk` 等一切"新加字段"在旧项目上的失效——即 71.7 的内浇道输入框在用户机器上大概率也一直没生效。

## E. 口径变化（会改变数值，需留意）

1. **冒口形状默认值**：设计中心原硬编码 `sphere_head`（球顶圆柱，效率 25%）→ 按 78.txt 改为**圆柱形（效率 14%）**。同模数下两者直径相同（h/d=1 时 M=D/6 等价），但**补缩效率不同 → 体积校核与迭代倍率 f 不同 → 冒口体积更大**。下拉可一键切回。
2. **排气口径**：原硬编码"⌀15 × 4 个 = 707 mm²" → 改为 **⌀3 × N（默认 3 个）**。⌀3 是排气孔的实际做法（Campbell 口径），但 3 个只有 21.2 mm²，**默认必然低于企业标准 1.5× 直浇道**，因此结果页会出现"⚠️ 排气面积比不足"并给出"需约 N 个 ⌀3 孔 + 采用推荐"。若希望默认直接达标，把 `VENT_N_DEFAULT` 或 `process.ventN` 默认值改成推荐值即可（一行）。
3. **内浇道默认厚度**（71.7 起）：`max(3, 主体壁厚÷3)`，本次仅把输入入口搬到结果页，口径未变。

## G. 结论与待关注

**GO**：78.txt 的 12 条全部落地；核心交互 Bug 已定位到"持久化项目加载"这一**模型层**缺陷并修复（影响面大于热结勾选本身）。

**待关注 / 建议**

1. **⌀3×3 排气默认值会触发"排气不足"提示**（§E-2）——是否把默认个数改为"标准推荐值"（随直浇道面积变化），请裁决。
2. **冒口形状默认改为圆柱形**后，同 Mc 下冒口体积变大（§E-1），历史对比数值会变。
3. 观察项（本轮未改）：结果页「③ 浇注系统」的横浇道固定为 `2 条 × 厚 25 mm`（manifest 硬编码），小件会出现横浇道总截面远大于直浇道（如 500 vs 50 mm²）；独立计算器可调，设计中心暂未开放。
4. 78.txt 未涉及的报告版式（卡片化）仍待下一阶段。
