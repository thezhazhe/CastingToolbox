## 1. 修复前后行为对照

### D1 —— 勾选热结 ≠ 确认 Mc

| 场景（重件 77.56 kg / 球铁 / 两个热结 mc 14、12） | 修复前 | **修复后** |
|---|---|---|
| ① 不勾选（自动 Mc = 14） | 🟡 需人工复核 + 未确认提示 | 不变 |
| ② **勾选 H1（不改任何数字）** | **✅ 可直接采用，未确认提示整条消失** | **🟡 需人工复核 + 未确认提示保留** |
| ③ 勾选 H1 并把 Mc 改成 20 | 🟡 + "按用户确认的…计算" | 不变 |
| ④ 勾选 H1 改值 + H2 未改值 | ✅（`edited` = true 即整体放行） | **🟡 + 未确认提示**（只要还有一个自动值就不放行） |

**机制**：勾选路径原来把等级交给 `reliabilityLevel({geomStatus, hsStatus})`，而它**只回答"几何/热结分析可不可信"**，
不回答"这个 Mc 是不是用户确认过的"。修复后两条路径**共用同一处事实**（`mcSrc`）与**同一句提示**（`AUTO_MC_NOTE`）。

**边界（明确不变）**：
- 勾选路径**恒为 `WARNING_REVIEW`**——全部改过值也是（与 PHASE 28.5 的单热结人工路径同口径：人工输入需用户自判）。
- "不足"方向不受影响：`volOk` 仍独立判定。
- 取消勾选 → 状态自动回到场景①（`mcSrc` 每次 `calculate()` 重算，**没有新增任何持久化状态**，因此不存在失效残留）。
- 更换产品 → `clearStlBoundData()` 清 `process.hsPick`（既有行为，本次实测确认）。

### D2 —— Mc 来源

| 实际送进 `runRiser` 的 Mc | 修复前显示 | **修复后显示** |
|---|---|---|
| 勾选 H1、Mc = 检出值 14 | 场景②来源行 = "STL 热结检测"（**恰好对**） | 同（且 `mcSrc` = 自动） |
| 勾选 H1、改成 20 | **"来源：STL 热结检测 Mc = 20 mm…自动估计值"**（错，20 是用户填的） | **"来源：用户输入 Mc = 20 mm（未使用 STL 自动热结点）"** |
| 改 Mc 输入框 | 用户输入 | 不变 |
| 无热结 → 壁厚兜底 | 壁厚/结构参考值 | 不变 |

**机制**：新增一个**由 `calcManifest` 在选值处标注**的字段 `mcSrc`（复用项目既有 `SRC` 语义），
随结果一起返回；视图层只消费它，**不再从 `process.mcHotspot` 反推**。
多热结时**逐项**标注（`items[i].mcSrc`），不再整组共用一个判断。

**顺带修掉的两处同源缺陷**：
- 多热结分页的来源行原来用 `|hsMc − Mc| > 1e-9`（数值差）判断——用户把值改回恰好等于检出值时会标错；现按 `mcSrc`。
- 多热结分页的自动值来源行**补上了 06A1 的"自动估计值"限制语**（原来只有单热结路径有）。

> **关于"不得只根据选中的热结或显示值推断来源"**：`mcSrc` 是在**选值处**确定的。对勾选路径，
> "用户是否改过"只能用 `p.mc` 与**引擎检出值** `hsById.get(p.id).mc` 比较得出——这是"用户改没改这个值"
> 的定义，不是从显示值反推来源；项目里 `process.hsPick` 是**整组一个 src**（写入时恒为 `USER_INPUT`），
> 没有逐项标记，本次**没有为此新增持久化字段**（117.txt §三：不引入不必要的新字段）。

### D3 —— 尺寸为什么不变

**先确认能不能可靠归因**：`runRiser` 的循环退出条件是 `modOk && volOk`；
把 `f` **退一格（0.05）**时"哪条约束会失败"，就是对最终尺寸的**确定性**归因。这是对同一次迭代的事后描述，
**不引入新公式、不改变收敛路径**。

| `bind` | 含义 | 界面行为 |
|---|---|---|
| `start` | f 起点 1.10 已双通过 ⇒ 尺寸由 "Mc × 1.10" 决定 | 沉默 |
| `modulus` | 上一轮模数不足 ⇒ 模数约束顶上去 | 沉默 |
| **`volume`** | 上一轮**体积不足** ⇒ 补缩体积校核主导，D/H 对 Mc 不敏感 | **出提示**（见下） |
| `both` | 上一轮两条都不足 | 沉默 |
| **`limit`** | 50 轮未收敛（f 撞上限 3.55）⇒ 当前 D/H **不是收敛解** | **出提示** |

**新增的两句解释**（只在"尺寸不由 Mc 决定 / 结果不可信"时出现，其余沉默以避免噪音）：

```
ℹ️ 本尺寸由补缩体积校核主导（冒口需承担整件补缩量），改变 Mc 基本不会改变 D/H。
   仅按模数（Mc × 1.10）所需直径为 ⌀92 mm。
⚠️ 迭代已达上限（f = 3.55）仍未同时满足模数与体积校核：当前 D/H 不是收敛解，请按「体积校核」一行判断。
```

**没有做的**（117.txt §四 明令）：
- **没有**强迫尺寸随 Mc 变化；**没有**改任何工程公式或系数；
- **归因无法确定时不出结论**——`bind` 缺失（旧结果/测试构造的假数据）⇒ `bindHint` 返回空串，
  **绝不默认说成"体积主导"**（该保守兜底已写成结构守卫 `08-7`）。
