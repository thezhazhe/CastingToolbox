## 4. 冒口问题（P0）—— 现状全貌

### 4.1 原始症状（用户报的）

> 工艺设计中心导入真实产品 STL 后，**按热节算出来的冒口偏大，有些明显超出工程合理尺寸。**

### 4.2 ★★ 已查明事实（两次独立实测，逐位吻合）

**根因不在热点算法，在体积校核那一段。**

`calcs/riser.js:213-216`：
```js
if (cw > 0) { const Vc = cw * 1000000 / rhoUsed; volOk = effV >= Vc * md.shrink; }
```
`cw` = **整件净重**（`calcManifest.js:271`）。**这条约束里没有 Mc。**

**2026-10-14 实测复现**（真实生产函数，设计中心入参形状）：
```
球铁 / 77.56 kg / Mc=11.43 / 圆柱形 / hd=1.0 / eff 缺省 14%
  →  D=144  H=144  f=2.10  bind=volume  converged=true
  →  仅按模数（Mc×1.10）所需直径 = ⌀75 mm      ← 放大 1.92×
  →  冒口重 / 铸件净重 = 21.5%
```
与 **V2.0-01（2026-10-07）** 记录的数字**逐位相同**。

**对照**：不传 `cast_wt`（独立计算器路径）同输入得 **D=75** ⇒ **放大全部来自体积校核段。**

**恒等式**：体积主导区 `冒口重 / 铸件净重 = shrink / eff`（**与几何无关的常数**）。
球铁+圆柱 = 3%/14% = **21.4%** · 球铁+球顶柱 = 12% · 灰铁+圆柱 = 14.3% · 铸钢+圆柱 = 32.1%。
**交叉重量 ≈ 7.5 kg**（超过它体积约束就取代模数约束）。

### 4.3 暂定方案（**历史讨论，未验证**）

原计划 P0 的六条方向里，第 4 条是「**不再让整个铸件体积自动放大冒口**」——
**即使用户看到的现象，也是这条要解决的。它至今未实现。**

第 3 条「`Mr ≥ 1.2 × Mc`，默认系数 1.20」：
- ⚠ **1.20 是曾经讨论的暂定方案，不是已验证的通用工程常数**（133.txt 原文）
- 代码里**设计端**用的是 **`f` 起点 1.10**、步长 0.05、上限 3.55（`riser.js:172,202,219`）
- `MODULUS_RATIO_MIN = 1.2` 存在于 `js/model/processInspection.js:57`，是**工艺检测中心的事后校核阈值**
  （PHASE 88 就有，`phase88_test.mjs:215` 等三条测试钉死）
- **同一个数字：一个是"该做多大"，一个是"做完够不够"。两者从未打通。**

## 8. 环境事实与坑（**全是踩过的**）

### 8.1 环境

1. **本机没有 Chrome，只有 Edge**。浏览器脚本一律走
   `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe` + CDP。
2. **github.com 的 git 传输被阻断**，`git push` 会失败。只有 `api.github.com` 可达。
   → 发版走 `node scripts/publish_via_api.mjs`。远端 main 是**快照提交，没有真实历史**。
3. **`publish_via_api.mjs` 的 `--message-file` 必须是真实文件**：传 `/dev/null` 会被 MSYS 转成 `D:\...\nul` → ENOENT。
4. **`tests/real-stl/` 是作者真实产品几何，不适合公开**。任何截图/演示/发布材料都不许用。
5. **大件测试夹具不入库**（约 2.2GB）。缺时**跳过而非失败**，见 `tests/FIXTURES.md`。
6. **Node 全量跑 ~25 分钟**。**后台跑**（`> /tmp/x.log 2>&1`），**不要用 `| tail`** —— 管道会缓冲到 EOF，看起来像"卡住了"。

### 8.2 几何 / 网格

7. **程序生成的测试件网格都不干净**：四面体 MC 在网格点恰好落在等值面上（`sdf == 0`）时会产出零面积三角形；
   被 `meshComponents` 的退化过滤剔除后**邻居丢一条边** → 组件被判"不闭合"。**这是夹具问题不是产品问题。**
   绕法：把包络整体平移一个小量（PHASE 94 用 `0.0173mm`），或调 `PAD`。
8. **MC 是内接多面体** → 表面积 A 系统性偏小、比 V 偏小更多 → **M=V/A 系统性偏大 0.5~1%**。
   断言应该判**偏差的方向**，而不是给一个宽容差。
9. **`principalAxis` 的 `|det|` bug 已修**（PHASE 94）。**散度定理那套四面体求矩只有带符号体积才成立**。
10. **`sliceArea` 的 `withPoly` 是 opt-in** —— 默认连 `repLoops` 这个键都不建。
11. **性能排查套路：给 `Map.get` 装计数器。** PHASE 97 靠这招发现 `meshDistance.js` 里
    `found = r`（应为 `if (found < 0) found = r`）导致每次邻近查询白扫 180 倍格子 —— **31.3s → 0.18s**。

### 8.3 前端 / CSS

12. **`[hidden]` 会被 CSS 盖掉**：浏览器默认的 `[hidden]{display:none}` 是**元素选择器权重**，
    `.card.section-card` 之类的类选择器权重更高 → 元素照样显示。
    **凡是用 `hidden` 控制显隐的自定义区块，CSS 都要显式写一条 `[xxx][hidden]{display:none}`**。
    且**断言查内容查不出这类问题**——要按 `getComputedStyle` 核验。
13. **CDP `Page.captureScreenshot`**：`clip` 用**页面坐标**不是视口坐标，滚动后要加回 `scrollY`；
    **不要用 `captureBeyondViewport`**（会让 `position:fixed` 的侧栏跑到页面中间）；
    拍移动端要用真实视口（390×844），**不要**拉高视口。
14. **CSS 会被浏览器缓存**。改了 `app.css` 后截图没变化 → 先删 `_edge_*` profile 目录再拍。
15. **写测试选择器时别把 class 当成 id**。**先 `querySelector` 确认拿到了再断言。**
16. **`#g_results` 在收起的 `<details>` 里 → `innerText` 恒为空串**（无布局）。
    探针要用 `textContent`，且**先 `replace(/\s+/g,' ')` 归一化**。
17. **`paint()` 不重跑 `bindImport()`** → 重绘后导入来源徽标说假话（PHASE 96 实测）。

### 8.4 i18n

18. **审计只扫 `t('...')` / `tr('...')` 字面量** —— 动态 key（对象表的值）扫不到，**必须手工登记**。
19. **占位符按出现顺序代入**。**译文重排会让"类型名填进限值"** —— PHASE 96 加了一条整体测试守住。
20. **英文词条含中文会挂 `72-T5`**。修法**不是**改白名单，而是让英文值包含白名单里**已有**的词条。

### 8.5 本机工具链

21. **★ 本机 `sed -i` 会吃掉 CR**：`a\r\nb\r\n` → `A\nb\n`（实测）。
    **cmd.exe 解析不了 LF-only 行尾的 `.bat`** —— 多行 `if (...)` / `for … do (` 块会被拆碎。
    **改 `.bat` / 任何给 cmd 用的文件，不要用 `sed -i`，用编辑工具。**
22. **量行尾不要用 grep 正则**：BRE 里 `\r` 只是字面字母 `r`。用 `git ls-files --eol` 或 Node 逐字节统计。
    **这个仓库的行尾本来就是混的** ——看到行尾警告先确认真实状态再慌。
23. **★★ 给 git 写中文 commit message 一律用 `-F 消息文件`，不要用 `-m` 内联。**
    本项目命令里天然带大量中文引号与反引号，bash 会把它们当字符串结束符 ——
    PHASE 98 实测：那次没真的执行，但**离"真的执行了一条删除命令"只差一个反引号**。
24. **`src.length` 不是字节数**：`readFileSync(f,'utf8')` 返回**字符串**，`.length` 是 **UTF-16 码元数**。
    `riser.js` 是 **19,958 字节 / 14,094 字符**。**要指纹就用 `createHash('sha256')`。**
