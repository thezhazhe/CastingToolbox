## 5. 冒口计算定义（§八）

| 量 | 定义 | 来源 |
|---|---|---|
| 体积 `V` | 冒口实体的封闭体积（mm³） | `engine/stl.js` `computeVolume()` |
| 表面积 `A` | 冒口实体的表面积（mm²） | `engine/stl.js` `computeArea()` |
| **模数 `M = V / A`** | 单位 mm | `model/objectMetrics.js` `modulusMm` |
| 包围盒 / 中心 | `computeBounds()`；中心 = 包围盒中心 | 同上 |
| 有效性 | 连通分量的 `closed`（网格是否水密） | `model/meshComponents.js` |

**没有引入新的模数定义**（§八 的硬要求）。`M = V/A` 是项目里唯一的实现，
本次没有第二套公式、没有复制粘贴。

### 5.1 不闭合的冒口 → 不给猜值（§八 末段）

`objectMetrics()` 是通用几何函数，对不闭合网格**也会算出一个 V/A**。检测层必须挡住它：

```
volumeReliable === false  →  riserModulus = null,  reason = 'not_closed'
表面积为 0 / 体积非正      →  riserModulus = null,  reason = 'zero_area'
```

此时判定为 **INFO +「无法可靠计算冒口模数」**，既不算「满足」，也**不算「不足」**
（tests/phase93_test.mjs 的 93-E 专门锁这条，并且先断言 `objectMetrics` 确实算出了值 —— 正因如此才必须挡）。

### 5.2 几何真值校验（§二十一）

先用**理论答案已知**的几何验证，再接真实 STL。实测（本机 res=48）：

| 几何 | 解析 V | 解析 A | 解析 M | 实测偏差 |
|---|---|---|---|---|
| 立方体 a=40 | 64000 | 9600 | 6.667 | V −0.01% · A −0.52% · **M +0.51%** |
| 圆柱 r=20 h=60 | 75398 | 10053 | 7.500 | V −0.18% · A −0.95% · **M +0.78%** |

偏差是**有方向的**：MC 得到的是**内接**多面体，棱/角处被切掉 → A 系统性偏小、且比 V 偏小得更多
→ M = V/A 系统性偏大。这是网格离散化的固有性质，不是算法缺陷。
测试因此断言**偏差的方向与量级**（A 只可能偏小、M 只可能偏大），而不是给一个宽到没有信息量的容差。

## 6. 模数比定义（§十）

```
模数比 = M_riser / M_hotspot
判据   = 模数比 ≥ 1.2  →  满足（PASS）
         模数比 < 1.2  →  不足（WARNING）
         算不出来       →  INFO（说明原因，不参与判定）
```

- **阈值只有一个：`MODULUS_RATIO_MIN = 1.2`**（沿用项目已有定义，§十 明确禁止重新发明）。
- **没有**引入 1.3 / 1.5 / 安全系数 / 材料修正 / 灰铁球铁特殊修正。
  tests/phase93_test.mjs 的 93-P 直接从源码里扫这段判定逻辑，要求除 `MODULUS_RATIO_MIN` 外**不出现任何硬编码阈值**。
- 边界按 `≥` 处理：恰好 1.20 判满足（93-H 锁死）。
- 距离**只计算 + 展示，不设红线**（沿用 88.txt §十三 的纪律）—— 只给 INFO。

### 6.1 不制造「负责冒口」（§十一）

工程模型只能支持**几何最近关系**，推不出补缩责任。因此：

- 字段名一律 `nearest`（最近），**不用** `responsible`。
- UI 只出现「最近热点 / 最近冒口」，并显式标注「**几何关系**」。
- 93-Q 是一条**机器可查的措辞纪律**：把注释剥掉后扫源码，只要「负责」与「冒口/热点/热结」同句出现、
  且不是否定句（"本版不做…的判定"这类辟谣句是规则本身的落地），测试就失败；
  英文侧禁止 `responsible`。

### 6.2 不制造过度承诺（§十末段）

- 卡片判语是「模数比满足要求」/「模数比不足」，**不是**「一定不会缩孔 / 一定能补缩 / 工艺一定正确」。
- 结果区固定带一句限定：模数比是**几何模数检查**，阈值 1.2 是经验设计参数，
  不等同于凝固模拟结论，也不代表"一定不会缩孔"。
- 93-Q 同时断言：视图里出现的所有「一定/保证/必然」类文案，必须带否定限定。

## 7. 多冒口处理方式（§八/§九）

- 支持：**一个 STL / 多个 STL / 一个 STL 内多个独立封闭实体**（沿用已验过的连通分量拆分，没有重新发明）。
- 内部统一编号 **R1 / R2 / R3 …**（按导入顺序；93-A/B/C 与浏览器测试都锁了「编号 = 顺序、不错位」）。
- 内部计算 **N（冒口）× M（热点）全部关系**，但 UI **默认只显示最近的那一个**；
  存在多个热点时才出现「查看全部热点（N 个）」，点开是一张小表，**不是**默认铺开的矩阵。
- 计数是**互斥且完备**的四分类：`满足 + 不足 + 不可信 + 无热点可比 = 冒口总数`（93-O 锁死）。

## 8. 多产品处理方式（§七）

- 继续支持单产品与多产品：一份 STL 里多个独立封闭实体 → 按连通分量拆成 **P1 / P2 / P3**（沿用 PHASE 89/91 已验过的机制）。

### 9.1 浏览器测试抓到的两个真 bug（已修）

1. **`setHighlight(null)` 把全部对象压暗了** —— 语义应是「没有任何选中 → 全部原色」。
   写反了会被"看起来对"的截图骗过去（模型只是暗一点），但页面一进来就是灰的。
2. **卡片上的 `data-pi-sel-kind` 与 `data-pi-sel` 都是"类别"**，传给选中函数的 ID 变成了字符串 `'riser'`
   → 高亮匹配不到任何对象。改为一律 `data-pi-sel`（类别）+ `data-pi-id`（具体 ID）。

### 9.2 单元测试抓到的一个真 bug（已修）

`derive()` 返回的是 `{hotspots, relation, summary}`，其中 `relation` 是 `buildRiserRows()` 的**整个返回对象**
（`{rows, counts, distances}`）。`renderDetail` 有一处写成 `d.rows.map(...)`，
在浏览器里抛 `TypeError` 并**中断了整个 paint 链** —— 卡片与详细表都不会画出来，但导入计数照常更新，
表面上「有反应」。已改名为 `d.relation.rows` 并加空值保护。

## 12. 已知限制

1. **只做几何模数检查，不做凝固判断。** 模数比 ≥ 1.2 不代表「一定不会缩孔」；
   本阶段**没有**流速 / 流量 / 充型时间 / 分流比例 / 压头 / 湍流判断（§十七：先把"几何截面积可靠"证明出来再说）。
2. **热点位置用的是引擎代表点，不是显示层的微调点** —— 两者可能差几毫米，
   卡片上的「距离」因此与 3D 里看到的 marker 位置可能有细微出入。这是刻意的：工程计算一律用引擎原值。
3. **最近热点是几何最近，不是工艺上"该被补缩"的那个。** 本版不做补缩区域划分（feed zone）。
4. **MC 网格的内接偏差**：A 系统性偏小 → M 系统性偏大约 0.5~1%（见 §5.2）。
   这是网格离散化本身的性质，对模数比（两个 M 相除）影响部分抵消。
5. **移动端底部标签栏放不下「试用中」**，窄屏（≤768px）时该标记从标签栏收进页面标题旁 ——
   两处至少有一处可见，但**不是同时可见**。
6. **PHASE 89~92 的浇注系统端到端覆盖随功能一起退役**：那套代码保留、单元测试（phase89~92）仍然守着模型层，
   但页面级的 E2E 不再覆盖它（因为它已经不在页面上）。要恢复 UI 时需一并把 E2E 挂回去。
7. 侧栏一级导航现在是 5 项；`scripts/browser_test.mjs` 的计数断言已同步（见 §1.1）。

4. 恢复浇注系统 UI 时，一并恢复它的页面 E2E（见 §12.6）。
