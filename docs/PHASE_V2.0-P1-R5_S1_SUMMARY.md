## 3. 修了什么

### 3.1 ★ S0 查出的两处"文案与实际计算相反"

**根因**：判据是 `hotspots.items` 有没有，不是 `hotspots.status`。而 items 在两个失败分支里**都会被写入**：

| status | 原界面显示 | `calcManifest` 实际 |
|---|---|---|
| `NO_HOTSPOT` | 主体壁厚 ÷ 2 = X | 用 `wallHot` ✅ 一致 |
| `LOW_CONFIDENCE` | **来源：STL 热结检测（最大热结 H1）** | **阻断，不计算** ❌ |
| `INSUFFICIENT_RESOLUTION` | **主体壁厚 ÷ 2 = X** | **阻断，不计算** ❌ |

**做法**：新建纯模块 **`js/views/hsSourceNote.js`**（166 行，无 DOM）作**单一来源** —— 照搬 V2.0-15 的 `riserStatus.js` 范式。设计中心只负责渲染。

**五态 → 实际文案**（浏览器逐态实测）：

| 状态 | 阻断 | 文案要点 |
|---|---|---|
| `ok` | 否 | 来源：STL 热结检测（H1）＋"自动估计值，尚未验证适用于所有几何" |
| 勾选热结 | 否 | 逐热结各用各自 Mc，主结果取 Mc 最大者 |
| **用户填了 Mc** | 否 | 「来源：**用户确认的** Mc = X —— 不是自动热结检测结果（状态：…）」，不声称检测可靠 |
| `NO_HOTSPOT` | 否 | 主体壁厚 ÷ 2 = X **＋ reason 原样带出** |
| `LOW_CONFIDENCE` | **是** | 「本次**不会**给出冒口建议 —— 推荐值不成立，也**不是**按主体壁厚 ÷ 2 估算」 |
| `INSUFFICIENT_RESOLUTION` | **是** | 同上口径 |
| `none` | 否 | 没有 STL 热结检测结果 |
| 取不到正值 | **是** | 与 `calcManifest` 的 `if (mc <= 0) return null` 对齐，不假装有值 |

**两条最容易做错的地方**（都写了正反两向断言）：

- **取值优先级必须与 `calcManifest` 逐支同序** —— 有热结项只看 `mcHotspot`；无热结项**先 `wallHot` 再 `mcHotspot`**。做反了就是"界面说用的是用户值、实际用了别的"。
- **几何 `INVALID` 是硬阻断**，人工填 Mc 也**不能**放行（V2.0-10 定案）—— 不再只给一个看似正常的推荐值。

### 3.2 ★ `rejected` 不再被说成"无热结"

`hotspotV3.js:240` 会产出裸字符串 `reason:'rejected'`（**有候选、也做了审计，但一条都没通过**），
它不在 `HS_REASON` 枚举里 ⇒ 原来一律回落成"无热结"。

`js/engine/**` 冻结 ⇒ 该键**只加在显示层**（`designCenter` + `processPage1` + `hsSourceNote`）。
**对照组已验证**：真·`no_candidate` 仍显示"未检测到热结候选"，两种原因没被合并。

> ★ 这一条**是浏览器测试抓出来的，不是我预先想到的**：`NO_HOTSPOT` 分支原来根本不带 reason，
> `rejected` 没地方显示。

### 3.3 ★ 两笔欠账真接线了

**↺ 恢复自动原值**（Mc / 主体壁厚 / 毛坯重量三处）

`restoreAutoValue()` 恢复的是 **v + src + conf 三件一起**，不是"把数字改回去"。

**关键决策**：R4 是草稿→保存两段式，而它**立即写项目** —— 直接拼会破掉「保存前项目数据不变」。
所以点 ↺ 只往 `state.draftRestore` **标记意图**，保存时才落盘；返回 `false` 时**如实报告**。
**只有真有 `orig` 且来源是 `USER_OVERRIDE` 才渲染入口** —— 没有原值的字段一个 ↺ 都不出现。

实测：改 77 保存 → `orig=50` ✅；点 ↺ → **项目一字未改**（仍 77）✅；保存 → `{v:50, src:STL_GEOMETRY_ANALYSIS, conf:high}` ✅。

顺带修 `srcTagHtml`：原来 `title` 里**写死**「（↺ 可恢复）」而界面上从来没有那个 ↺ ⇒ 改成"给了入口才提 ↺"。

**逐热结改 Mc**（参数窗口 B 模块行内，不是左栏）

每行 = `H1` + 检出模数 + 区域体积 + 置信度 + 该热结自己的「✎ 冒口设计 Mc」。
按 id 绑定，**改 H1 时 H2 一字未动**（实测）；只改草稿，保存前项目不变（实测）；
逐项来源标注正确（改过的 `USER_OVERRIDE` / 未改的 `STL_GEOMETRY_ANALYSIS`）；
未勾选的行输入框**禁用**（那条路径根本不计算，可编辑就是假入口）；
另有「↺ 改回检出值」，实测**点了+保存后确实回到检出值**（不是假按钮）。

### 3.4 `hsPick` 双入口来源语义统一（**按枚举定义判定，不是为一致而一致**）

`USER_INPUT` = 用户直接输入；`USER_OVERRIDE` = **用户修改了自动值**。

**判定用 `USER_INPUT`**，三条依据：① `hsPick` **没有自动写入口**（默认 `[]` = 自动模式）；
② `set()` 只在原来源是 STL/DERIVED 时才固化 `orig` ⇒ 标成 OVERRIDE 时 `orig` 永远不存在，
**图例却承诺"可 ↺ 恢复"** —— 一个兑现不了的承诺；③ v1.1.0 与左栏本来就是 `USER_INPUT`。

**没有丢失任何真实区别** —— 对这个参数而言那个区别本来就不存在。左栏勾选行为一字未改。
另修正了一处**注释与实现不符**（原注释称"逐热结 Mc 编辑在 B 模块里"，而 146 轮删掉后其实没有）。

### 3.5 失效指路文案（3 处）

145/146 删掉的入口，文案还在指路 ⇒ 全部改指真实位置（顶栏「⚙️ 分析条件与工艺参数」A/B/C 模块）：
