## 7. “保存”和“分析”的实际行为及数据生命周期

### 7.1 行为

| 动作 | 行为 |
|---|---|
| 编辑参数 | 只写 `state.paramDraft`；项目不变 |
| 点「保存」 | 写入 `CastingProject`、清草稿、重渲染来源徽章/热结行；已有结果 `markChangedStale`；**不调用 runAnalysis/autoRecompute** |
| 无修改点「保存」 | 明确提示“参数未发生变化”，**不把全部结果误标过期**（旧实现的空数组会走 `markAllStale` 兜底） |
| 顶部 ④「分析」 | 检查草稿 → 有草稿时确认“先保存再分析” → 参数门禁 → 完整 `runAnalysis` → 刷新结果/状态 |
| 分析失败 | `lastRun.ok=false`；旧结果保留但标记过期；不清空、不冒充最新 |
| 保存后不分析 | 状态 chip/横幅立即显示“结果已过期”；等待也不会自动分析 |
| 重复点分析 | `state.busy` + 250ms 去重；不会重复绑定 DOM、不会卡在“分析中” |
| 分析过程中切换面板 | `runAnalysis` 是同步执行；期间只置 `state.busy`，不重建/重绑分析链；不存在并发分析 |
| 保存失败 | 显式 toast；草稿保留；不触发分析 |
| 切换面板 | 草稿保留；关闭需确认；不静默丢失 |
| 换 STL | STL 绑定数据清除；用户 RH 保留并 toast 提示复核；结果重建 |
| 结果页内联参数 | **保留原有直接操作语义**：写项目 + 600ms 防抖重算；它不是参数窗口的“保存”按钮，本阶段未改为显式分析（见 §13 待决策） |

### 7.2 数据生命周期

`CastingProject` 是唯一权威参数/结果存储；`state.paramDraft` 只活在面板会话；`state.stale` 是唯一结果有效性标记；`state.results` 是最近一次成功分析。保存后 `stale` 立即置位；只有 `runAnalysis` 成功才清空并更新 `results`。失败分支回滚本次写回的 `runner.result / risers.items / yield.result`。

### 7.3 验证

- 首次保存：`flow=B`、无结果状态条、状态 chip 为“参数有效，可开始分析”；点 ④ 后才出现结果。
- 改形状保存：过期横幅出现；等 1.3s 仍过期；点 ④ 后清除，项目形状为新值。
- 未保存草稿点 ④：先弹确认；取消 → 项目不变、草稿仍在；确认 → 保存 + 分析成功。
- 空保存：结果仍“当前结果有效”，无过期横幅。

## 8. 出品率修改前后口径及测试案例

### 8.1 核心改动（仅允许范围）

`calcs/calcManifest.js` 的 `yield.calculate` **新增字段**：

| 字段 | 公式 | 说明 |
|---|---|---|
| `cavityCount` | `g.cav`（回退 `production.cavities`） | 实际采用的型腔数 |
| `castingMass` | `g.castingMass`（回退 `单件 × 腔数`） | 整模铸件毛坯重 |
| `riserUnit` | 单套冒口重（与旧 `riserWt` 同值） | 明确“单套” |
| `riserWtTotal` | `riserUnit × cavityCount` | 整模冒口重（每腔一套假设） |
| `gatingWtResidual` | `G − castingMass − riserWtTotal` | **反推残差**，不是实测浇道重 |

## 13. 仍未解决的问题及原因

4. **底注 Hp 不随 RH 变化**：现有公式事实，未在 S4 改；是否需要工程口径调整需单独决策。
