## 3. 冻结的核心算法规则

以下规则**逐条对应代码行**，均为当前工作区的真实实现。

### 3.1 尺寸决策（唯一的尺寸来源）

| # | 规则 | 位置 |
|---|---|---|
| 1 | 目标冒口模数 `Mr_target = Mc × MODULUS_TARGET_RATIO`，`MODULUS_TARGET_RATIO = 1.2`（唯一命名常量） | `calcs/riser.js:32`、`:248` |
| 2 | 推荐尺寸由 `Mr_target` **直接反求**；**不存在** f 迭代、不存在 f 上限 3.55 | `calcs/riser.js:239-249` |
| 3 | 高径比取整规则**只有一条**：`H = round(D × hd)`，再按形状修正（`sphere_head` 补 `H ≥ r`、`sphere` 取 `H = D`） | `calcs/riser.js:219-224` |
| 4 | 尺寸取**最小可行整数档**：先上探达标，再下探到最小（上探/下探各限 8 档） | `calcs/riser.js:235-236` |
| 5 | 连续解取整为 0 ⇒ **原样返回，不得升档抢救**（退化输入必须判 `null`） | `calcs/riser.js:234` |
| 6 | 取整后**必须真正达到**目标：`Mr_act ≥ Mr_target`（浮点精度内），否则返回 `null` | `calcs/riser.js:263` |
| 7 | 四个形状（`cyl` / `sphere_head` / `sphere` / `square`）共用同一规则与同一几何公式（几何公式**未改动**） | `calcs/riser.js:58-94` |

### 3.2 浮点判据

| # | 规则 | 位置 |
|---|---|---|

| 9 | `meetsTarget` 是全模块**唯一**达标判据，三处共用：尺寸搜索 `okAt` / 返回守卫 / `modOk`+`converged`（口径必须一致，否则会出现"搜索接受、守卫拒绝 ⇒ 合法输入返回 null"） | `calcs/riser.js:229,263,270,283` |

### 3.4 冻结边界

**在冻结范围内**：上述 1~14 条 + `calcs/riser.js` 的全部行为（含输入守卫三态语义，`calcs/riser.js:96-200`）。

- `js/engine/**`（V3 热点引擎，`Mc` 的来源）—— 冻结区仅指"本轮不得改动"，其**精度局限仍在**（见 §6.2）。

- 旧体积约束本身的**工程正确性** —— 它只是被降级，其假设问题（"整件净重由单个冒口承担"）**未解决**。
- `MODULUS_TARGET_RATIO = 1.2` 的**工程取值** —— 见 §6.3。

### 3.5 冻结的含义（后续开发约束）

1. 以当前实现作为**后续开发的基准**。
2. 没有新的真实案例或明确的缺陷证据时，**不再调整**冒口计算规则。
3. **后续 UI 改造只能调用现有计算入口、展示已有结果，不得顺便重写算法。**
4. 未来若发现确实影响计算正确性的 Bug，可以提出独立修复，但必须同时给出：证据、影响范围、回归测试。
5. 冻结**不意味着**宣称该算法已经过真实生产验证。

## 7. 解冻条件

出现下列**任一**情形才解冻，且必须走独立阶段（含证据、影响范围、回归测试）：

1. 有证据证明当前实现存在**计算错误**（含几何公式、取整规则、浮点判据）。
2. **真实铸件案例**揭示明确、可重复的问题（`cases.csv` 录入 ≥3 条，含反向案例）。
3. 发现会导致**错误结果展示**或**计算结果失效**的关键缺陷。

下列情形**不构成**解冻理由：

- 单纯觉得 `1.2` 偏大或偏小（无数据支撑）。
- 单纯希望尺寸更小 / 更大 / 更好看。
- 为了让某个旧测试"回到绿色"。
- 因为旧体积校核报"不足"（它已不是判据）。
