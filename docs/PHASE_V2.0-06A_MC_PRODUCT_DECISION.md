## 1. 当前 Mc 对产品的实际影响

### 1.1 Mc 在产品里流向哪里【源码确认】

| 去处 | 代码 | 与 Mc 的关系 |
|---|---|---|
| 自动 Mc 唯一来源 | `js/views/designCenter.js:803` `mcHotspot = round(hs.hotspots[0].mc × 10)/10` | **只取主热结 H1**，四舍五入到 0.1 |
| 冒口所需模数 | `calcs/riser.js:88` `Mr_need = Mc × f`（f 从 1.10 起、每 0.05 递增至双通过） | 线性 |
| 冒口直径 | `calcs/riser.js:90` `D = sd.DfromM(Mr_need, hd)`；圆柱 `DfromM = Mr(2+4hd)/hd`，hd=1 → **D = 6·Mr_need** | **线性 ∝ Mc** |
| 冒口颈直径 | `calcs/riser.js:117` `d_neck = round(4 × Mc × neck_k)` | **1:1 线性 ∝ Mc** |
| 冷铁默认壁厚 | `calcs/calcManifest.js:350` `T = process.chillT \|\| mc × 2` | 内建假设 **Mc = 壁厚/2** |
| 冒口检测判据 | `js/model/processInspection.js:177` `ratio = riserModulus / h.mc`；`ok = ratio ≥ 1.2` | **Mc 偏低 ⇒ ratio 偏高 ⇒ 偏"合格"** |
| 体积校核 | `calcs/riser.js:107` `volOk = effV ≥ Vc × shrink` | **与 Mc 无关**（唯一缓冲） |

### 1.2 出错会导致什么

- **偏大**：出品率下降、成本上升，不危险。
- **偏小（当前方向）**：`D` 与 `d_neck` 同步缩小 ⇒ 冒口先于热节凝固 ⇒ **不补缩**；冷铁按偏薄截面配 ⇒ 冷铁不足；`ratio ≥ 1.2` 判据虚高 ⇒ **假 PASS**（安全判据失效）。
- **缓冲**：`volOk` 是独立于 Mc 的体积校核。重量已知且体积校核主导时（V2.0-05A 实测 HR4012：Mc 8→20 冒口完全不变），Mc 误差被掩盖；**只有在模数主导的场景才暴露**。

### 1.3 用户需要什么精度

产品里**没有**任何现成的 Mc 数值容差【源码确认，全仓检索无 `expectMc` 断言、无容差定义】。
**不编造行业标准**。按 §二 提出的**项目内部临时验收标准**（标明：这是本项目建议，不是行业标准）：

| 级别 | 判据 | 理由 |
|---|---|---|
| 不可接受 | 偏差改变冒口**有无补缩能力**的结论（即 `Mr_act` 跨过真实热节模数） | 方向性错误 |
| 可接受 | |报告 Mc ÷ 局部模数 − 1| ≤ **20%** | 小于 rd 级档差，不改变"是否需要加大一档"的判断 |

20% 的出处：`DfromM` 与 `d_neck` 对 Mc 都是线性，20% 的 Mc 误差 = 20% 的尺寸误差；而冒口直径每档相差约 10~20%。**这是项目建议值，不是行业标准。**

## 2. 已有证据与最小独立验证结果

### 2.1 已有证据（V2.0-05A~05H）

- 【实测·05G】`Mc ≡ (1/3)×d(峰点)` **逐位成立**（12/12 配置，残差 0）；coarse 场 capped 比例 11/12 = 100.00%。
- 【实测·05G】thickEnd 的 `d_max = 30.000000`（独立扫掠测定），L1→L4 缺口 7.81% → **0.17%**。
- 【实测·05H】`d = 0` 洞点曾带 `M = 未封顶 V/A`（最高 1.559× Mc），已修（净改 1 行）。
- 【源码确认·05A】`modulusCeilRatio` 三处现成解析真值**从未被消费**；收敛性从未测过。

### 2.2 最小独立验证 A：纯几何对照（无采样格点、无 M 场、无 ceiling）

`phasev2006a_window_vs_ceil.mjs` —— 解析已知几何，直接在**热中心**调 `windowVoxels(vox, center, R = 2×d_true)`：

| 几何 | 解析模数 | (1/3)·d | **(1/3)d ÷ 解析** | **窗口 V/A** | **窗口 ÷ 解析** |
|---|---|---|---|---|---|
| 板 300×200×40 | **20.000**（t/2） | 6.667 | **0.333** | **20.000** | **1.000** |
| 立方 100 | 16.667（a/6） | 16.667 | 1.000 | 16.667 | **1.000** |
| 圆柱 ⌀80×120 | 15.000 | 13.333 | 0.889 | 12.787 | 0.852 |
| 厚端块 120×60×60 | 12.558 | 10.000 | 0.796 | 12.444 | **0.991** |
| pvpPair 板 80×60×30 | 8.000（6 面下界） | 5.000 | 0.625 | 7.935 | 0.992 |

**【实测】关键结论：同一个物理位置上，"窗口 V/A"复现解析模数到 0.85~1.00×，
而引擎的 "(1/3)d" 在板状件上低了 3 倍（0.333×）。**
窗口 V/A 在 vs = 10 / 5 / 2.5 / 1.25 四档**全部稳定**（板四档都恰好 20.000）。

**几何依赖的解析解释【推测，但可手算核对】**：
对无限板 `M = t/2 = d`、圆柱 `M = D/4 = d/2`、球 `M = D/6 = d/3`。
⇒ 正确的几何因子是 **1(板) / 1/2(圆柱) / 1/3(球)**，而 `modulusCeilRatio` 是**一个与几何无关的常数 1/3**，
只对最紧凑的形状成立。这解释了上表的 1.000 / 0.889 / 0.333。

### 2.3 最小独立验证 B：不能简单取消 ceiling（20 模型实证）

`phasev2006a_models20.mjs` —— 生产参数 vs `modulusCeilRatio = 1e9`（实验旋钮，不改进生产代码）：

| 观测量 | 结果 |
|---|---|
| Mc(封顶) ÷ Mc(未封顶)，n=15 | min **0.110** · p50 **0.208** · max 0.289 |
| 检测状态改变 | **5/20**：t09 · t12 · t13 · t15 · t17 由 `ok` → `NO_HOTSPOT` |
| 热点数改变 | **10/20** |

**【实测】未封顶场的全局 argmax 落在近表面点**（窗口被表面切掉 → 只剩薄层 → `V/A ≈ 2d` 虚高，
如 uniformCube 65.625 vs 真值 16.667）——**这是几何伪影，不是模数**。

⇒ **ceiling 是检测链的承重墙**，不是可以拿掉的补丁。这也**证伪**了"直接改用未封顶 V/A"这条修复路线。

### 2.4 最小独立验证 C：窗口 V/A 离开热中心迅速退化

`phasev2006a_local_va.mjs` —— 在引擎报告的**代表点（region 质心）**上测窗口 V/A ÷ 报告 Mc：

n=20，比值 **0.921 ~ 5.830，中位 1.444**。

**【实测】同一个"窗口 V/A"，在热中心上准（0.85~1.00× 解析），在代表点上散成 0.92~5.83×。**
⇒ 它是**位置敏感**的量；换估计量不是"最小修复"，而是把**稳定的几何偏差**换成**脆弱的定位偏差**。

## 3. 当前方法是否满足产品目标

| 热结形态 | 实测 Mc ÷ 解析 | 是否满足 §1.3 的 20% 判据 |
|---|---|---|
| 等轴/块状（立方） | **1.000** | ✅ 满足 |
| 厚端块（120×60×60） | **0.796** | ⚠ 临界 |
| 圆柱（⌀80×120） | **0.889** | ⚠ 临界 |
| **板状（t=40）** | **0.333** | ❌ **不满足，低 3 倍** |

**结论：不满足。** 对板状/长条状热结（厚板、板+凸台、长条肋、箱体厚垫），
自动 Mc 系统性偏低，方向是"冒口偏小 + 判据偏合格"，即**危险方向**。
对等轴热结则基本可用。

【未验证】真实铸造件的温度/缩孔实测数据本项目没有，故**无法**用实际废品率验证以上偏差；
本表的"解析模数"是经典凝固模数公式，属工程公认量，但不是本项目的实测真值。

## 4. 最终决策

# **C —— 暂时限制功能适用范围**

**为什么不是 A**：板状热结实测低 3 倍，且方向危险（§3），不满足 §1.3 验收标准。

**为什么不是 B（没有最小修复方案）** —— 三个候选逐一被证据否掉：

| 候选 | 否掉它的证据 |
|---|---|
| 改大/取消 `modulusCeilRatio` | §四 禁止仅凭理论改；且【实测】取消 ⇒ 5/20 状态崩、10/20 热点数变；单一常数无法表达 1 / 1/2 / 1/3 的几何依赖 |
| 改报"未封顶窗口 V/A" | 【实测】未封顶场 argmax 落在近表面伪影（§2.3）⇒ 会改峰选择 ⇒ 属核心算法语义变更 |
| 改报"热中心点的窗口 V/A" | 【实测】热中心上确实准（0.85~1.00×），但要**只在该点**取值就必须先修"窗口被表面切掉"的伪影 ⇒ 核心算法重写 |

⇒ 满足 §六 的停止条件："**如果需要大规模重写 M 场或改变核心算法定义，则停止实施，先报告必要性、收益、成本和风险。**"

## 6. C 的适用限制与最小后续行动

### 6.1 适用限制（**建议照此标注给用户**）

- **可以继续用的能力（保留）**：热结**定位**、**排序**、**相对比较**、区域体积、置信度。
  【实测·BASELINE】峰值检出 19/20（PHASE 85），这部分不受本次结论影响。
- **不得直接当模数真值用的**：自动 Mc 用于 **① 冒口尺寸/冒口颈 ② 冷铁默认壁厚（2×Mc）③ 冒口检测的 1.2 模数比判据**。
  这三处的 Mc 必须来自**用户按热节壁厚输入**（产品已有入口：`process.mcHotspot` 用户覆盖
  + `resultsCenter.js:43` 的 `mcUser` 分支 + `riser.js:68` 的「热节圆直径 d」口径）。
- **偏差量级（可直接写进说明）**：等轴热结 ~0~20%；圆柱 ~11%；**板状热结可达 −67%（低 3 倍）**。

### 6.2 最小后续行动（两步，第一步零算法改动）

**第一步（产品层，可立即做，不碰引擎）**：
在自动 Mc 的展示处（`resultsCenter.js:43` 的"来源：STL 热结检测 Mc = …"、
`processPage1.js:120` 的"最大热节 Mc"）增加一行限制说明，并在检测页/结果页把
**"自动 Mc"与"用户输入的 Mc"** 的用途区分开——模数比 1.2 判据在 Mc 来自自动值时给出"结论仅供参考"的标注。
> **本阶段未实施**：112.txt §六 首句为"本阶段默认只读"，且这是**对外可见的文案改动**，
> 需要你确认措辞后再动。文案与落点已在上表列全。

**第二步（需 06B 决策，属核心算法变更）**：
把热中心点上的估值量从 `(1/3)·d` 换成**窗口 V/A**（或几何感知的 ceiling），
**前提条件是先消除"窗口被表面切掉 → V/A ≈ 2d"的近表面伪影**。
- 收益【实测】：热中心上 0.85~1.00× 解析，板状件由 0.333 → 1.000
- 成本：触及 `modulusField.js` 的 ceiling 语义 ⇒ 峰值/排序/`normalizedModulus`/`confidence` 全变 ⇒
  `peakMinRatioSoft` · `peakProminenceMin` · `uniformPromTop2Ratio` · `regionVolumeMaxRatio` 需重标定
- 风险：20 模型里有 5 个靠 ceiling 维持 `NO_HOTSPOT`；伪影不除就会把伪峰报成热点
- 验证方式（若做）：5 个解析几何上 `|Mc ÷ 解析 − 1| ≤ 0.20`，且 20 模型的检测状态逐项对照解释

## 7. 对 V2.0 后续开发的直接建议

1. **不要为 Mc 单独开新研究阶段**。根因已定位到一个常数与一个估计量的语义错配，
   再做的实验不会产生新的决策信息（§2.3/§2.4 已经排除了两条简单路线）。
2. **把 06B 定位成"产品可用性收口"而不是"算法研究"**：
   先做 §6.2 第一步（文案 + 用途区分），再决定是否走第二步。
3. **`modulusCeilRatio` 的语义要在 06B 前置裁决**（05G 已标记，本阶段未动）：
   它到底是"检测用的场形常数"还是"模数上界"？两个用途必须拆开，否则永远互相拖累。
4. **建议顺手统一产品口径**（低风险、高一致性收益）：
   目前 4 处 `距离/2` 与引擎 `距离/3` 并存，即便暂不改算法，也应先让 UI 明确说明用的是哪一个。
5. **不要碰的**：`calcs/riser.js` 的公式、体积校核、`regionVolumeMaxRatio`、
   `phase24 T5`（V2.0-03 遗留，见 `BASELINE.md` 追加段）。
