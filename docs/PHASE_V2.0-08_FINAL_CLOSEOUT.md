### 1.2 检查过、判定**不构成问题**的项

- **自动估算的 Mc 被表述为已验证的准确值** —— **不成立**。`AUTO_MC_NOTE` 一直在报告里（`.meta` 行），
  含「未经确认」「尚未验证适用于所有几何」。**缺的是等级（R1）与来源行（R2），不是限制说明本身。**
- **`limit`（迭代撞上限）时报告误导** —— **不成立**。该情形下 `volOk === false`，
  报告显示 `体积补缩 不足，需加大冒口或加冷铁 ⚠️`，用户不会误判为可用。页面另有一句更精确的
  「不是收敛解」，属**更强的表述**而非**缺失的限制**。
- **第 6 节「WARNING / 数据可靠性」显示"无警告"** —— **不成立**。该段收集的是 `warnings` 数组
  （采样欠解析、各模块警告），与冒口可信度是两回事；冒口的限制说明本来就走冒口块的 `note`。

### 1.3 关联文件：核验后**不需要改**

- **② `riserView.js`（独立冒口计算器）**：该入口的 Mc **从来不是自动估计值**——三种模式
  （`direct` 直接输入 / `hot_spot` 输入 d 取 d/2 / `wall` 输入 t 取 t/2）**全部由用户输入驱动**，
  且 `prefillMaterial` 只带入材质、**不带入任何项目里的 Mc**（`js/views/riserView.js:5,323`），
  结果中心也没有任何跳转到该计算器的入口。⇒ 不存在"自动估算被当成用户输入"的场景，
  报告写「热节模数 Mc = …」与事实相符，页面与报告口径一致。
- **③ `wizard.js`（向导）**：`state.mcMode === 'wall'` 时 `mc = state.wall / 2`（`wizard.js:396`），
  是**由用户填的主壁厚直接换算**，不是任何自动检测结果；同一张表里紧挨着就印着 `主壁厚 24 mm`，
  两个数字可互相印证。向导全程无 STL、无热点检测 ⇒ **不存在"自动 vs 已确认"的区分需要标注**。
  另：向导「毛重当补缩金属量」的口径问题属 118.txt §三**明确排除项**，本阶段不处理（见 §6）。

### 逐条改动

**(1) R1 — 报告给出可靠度等级**
`LEVEL_TEXT` 从 `resultsCenter.js` 上移到 `reportGenerator.js` 导出（那里本来就放着
`SRC_BADGE_TEXT`，属同一类"展示用标签表"），两边 import 同一份。冒口块首行输出
`可靠度：🟡 需人工复核`，配色随等级（`.lvl-s / .lvl-w / .lvl-b`）。
**等级未知（旧结果 / 合成数据）时不出行**——与 V2.0-08 `bindHint` 同一条纪律：**不编造**。

**(2) R2 — 报告印出设计模数 Mc 及其来源**
新增 `mcSrcText(src)`，**只认 `calcManifest` 在选值处标注的 `mcSrc`**（不从任何别的字段反推——
反推正是 D2 的成因）。主表首行输出 `设计模数 Mc 14 mm（🟢 STL 自动检测（未经确认））`。
三类来源：`🟠 用户确认` / `🟢 STL 自动检测（未经确认）` / `🔵 壁厚/结构参考值`；未知来源**不出行**。

**(3) R3 — 多热结表新增「Mc 来源」列**
逐项消费 `it.mcSrc`（V2.0-08 已逐项标注），混合场景下 H1/H2 各自的来源一目了然。

**(4) R4 — 多热结尺寸改用形状库 `sd.label`**
与单热结路径**同一写法**（`it.sd?.label ? it.sd.label(it.D, it.H) : '⌀D×H'`，后者仅为兜底）。
正方柱 → `方134×H134`，球形 → `球⌀147`。**这不是显示偏好，是修正一处标注错误。**

### 为什么这些改动不会动到工程数值

- 改动全部在**视图层**（`js/views/`），不在 `calcs/`、不在 `js/engine/`；
- 新代码只**读**结果对象的字段（`r.level` / `r.Mc` / `r.mcSrc` / `it.mcSrc` / `it.sd`），**不写**任何字段；
- `mcSrcText` 是纯查表函数，无算术。
