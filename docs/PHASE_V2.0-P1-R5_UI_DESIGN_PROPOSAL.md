### 1.2 状态机：当前并存**两套**，判定源不同

**【事实】** `designCenter.js:118-124` 的 `workflowState()` 只有 5 态、判定极简：

```js
if (state.busy) return 'C';
if (state.lastRun && state.lastRun.ok === false) return 'E';
if (!state.mesh) return 'A';
if (!state.results) return 'B';
return 'D';
```

**【事实】** `designCenter.js:169-186` 的 `computeState()` 是**另一套 7 态**（busy / failed / stale / ok / idle / needparam / ready），只喂状态 chip 与底部状态栏。

| 态 | 真实判定 | 顶部主按钮 | 左栏 | 三维区 |
|---|---|---|---|---|
| A 未导入 | `!state.mesh` | 📥 选择 STL 文件 | **整列不存在**（CSS `[data-flow=A]`） | 只有导入区 |
| B 已导入未分析 | 有 mesh 无 results | ▶ 开始分析 ／ ⚙️ 确认工艺参数（按 `paramsReady()` 二分） | 概览 + 热结 | 三维 + 校验条 + 浮层控件 |
| C 分析中 | `state.busy` | ⏳ 正在分析…（disabled） | 保持 | 进度条 |
| D 分析完成 | 有 `state.results` | 📋 查看分析结果（结果视图内＝🔁 重新分析） | 保持 | 三维 + 6s 就绪高亮 |
| E 失败/条件不足 | `lastRun.ok === false` | 🔁 重新分析 ／ ⚙️ 修正工艺参数 | 保持 | + 过期横幅 |

> **【事实·设计约束】** 代码注释明确：主按钮文案/动作只能由 `workflowState() + paramsReady()` 真实判定驱动，**不得看 UI 标记**（`designCenter.js:930`）；状态 chip 与状态栏是外壳状态的**唯一显示位**（`renderStateChip`，`:188-190`）。

### 1.3 参数窗口现状（`#dc_paramDlg`）

**【事实】** `paramFields()`（`designCenter.js:562-612`）**20 个可编辑字段**，分 A/B/C 三模块；`readonlyRows()`（`:615-631`）**5 个只读项**（外形尺寸 / 体积 / 最大壁厚 / 净重 / 热结数量），排在各模块可编辑项**之后**（`:737-739` 写明是为手机竖屏让位）。

| 模块 | 字段数 | 内容 |
|---|---|---|
| A · 分析条件 | 4 | 材料大类★ / 模型单位 / 主体壁厚 / 毛坯重量★（★＝required） |
| B · 冒口设计 | 3 + 热结勾选 | 热节模数 Mc / 冒口形状 / 冒口高度 RH ＋ `hotspotPickHtml()` 勾选列表 |

**【事实·必须保留的语义】**（146 §3.4 的落地，`designCenter.js:139-152, 866-913`）：

* 窗口内输入**只进 `state.paramDraft`**（局部对象，不写项目、不参与任何计算）；`geometry.unit` 的 base 取 `state.unit` 而非项目值（`:776`）。
* **`paramIssues()` 必须双口径**：状态 chip / 主按钮 / 分析门禁看**已保存**（`false`），窗口内保存按钮看**草稿**（`true`）。混用会直接违反"UI 说已确认、计算用旧值"。
* 保存顺序：**单位最先应用**（重写全部 `geometry.*`）→ 材料大类（`USER_INPUT` + `applyFamilyDefaults`，用户显式改过的不覆盖）→ 其余 `proj.set()` → `refreshWeight()` → `markChangedStale(paths)` → 关窗 → `autoRecompute()`（600ms 防抖，**仅当已有结果时**触发）。
* 取消时有脏草稿 → `window.confirm`（**注意：无头浏览器会被它挂死**，测试须打桩）。

**【事实】当前硬门禁只有 2 条**（`:153-162`）：`material.family` 非空、`geometry.blankWeightKg > 0`。其余 18 个字段都**有可追溯默认值**，不阻塞分析。

## 4. 三种布局方案的比较及明确推荐

### 4.1 方案定义

| 方案 | 结构 |
|---|---|
| **A 保留左栏** | 现状：`应用导航(236) + 左栏(300) + 三维`，信息重组进左栏 |
| **B 删左栏 + 纯弹窗** | 顶部导航 + 一系列独立弹窗完成全部操作 |
| **C 用户提出** | 顶部流程导航 + 中央三维模型 + 按需任务面板 + 独立结果视图 |
| **D 本方案** | C 的精确化：**顶部流程条（5 步，含状态）＋ 中央三维 ＋ 右侧按需任务面板（320~360px，默认收起，内容随步骤切换）＋ 独立结果视图** |

### 4.2 八维比较

| 维度 | A 保留左栏 | B 纯弹窗 | C（原样） | **D（推荐）** |
|---|---|---|---|---|
| 新用户理解成本 | 中——左栏 12 个诊断数据格会淹没重点，且"下一步做什么"只能靠底部一行 chip | 高——弹窗是"孤岛"，没有全局进度感 | 低——流程条直接点出 5 步 | **低**——流程条＝步骤 + 状态 + 完成勾选；当前步骤决定右面板内容 |
| 参数说明/图片的展示空间 | 差——300px 窄栏放不下 330px 宽的 SVG，长说明要挤成多行 | 中——弹窗 `min(920px,100%)` 够宽，但**多个弹窗之间无法对照** | 好——面板可给到 360px，且可做宽屏双列 | **好**——右面板 360px 常态；窄屏/演示时面板可临时加宽到 460px；图 + 说明同屏 |
| 三维可视面积（1366 屏） | **798 px** | 1106 px（全宽） | 1106 px | **746 px（面板开）／1106 px（面板关）** |
| 熟练用户操作效率 | 低——所有内容常驻，找东西靠滚动 | 低——"打开→填→关闭"循环，用户明确要求避免 | 中——取决于"按需面板"怎么定义 | **高**——流程条一键跳步；面板不关不弹；结果页保留 6 项快速调整 |
| 页面切换/弹窗数量 | 0 弹窗 / 1 视图切换 | **最多**（≥5 类弹窗） | 中 | **0 弹窗 / 1 视图切换**（参数不再用模态） |
| 长表单可读性 | N/A（不是表单布局） | 差——模态内滚动，看不见背景上下文 | 中 | **好**——分步骤后单屏最长 ≈ 9 个字段（浇注模块），桌面双列 → 3 行 |
| 手机竖屏 / 小窗口 | 已改为抽屉（<960px），**额外成本已付** | 弹窗全屏，尚可 | 需另定 | **最好**——右面板在 <960px 直接变成全宽覆盖层，与现有 `rail-open` 抽屉机制同源（**已有实现可改**） |
| 实现复杂度 / 维护成本 | 低（不动） | 中（新建弹窗体系） | 中高 | **中**——复用现有 `#dc_paramDlg` 的字段表/草稿/保存语义与 `.dc-resview` 结果视图；主要是布局与分组重排，**不碰任何计算契约** |

### 4.3 推荐：**方案 D**（【建议】，并给出取舍理由）

**为什么不选 A**：A 的核心成本是**永久性**的——300px 在 1366 屏占 22% 宽度，而它的内容（§1.6 #2）大部分时候无决策价值。更要命的是应用导航已经在左边，"导航 + 信息栏"两个左列让视线每次都要横跨两栏才能回到三维。

**为什么不选 B**：用户自己已经点破了——「不要机械地把九个阶段做成九个页面。合理合并操作，避免用户不断打开、关闭弹窗。」B 正是弹窗最多的一档；而且模态弹窗**切断了"看热结 → 改 Mc → 再看"的连续性**，而这条路径是冒口设计的核心动作。

**为什么选 D 而不是 C 原样**——D 相对 C 的三处精确化，每处都有依据：

1. **面板放右侧，不放左侧**：应用导航已占左侧；右侧面板与左侧导航形成对称，视线轴是"导航 → 三维 → 属性"，也符合 CAD/CAE 工具（属性面板在右）的既有习惯。**这不是我的偏好，是 236px 已被占用后的唯一不叠加选择。**
2. **面板默认收起、按需展开**：直接回应「左侧信息栏长期占据空间」。收起时三维拿到全宽 1106px（比现状 **+39%**）；展开时才付出宽度，而展开的时刻用户正在填参数、不需要转模型。
3. **面板内容随"流程条步骤"切换，参数不再用模态浮层**：这一条同时解决三件事——「长表单读不完」（拆成 4 个步骤，单步最长 9 字段）、「反复开关弹窗」（面板不关，只换内容）、「新用户不知道下一步」（流程条就是答案）。**代价是放弃了模态的"重聚焦"效果**，需要用流程条的高亮和状态点补偿。

**【建议】同时保留的 C 的优点**：独立结果视图（R3/R4 成果，不动）、顶部可见的进度与状态。

### 4.4 四样东西分别放哪（【建议】）

| 内容 | 放哪 | 为什么 |
|---|---|---|
| **顶部流程条** | 主工具栏下方常驻一行，5 个节点：`① 导入模型 → ② 分析条件 → ③ 冒口设计 → ④ 浇注系统 → ⑤ 查看结果` | 它是"我在第几步 / 下一步做什么"的**唯一答案**，必须常驻、必须一眼可见。同时替代 v1.1.0 的「③ 参数与执行条件」大标题与 R3 已删的「设计步骤」块 |

| **分析概览** | **拆分**：①「外形尺寸 / 净重 / 毛坯重 / 最大壁厚 / 最大热结 Mc」→ 右面板第①步顶部（**与参数面板同屏**，因为填参数时要参照）；②「表面积 / 三角面 / 距离场采样 / 厚度估计 / 网格校验」→ **折叠的「模型诊断」**，默认收起 | 直接回应「分析概览价值有限」：把"填参数要参照的 5 个数"与"排障才看的诊断数"分开。诊断信息不是没用（STL 有问题时是关键线索），只是**不该常驻**。 |

## 5. 从导入 STL 到查看结果的完整用户流程

> 写法：每阶段列「看到什么 / 能做什么 / 系统自动做了什么 / 需要用户确认或输入什么 / 缺参数怎么提示 / 失败怎么引导 / 怎么返回不丢数据」。

### 步骤 ① 导入 STL（状态 A）

* **看到**：中央大导入区（📂 + 「拖拽 STL 到此处，或 选择 STL 文件」+ 小字 `支持 Binary / ASCII STL · 完全本地解析 · 数据不出本机`）。**无左栏、无右面板**，页面只有这一件事。
* **能做**：拖拽 / 点选 / 最近文件（**【建议】新增**：记住上一次文件名，一键重导）。顶部流程条 ① 高亮，②~⑤ 灰。
* **系统自动**：解析 → 网格校验 → 距离场 → 热结分析。进度条按现有 9 段真实分片文案推进（`PROGRESS_STAGES`）。
* **需要用户**：无。
* **失败引导**：见步骤 ⑥。
* **返回**：无上一步。

### 步骤 ② 模型信息（状态 B，流程条 ① 完成 → ② 待确认）

* **看到**：中央是三维模型（导入结束自动切回，**不自动进入下一步**）；右面板自动展开到「模型信息」：顶部 5 个关键数（外形尺寸/净重/毛坯重/最大壁厚/最大热结 Mc）→ 热结列表（每项 `H1 · Mc x mm · 区域 y cm³` + 「参与冒口」勾选）→ 折叠的「模型诊断」。
* **能做**：转模型（旋转/缩放/平移）；点热结 = 只选中/高亮，**相机不动**（146 §6 成果，保留）；切标准视图；勾选热结。
* **系统自动**：把 STL 结果写入 `CastingProject` 并标来源 `STL_GEOMETRY_ANALYSIS`。
* **需要用户确认**：**只在这一步确认"这个模型/这些热结对不对"**——不要求用户重复确认已经可靠确定的量。
* **缺参数提示**：此时若 `material.family` 为空，流程条 ② 显示 `⚙`，底部 chip 显示 `⚠️ 缺少必要条件：材料大类未指定`。
* **返回**：可随时点 ① 重新导入（**【建议】有结果时二次确认**）。

### 步骤 ③ 分析条件（状态 B）

* **看到**：右面板切到「分析条件」；中央三维**仍在**（用户能一边看模型一边填）。
* **能做**：选材料大类（**必填，系统绝不猜**）、模型单位、主体壁厚、毛坯重量；点字段旁的 `ⓘ` 展开说明。
* **系统自动**：材料大类选定后带出密度、收缩率、出品率区间、加工余量等级 —— **并用 v1.1.0 的联动提示条显式告诉用户"这些值会立即随动"**（§2.2⑤，现缺失）。用户显式改过的派生值不再被覆盖。
* **需要用户输入**：材料大类（必填）+ 单位（若 STL 非 mm 建模）。
* **缺参数提示**：底部 chip 逐条列出缺失项与**为什么要它**（`材料大类未指定（STL 无法识别材料）`）；点 chip 直接跳到该字段并聚焦。
* **返回**：流程条点 ② 回模型信息；**切步骤不丢任何已输入内容**（草稿随面板存活，或直接落盘——见 §6.4）。

### 步骤 ④ 冒口设计（状态 B）

* **看到**：右面板切到「冒口设计」：热节模数 Mc（带来源徽章 + 说明 + **可展开的"Mc 怎么估"**）→ 热结勾选 → 冒口形状（含模数式）→ 冒口高度 RH。
* **能做**：改 Mc、勾选多热结、换形状、改 RH；点 `ⓘ` 看四种 Mc 估法（§2.2⑫）。
* **系统自动**：Mc 默认取 STL 最大热结；RH 在冒口算完后回写。
* **需要用户确认**：**Mc 是这一步唯一值得"确认"的量**——尤其当系统用的是"壁厚÷2 兜底"而不是真热结时，必须显式提示（v1.1.0 原文见 §2.2⑩2）。
* **缺参数提示**：无硬门禁（有兜底）；但兜底时**必须显示警示**而非静默。
* **返回**：点 ③ 回分析条件；模型/热结/参数全在。

### 步骤 ⑤ 浇注系统（状态 B）

* **看到**：右面板切到「浇注系统」：浇注位置（**下方紧贴示意图**）→ Ho / ph（**图的尺寸线正好解释这两个量**）→ 浇注系统比例（含 7 条适用条件 + `ⓘ` 弹窗）→ 内浇道 / 横浇道 / 排气 → 折叠的「生产条件」（型腔数 / 出品率 / 造型线 / 铸造方法）。
* **能做**：改全部浇注参数；点图放大。
* **系统自动**：比例空 = 按材料与重量自动推荐（选项文案直接写出推荐结果）。
* **需要用户输入**：一般不需要（全部有默认）；**但要能一眼看出"这是默认值、可以改"**。
* **缺参数提示**：无硬门禁。
* **返回**：点 ④ 回冒口设计。

### 步骤 ⑥ 检查必填项与参数状态（贯穿 ③~⑤）

* **看到**：流程条每个节点上的状态点 + 底部 chip + 面板底部的保存条。
* **机制**（**【建议】沿用 146 §3.4 的契约，不新造**）：
  * 面板内改的是**草稿**（不写项目、不参与计算）；
  * 面板底部固定条：`[取消] [保存并重新分析]`，左侧灰字实时显示还缺什么；
  * 有脏草稿时关闭/切步骤 → 明确询问（保留现有 `confirm` 语义，但**改成面板内联提示条**，因为无头环境/触屏下原生 `confirm` 体验差 —— **【需你决定·2】**）；
  * 保存后：写项目 → 按 `PARAM_OWNERS` 精确标记受影响模块过期（无登记归属时保守全标）→ 600ms 防抖重算。

### 步骤 ⑦ 开始分析（状态 C → D/E）

* **看到**：主按钮 `▶ 开始工艺分析`；点击后进度条推进，按钮变 `⏳ 正在分析…`（禁用）。
* **系统自动**：按固定任务集 `shrinkage → machining → riser → gating → yield` 执行。
* **需要用户**：无。
* **【建议】跑完不自动切结果视图**（146 的既定决定，保留），改为：主按钮 6s 就绪高亮 + toast + 流程条 ⑤ 变为可点。

### 步骤 ⑧ 查看结果及详细信息（状态 D）

* **看到**：独立结果视图（三维仍在 DOM 中、不销毁）。三类别页签 + 每页三层：核心结论卡 → 关键数值及单位 → 🔎 详细信息。
* **能做**：切类别、展开详细信息、**快速调整 6 个高频参数**（见 §7.4）、生成报告、打开独立计算器、返回工作台。
* **【建议】新增**：页内「本页结论一句话」摘要（**只保留一句，不重复下方卡片**）＋ 未验证限制的醒目条（§7.5）。

### 步骤 ⑨ 返回工作台、修改参数、重新分析

* **看到**：`⤡ 返回三维工作台` → 只切视图，**不清空任何东西**（146 §P0-2 成果，保留）。
* **修改**：走右面板（完整说明）或结果页（快速微调）。
* **旧结果处理**（**【建议】保留现有机制，仅补可见性**）：不隐藏、不清空旧结果；面板保存后底部出现过期横幅 `⚠️ 参数已修改，当前结果已过期（待重新分析）` + `🔄 重新分析` 按钮；结果页对应卡片标灰角标。

### 步骤 ⑩ 分析失败 / 条件不足（状态 E）

**【建议】失败分三类，给三条不同的出路**（现状是同一句话）：

| 类别 | 判定 | 面板/界面给什么 |
|---|---|---|
| **参数缺失** | `paramIssues()` 非空 | 逐条列出缺什么 + **为什么需要它**（对应哪个计算器），一键跳到该字段聚焦 |
| **几何不可信** | `geometry.geomStatus === 'INVALID'` | 明确「网格本身不可信 ⇒ 净重/体积/热结位置全部不可信；人工填 Mc 也替代不了这些输入」＋ 回到 ① 换文件；**并指出具体是哪条网格问题**（复用 `MESH_ISSUE_TEXT` 8 条原文） |
| **算法未能给出可靠结果** | 热结 `LOW_CONFIDENCE` / 无热结 / 采样欠解析 | 说明**是哪一种**（`hsReasonText` 7 条已有），并给"该怎么办"：勾选其他热结 / 手填 Mc / 复核壁厚 |

## 附录 A · 三个"必须记住"的技术约束（重构时最易踩）

1. **视口浮层控件不得放进 `#dc_view3dBox`** —— 它是 OrbitControls 的 domElement，`setPointerCapture` 会把 `click` 重定向到容器。146 轮的标准视图全失效就是这个原因。
2. **`paramIssues()` 的双口径不得合并** —— 状态 chip 看已保存、保存按钮看草稿。
3. **`.dc-ws [hidden] { display:none !important }`** —— `[hidden]` 是属性选择器，会被 `.btn`/`.chip` 这类类选择器同权重顶掉；新组件必须挂在 `.dc-ws` 下或自带守卫。

## 附录 B · 本方案的"不做什么"

* **不新画任何图**（唯一需要的图已存在，只是被删了调用点）。
* **不引入任何外部依赖 / CDN**（Three.js 保持本地）。
* **不改任何公式、默认值语义、单位、字段契约、工程判级**。
* **不启动 P2，不发布 V2.0**。
* **不为界面简化删除任何参数、工程说明或已有示意图**。
* **不把 UI 设计问题当算法问题修**：本方案没有一条改动落在 `calcs/**` 或 `js/engine/**`。
