## 3. 出品率 P0：一模多件的真实口径

### 3.1 代码追踪（不是按字段名猜）

| 环节 | 实际代码 | 结论 |
|---|---|---|
| 型腔数输入 | `production.cavities`；`calcManifest` gating 入参 `cav: proj.getV('production.cavities') || 1` | 真实参与计算 |
| 产品重量 | `gating.calculate` 传 `pw: geometry.blankWeightKg`（**单件毛坯重**） | 单件口径 |
| 整模铸件质量 | `gating.js` `castingMass = pw * cav` | 正确（仅 P47 浇注时间用） |
| 浇注重量 G | `gating.js` `G = castingMass / yv` | 由**预估出品率**反推，不是实称 |
| 实际出品率 | `gating.js` `ya = pw*cav/G*100` ⇒ **恒等于 yv** | 数学恒等式，不是实重统计 |
| yield 铸件重量 | `calcManifest.js` `castWt: wt`（`wt = blankWeightKg`，单件） | **单件口径** |
| yield 浇注系统重 | `calcManifest.js` `runnerWt = g.G - wt` | **只减单件；未乘 cav；未扣冒口** |
| yield 冒口重量 | `calcManifest.js` `riserWt = Σ Vr×rho/1e6`（单套/单件冒口） | **未乘 cav** |
| 最终结果页旧值 | `resultsCenter.js` 曾读 `gating.ya` 标“实际出品率”；yield 页曾用 `y.castWt / y.pourWt` | 前者是恒等值；后者 2 腔/4 腔分别显示 32.5%/16.25% |
| 独立浇注计算器 | 与设计中心共用 `calcs/gating.js`，同样输出 `ya` | 逻辑无差异；差异只在显示口径 |

### 3.2 实测案例（真实生产函数，球铁 / 单件毛坯 20 kg / 净重 18 kg / 预估出品率 65%）

| 项目 | 1 腔 | 2 腔 | 4 腔 |
|---|---:|---:|---:|
| 单件毛坯重 kg | 20.000 | 20.000 | 20.000 |
| 整模铸件毛坯重 kg | 20.000 | 40.000 | 80.000 |
| 单套冒口重 kg | 2.081 | 2.081 | 2.081 |
| 整模冒口重（× 腔数，假设每腔一套） | 2.081 | 4.163 | 8.325 |
| 浇注重量 G kg | 30.769 | 61.538 | 123.077 |
| 差值 = G − 整模铸件重 kg | 10.769 | 21.538 | 43.077 |
| 浇道重 = 差值 − 整模冒口 kg（同一假设） | 8.688 | 17.376 | 34.752 |
| 设计预估出品率 % | 65.0 | 65.0 | 65.0 |
| 铸件占 G（= 设计预估，恒等） % | 65.0 | 65.0 | 65.0 |
| 铸件 + 冒口占 G %（未含浇道） | 71.76 | 71.76 | 71.76 |
| **现有核心 `yield.runnerWt` kg** | 10.769 | **41.538** | **103.077** |
| **旧 yield 页“出品率” = 单件 ÷ G %** | 65.0 | **32.5** | **16.25** |
| 最终实重出品率 | — 不能独立给出 | — | — |

> 计算脚本与断言见 `tests/phases3_yield_rh_test.mjs`（S3-Y1/Y2/Y3）。
> “最终实重出品率”不能由现有核心独立给出：G 本身由预估出品率反推；核心没有独立的
> 浇道实重。任何“铸件 ÷ G”的百分比都只是设计口径。

### 3.3 已确认缺陷（按发生位置）

1. `calcs/calcManifest.js`：`yield.castWt` 是单件，不是整模。
2. `calcs/calcManifest.js`：`yield.runnerWt = G − 单件毛坯重`——未乘型腔数，且这份差额里**包含冒口**（没有扣冒口）。
3. `calcs/calcManifest.js`：`yield.riserWt` 是单套冒口，未乘型腔数。
4. `calcs/gating.js`：`ya` 是恒等式 `pw*cav / (pw*cav/yv) ≡ yv`；旧 UI 把它叫“实际出品率”。
5. `js/views/resultsCenter.js`（旧）：浇注详细行直接显示 `gating.ya`；旧 yield 页用 `castWt/pourWt`。
6. `js/views/reportGenerator.js`（旧）：导出报告同样用 `castWt / pourWt`。
7. **重复计算**：旧报告同时显示 `runnerWt` 与 `riserWt`，而 `runnerWt` 的差额里已经包含冒口——
   两者相加会重复计算冒口重量；本阶段报告已改为整模账目，不再给出这两个互相重叠的旧字段。

### 3.4 结论

**C —— 存在确定的计算缺陷，但缺陷位于冻结计算核心，本阶段未擅自修改；能安全完成的显示/报告部分已修复。**

- 未改 `calcs/calcManifest.js` 的任何公式/默认值/输入输出语义。
- 未改 `calcs/gating.js` 的 `ya` 公式（只改 UI 标签）。
- 未用第二套公式“修好”最终出品率；结果页明确写“暂不能给出（核心没有独立的浇道实重）”。

### 3.5 最小核心修复方案（建议，待单独决策）

1. `yield.calculate` 增加整模字段：`castWtTotal = wt * cav`；`riserWtTotal = riserWt * cav`
   （假设每腔一套；若将来引入“一套冒口服务多腔”，需另给输入，不得默认）。
2. `runnerWt` 改为 `G - castWtTotal - riserWtTotal`，并在不能可靠得到时返回 `null`，不要用差额冒充。
3. 把 `gating.ya` 改名为 `designYield`（或保留字段但停止在 UI 标“实际”）。
4. “最终实重出品率”只在有**实测浇注重量**或**独立浇道实重**时计算；否则返回 `null` + 原因码。
5. 这些都在 `calcManifest.js` 冻结区，需用户/工程负责人单独授权后修改并重新基线化。

### 3.6 本阶段已安全落地的显示修正

- 结果页浇注明细：`设计预估出品率（用于反算 G）` + `铸件重 ÷ G（恒等反算，不是实重统计）`。
- 结果页新增“生产条件与整模重量口径”卡 + “整模重量口径与出品率核对”折叠表：
  单件/整模铸件重、冒口单套/整模、差值、浇道重（带“每腔一套”假设）、铸件/铸件+冒口占 G、
  最终实重出品率“暂不能给出”。
- 导出报告同样改为整模账目；新增 Node 断言防止 16.25% 回归。
- 独立浇注计算器标签改为“设计出品率（按输入预估反推）”，并注明恒等关系。
- `js/views/yieldLedger.js` 是**纯显示派生**，不参与任何设计计算；注释中明确假设与缺口。

## 4. RH P0：真实定义、最终处理与数据流

### 4.1 两个 RH 不是同一个物理量

| 来源 | 定义 | 证据 |
|---|---|---|
| 冒口计算 | `H` = 冒口自身的总高度；`H = round(D × hd)`（球顶柱另保证 H≥R，球形 H≡D） | `calcs/riser.js` 的 `hOf()` / `sizeAt()` |
| 浇注系统 | `rh` = **冒口高出铸件顶面的距离**（铸件顶 → 冒口顶） | `js/views/gatingDiagram.js` 顶部注释（Excel K15）；`gatingView.js` 输入标签“冒口高于铸件顶面的距离” |
| 设计中心旧行为 | `runAnalysis` 直接把 `r.H` 写进 `process.riserHeight`，gating 读它 | `designCenter.js` 回写；`calcManifest.js` `rh: proj.getV('process.riserHeight')` |

⇒ 旧行为只在“顶冒口直接坐在铸件顶面”时成立；侧冒口/带冒口座时，`H` 不等于浇注需要的 RH。
这不是变量名问题，是**物理定义差异**。

### 4.2 最终处理（已实现）

- RH 仍是**唯一的** `process.riserHeight`；不建第二份存储。
- 在 ③ 浇注系统设计（生产条件之后）提供可编辑输入：
  - 标签：`RH（冒口顶面高出铸件顶面）`；
  - 来源徽标：`冒口计算自动值` / `用户指定` / `尚未回写`；
  - “自动参考”行：优先 `orig`，否则当前 `CALC_RESULT`，否则最近一次 riser 的 H；
  - 明确说明：`C = ph + rh`、`Hp`，以及“H 只有顶冒口坐在铸件顶面时才等于 RH”；
  - 手动值在面板草稿中编辑，保存后 `USER_OVERRIDE`；
  - 有 `orig` 时提供 `↺ 恢复自动值`（`restoreAutoValue` 一并还原 v/src/conf）。
- 优先级：**用户指定 > 冒口自动回写**。
  `runAnalysis` 回写判断同时尊重 `USER_OVERRIDE` 与 `USER_INPUT`（旧实现只判断 USER_OVERRIDE）。
- 换 STL：
  - 自动值（CALC_RESULT）清除，避免旧模型高度残留；
  - `USER_OVERRIDE` / `USER_INPUT` 保留，并在分析完成 toast 明确提示：
    “⚠️ 手动指定的 RH 已保留；更换模型后请到「浇注系统设计」复核该值是否仍适用。”；
  - 保留值的 `orig` 同时失效，避免“恢复”成旧模型的自动 H。
- `CastingProject.set` 的自动值基准判断补上 `CALC_RESULT`：用户第一次改 RH 时能固化 `orig`，
  `↺` 才会出现（旧实现下 `restoreAutoValue` 对 CALC_RESULT 永远不可用）。

### 4.3 未解决/边界

- **自动 RH 仍是“顶冒口假设”**：核心没有冒口位置/高度基准输入，无法自动判断侧冒口。
  本阶段通过文案 + 可编辑值把假设显式化；没有新增自动几何推断。
- 如果将来要“按位置自动算 RH”，需要冒口位置/高度基准进入 `calcManifest`/riser 结果；
  会触及冻结语义，需单独阶段。
- 手动 RH 换模型后保留是产品选择（用户要求“不得静默覆盖”）；同时用 toast + 常驻说明提示复核。

## 5. H/D P1：支持范围与实现状态

### 5.1 现有模型支持

- `calcs/riser.js` 的 `runRiser` 接受任意正 `hd_ratio`：
  - `cyl` / `square` / `sphere_head`：`H = round(D × hd)`，进入模数/体积。
  - `sphere_head`：额外保证 `H ≥ R`。
  - `sphere`：`H ≡ D`，`hd_ratio` **不改变几何**（球只有一个尺寸自由度）。
- 独立冒口计算器 `riserView.js` 提供 `0.8 / 1.0 / 1.2 / 1.5` 四档；没有 2.0 选项。

### 5.2 设计中心为什么没做

- `calcs/calcManifest.js` 的 riser 调用**硬编码** `hd_ratio: 1.0`（冻结文件）。
- 要让设计中心支持 H/D，必须改这一行并增加项目参数；这属于冻结计算语义变更。
- 因此本阶段：
  - 没有新增假的 H/D 输入；
  - 在 ③ 冒口设计和结果页显示 `H/D = 1.00（只读 · 设计中心固定）`；
  - 明确说明独立计算器支持、设计中心这条链固定 1.0。

### 5.3 最小实现方案（待授权）

1. 新增 `process.hdRatio`（默认 1.0，来源/恢复语义与其它设计参数一致）。
2. `calcManifest` riser 调用改为读取该参数（缺省 1.0），仍走 `runRiser`。
3. UI 按形状给选项：柱/方/球顶柱可用；球形不提供（或只读说明 hd 无效）。
4. 结果页显示实际 H/D 与“球形 H≡D”的限制。
5. 需要重新基线化 49 个历史 riser 用例（hd=1 以外的数值会改变 D/H/Vr）。

## 8. 参数唯一性与结果有效性

- **唯一权威状态**：仍是 `CastingProject`；草稿只在面板会话内存在，保存后落盘。
- RH / Mc / 形状 / 浇注条件都只有一份存储；结果页只读展示 + 指回参数面板。
- 参数修改后：
  - 面板保存：`markChangedStale()` → 状态条/外壳立即显示过期 → 分析成功清除；
  - 结果页内联：`applyParam` → `markAllStale()` → 状态条立即变为 stale → 防抖重算成功恢复。
- 分析失败：不替换旧结果；回滚本次写回；状态条 failed；旧结果明确标为过期（S2.2 既有，S3 状态条复用）。
- 保存失败：注入测试（内存冻结一个参数条目）验证——显式 toast、草稿保留、不触发分析、项目值未变；
  之后 reload 清掉注入，不污染项目。
- 首次分析 / 必填项缺失 / 参数未保存 / 分析中重复点击：S2.2 专项继续通过。
- 多热结：`p78` 继续验证 H1/H2 草稿勾选、逐项 Mc 绑定、↺ 改回检出值。
- STL 更换：清理几何/热结/旧结果；用户 RH 保留并提示；其余用户前置参数按既有规则保留。
