## 0. 一句话结论

**【实验事实】** 在 3 个几何 × 4 档分辨率共 12 个配置中，**`Mc ≡ (1/3) × d(峰点)` 逐位成立**，
且 M 场的**最大点 12/12 全部被 ceiling 截断**（coarse 场 capped 比例 11/12 恰为 100.00%）。
因此 `finer → larger` 不是"热模数场在收敛"，而是 **`(1/3)×(最厚处内切半径)` 这个几何量
在晶格上的单侧逼近**。**H1（截断比例下降导致 Mc 上升）前提被证伪**，但实验揭示了一个比 H1 更强的机制。

## 1. 静态审计（Step 1，109.txt §二十二）

### 1.1 ceiling 如何参与 M 值计算【代码机制】

```
js/engine/v3/modulusField.js:64   m = w.v / w.a            // 未封顶 V/A（windowVoxels）
js/engine/v3/modulusField.js:71   const d = sample.dists ? sample.dists[i] : null;
js/engine/v3/modulusField.js:72   if (d !== null && d > 0) m = Math.min(m, o.modulusCeilRatio * d);
js/engine/v3/configV3.js:45       modulusCeilRatio: 1 / 3
```

- `d` = `sample.dists[i]` = 该采样点到表面的 **BVH 距离**（不是 `tArr` 的局部完整厚度 `t`）
- 封顶值 `ceiling = (1/3) × d`
- **消费端**：`M[t]` → `findPeaks(refField.M, …)` → `p.M` → `hotspots[].peakModulus` = **Mc**

### 1.2 `sample.dists` 是 refine 的、不是 coarse 的【代码机制】

```
hotspotV3.js:118   const refField = buildModulusField(coarse.vox, ref, o, 1.0);
                                                        ↑ vox      ↑ sample
```
`sample` 位置传的是 `ref`（`refineSample` 的返回值），故 `d = ref.dists[i]`。

### 1.3 记录：`sampling.js:338` 注释与实际代码不符（**只记录，不修**，109.txt §二）

```
sampling.js:338  // 局部完整厚度（PHASE 24：M 场物理上限用 t 而非 d——板/肋状厚结构不被 (1/3)×d 错误压制）
sampling.js:341  return { …, dists, char, thin, tArr: thin.tArr, … };
```
注释称上限用 `t`，但 `modulusField.js:71` 实际读 `sample.dists`（= `d`）。
`modulusField.js:66-70` 的注释则明确写着 PHASE 24 的 `t` 方案**被否决**（"d 上限是承重墙"）。
**⇒ `sampling.js:338` 的注释是 PHASE 24 的残留**，与生效行为不一致。**属冻结区文案不一致，未修。**

## 2. L4 构造（Step 2，109.txt §四）

### 2.1 推导依据【代码机制】

```
sampling.js:116-118   experimentalGs > 0 → vs = mdim/gs, gs = experimentalGs      （coarse 场分辨率）
sampling.js:321       refineVs = min(coarseVs, region_mdim / refineMinRes=16)
sampling.js:322       refGs    = max(round(region_mdim / refineVs), 16)
sampling.js:326       stride   = max(1, ceil(cbrt(refGs³ / refineMaxPoints)))
spacing = refineVs × stride
```
**`experimentalGs` 通过 `coarseVs` 耦合到 refine 的 `refineVs`** —— 场变细会连带把采样晶格变细，
若不加大 `refineMaxPoints`，`stride` 会跳档使 `spacing` 反而变粗（05C 的 sampling confounding）。

### 2.2 取值（**不是机械取值**）

用 L3 实测反推 `region_mdim = refGs_L3 × refineVs_L3`，再预测 L4 的 `refGs₄` 与 `stride` 跳变点 `∛R`：

| geometry | L3 region_mdim | 预测 refGs₄ | 要"stride 不跳档"需 ∛R |
|---|---|---|---|
| thickEnd | ≈ 208mm | ≈ 87 | ∈ [43.5, 87) 保持 stride 2 |
| HR4012 | ≈ 225mm | ≈ 72 | ≥ 72（否则 stride 1→2，spacing 6.25 > L3 的 4.6875 → 违反 §四C） |
| pvpPair | ≈ 96mm | ≈ 98 | ∈ [49, 98) 保持 stride 2 |

取 **∛R = 84.34 ⟹ refineMaxPoints = 600 000**，同时满足三者。
（R 越大越安全且**当 stride 已为 1 时增加 R 零成本**——`for (i = 0; i < gs; i += stride)` 已遍历全部格点。）

> **不得以"让 Mc 更稳定"为选择依据**（§四）：上述推导**只用 L3 的几何/代码量**，与 Mc 无关。

**L4 = `experimentalGs: 192` · `refineMaxPoints: 600000`**（§四 A/B/C 实测复核见 §4.2）。

**【代码机制】三层守卫叠加出的缺口：**

```
sampling.js:337    char = dists.map(d => (d !== null && d > 0.001 ? d * 2 : null));   // d=0 → char=null
modulusField.js:58 let r = (c !== null && c > 0) ? k * c : k * o.charFloor;           // → R = charFloor = 1.0mm
modulusField.js:71 const d = sample.dists ? sample.dists[i] : null;
modulusField.js:72 if (d !== null && d > 0) m = Math.min(m, o.modulusCeilRatio * d);  // ★ d=0 → 不封顶
```
⇒ `d = 0` 的采样点 **`M = 未封顶 V/A`**，且窗口半径退化为 `charFloor = 1.0mm`。

**【实验事实】洞的分布（3 几何 × 4 档，逐区域扫描全部 refine 采样点）：**

| geometry | L1 | L2 | L3 | L4 | 洞内最大 M vs 报告 Mc |
|---|---|---|---|---|---|
| thickEnd | **49/6427 (0.76%)** | **105/13929 (0.75%)** | 0 | 0 | L1: **14.3750 vs 9.2188 → 1.559×**；L2: 9.5833 vs 9.6181 → 0.996× |
| HR4012 | 0 | 0 | 0 | 0 | — |
| pvpPair | 0 | 0 | 0 | 0 | — |

**洞点样例（thickEnd L1）**：`@[60.000, −12.031, −12.031]`，`M = raw = 14.3750`，`d = 0`，
`char = null`，`R = 1.0000`（= charFloor），正好落在 `bounds.max[0] = 60.00` 上。
（该 region 的 `vs = 7.1875`，`x` 向最后一个格点算出恰为 60.000000 —— **晶格相位巧合**。）

**【实验事实】该点为什么没被报成热点 —— 不是 ceiling 挡住的：**

| 环节 | 结果 |
|---|---|
| `findPeaks` 候选资格：`gridNeighbors6` 邻居数 | **5 个**（不是 0）→ **通过** |
| `isMax`（无邻居严格更大） | **true**（邻居 M = 2.396 / 14.375 / 8.625 / 14.375 / 8.625）→ **通过** |
| 环带显著性：`ring = {q : 1R ≤ dist(q,peak) ≤ 2R}` | **R = 1.0mm → 环带 = [1.0, 2.0]mm** |
| `peakRegion.js:66` `if (ring.length < 3) continue;` | **环带内 0 个采样点**（`vs = 7.1875mm` ≫ 2.0mm）→ **在此被丢弃** |

**⇒ 【工程解释】挡住这条 14.375 的路径是 `ring.length < 3`，而它生效的前提是
`vs > 环带外径 2mm` —— 是一条"分辨率恰好够粗"才成立的**偶然**防线，不是 ceiling。**

**【推测】** 若某几何同时出现 ①`d = 0` 的洞点、②`vs < 2mm`，该点的环带将含采样点、
prominence 因周围表面层 M 很低而很高 → **可能成为峰并超过 ceiling 限定的 Mc**。
**本数据集未观察到该组合**（thickEnd 的洞只在 vs = 7.19mm 的 L1/L2 出现），故仅为推测。

**【记录，不修】**（109.txt §二"如果发现新的生产代码 Bug：只记录，不修"）
`modulusField.js:72` 的守卫是 `d > 0`；`d = 0`（采样点恰落在模型表面）既不封顶、

## 6. H1 判定（109.txt §十 / §十一）

> **H1**：「field 越细 → coarse voxel 离散误差越小 → `modulusCeilRatio` 对候选点的**截断比例下降** → Mc 系统性上升。」

| H1 预言 | 实测 | 结论 |
|---|---|---|
| 截断比例 **下降** | **上升至 100%**（thickEnd 95.58→97.24→100→100；HR4012 99.39→99.99→100→100；pvpPair 100→100→100→100） | **前提被证伪** |
| Mc 随之上升 | 部分上升（thickEnd ✔ / HR4012 ✘ / pvpPair ✔） | 相关性不成立 |
| 三变量一致趋势 | raw/cap 在 1.054–2.045 间**无单调趋势** | 不成立 |

### ⇒ **H1 = NOT SUPPORTED**（其因果链的前提被实测证伪）

**【实验事实】截断比例不降反升；且 Mc 与截断比例无关——Mc 与 `(1/3)d(峰点)` 逐位相等。**

### 6.1 但实验给出了一个**比 H1 更强**的机制

**【代码机制 + 实验事实】** ceiling 不是"偶尔截断离群点"，而是 **M 的定义本身**：
因为 `M ≡ min(V/A, (1/3)d)` 且实测 **12/12 配置的场最大值点、11/12 配置的 coarse 场全部点**
都满足 `V/A > (1/3)d`，所以 **`M ≡ (1/3)d`，V/A 完全不进入 Mc**。
（**唯一例外通道 = `d = 0` 的采样点不封顶**，见 §5.5；该通道未改变任何一档的报告 Mc。）

**⇒ 严格按 109.txt §十 的措辞：实验不支持"ceiling truncation 是系统性 finer→larger 的重要候选机制"
这句话的**因果方向**；正确的表述是：**

> **ceiling 不是 finer→larger 的"候选原因"，而是 Mc 的全部定义。Mc 的"漂移"就是
> `(1/3)×d(晶格 argmax)` 的变化。**

### 9.3 ★ 必须同时记录的一条硬约束（109.txt §十八）

> **本阶段的"工程稳定性"来自 `(1/3)×d` 的几何收敛，不是热模数算法的收敛。**

【实验事实】`Mc ≡ (1/3) × d(峰点)`，**V/A 不参与 Mc**。
【工程解释】因此：
- 就 **"Mc 数值稳定到足以支撑工程设计"** 而言 —— **是**（ΔD ≤ 1mm）。
- 就 **"Mc 是正确的热模数"** 而言 —— **本阶段没有测过，也无法测**：因为当前 M 场里根本没有 V/A。

**这直接影响 V2.0「纯模数法」的语义**：`Mr ≥ F_M × Mc` 中的 `Mc` 实际是
**(1/3) × 最厚处内切半径**，因此 `F_M` 是"相对 (1/3)d 的安全系数"，
**不是**"相对 Chvorinov 模数的安全系数"。

**⇒ 建议：V3 可以作为"工程冻结候选"，但 `modulusCeilRatio` 的语义归属
（物理上界 vs 经验压缩系数）必须在 V2.0-06 之前**独立裁决**。
本阶段**不修改**它（§十八 纪律）。**
