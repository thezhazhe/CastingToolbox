## 2. Campbell 浇注方法计算链（源自用户资料；已逐条回全书译本核实）

> 资料内方法为**完整可执行链**（13 章给了 30kg 钢完整算例）。证据标注：译本可查=✓（引文定位行号）；导读与译本有出入处见 ★；工具无法自我验证处=UNCERTAIN。

**总览：先算流量 → 再定每个零件面积 → "自然加压(1:1:n) + 独立减速机制"双腿走路；一套方法适用所有金属（伽利略同时间律，13.7）。**

```
输入：铸件+浇冒总重 W（估算即可，迭代差几毫米）
  │ ① 浇注时间 t：可选范围内（例 5~25s）强烈建议选最长（13.5）
  │    硬约束：造型线节拍 / 液面上升速率下限（铝 <60mm/s 出表面条纹；钢车间常见 20mm/s）
  │            / 最薄（最小模数）截面开始凝固前必须充满（图13.4）
  ▼
平均充型速率 = W/t  →  设计速率 ≈ 1.5(几何) × 1.3(摩擦) ≈ 2×平均（13.7）★符号污染：译本"1:5°1:3=2:0"=1.5×1.3≈2.0 ✓
  ▼ Q = ṁ/ρ（液态密度；钢例 6kg/s ÷ 7×10³ → 0.86×10⁻³ m³/s）✓
浇口杯：1 秒杯 = Q×1s 体积（高×2"超高"）；偏置阶梯式；塞子（13.8）✓（译本 Vb=Q/tr 除号讹误，tr=1 同值）
  ▼ v = √(2gh)（h 从浇口杯液面起算；只此一速 + Q=vA，其余"损失系数"一律不叠算——11 章声明：不采用水力学摩擦系数累加法）✓✓
直浇道：逐点 v→A → 双曲线锥形（嫌麻烦：直锥 + 入口放大 20%）/ 推荐缝隙式（例入口 10×60→出口 6.5×50）；倒锥最小化+底部预期湍流 ✓
  ▼ 1:1 横浇道：面积 = 直浇道出口（1:1，避免损失估算"反正不精确 20%"）；"满足流量下尽可能小"；下箱；弯角圆角 1~2 倍厚 ✓
  ▼ 减速（自然加压不减速，必须独立机制，优先级）：
     1) 泡沫过滤器（首选；降速至 1/4~1/5；其后通道放大 ≤4 倍、工作例取 3 倍；过滤器面积 ≥ 横浇道 2~4 倍(厚壁 2/薄壁 4)；前置液压锁+捕泡）✓
     2) 涌流/旁通冒口（切向圆柱；铸件埋 20~30mm 后喷射被抑制；尺寸按经验+模拟）✓
     3) 垂直扇形内浇口（唯一可靠减速型浇口，威布尔模数 +4 倍；扩张型速度可放宽至 1.0）✓
     4)（未来）涡流吸能
  ▼ 内浇口（速度判据定面积）：入型速度 0.5 m/s 安全线（作者自用 ≤1.0、绝不超过 1.2=70mm 落差；100mm(1.4) 需过滤器；>200mm(2 m/s) 必卷吸）
     快速规则：轻合金 ~1000 mm²/(kg/s)、重合金 ~500 mm²/(kg/s)（12.4.3，A=Q/v 取整）✓★
     缝隙式厚 < 壁厚一半（T 形热节消除、兼散热片）；垂直内浇口 ≥50~100mm 高；长度 ≤ 2×静滴高度（铝 26/铁钢 16）★
     横向速度复核（式12.1 Lᵢ=2h）→ 不够就加内浇口数
  ▼
输出：浇口杯/直浇道/横浇道/内浇口各段几何 + 减速件 + 浇注比（1:1:n，n=4~10，**是结果不是输入**；带过滤器 1:1:4；带旁通可 1:1:1）
```

**计算链完整性判定：完整**（输入→时间→速率→直浇道逐点→1:1 横浇道→减速件→内浇口速度定面积→输出几何；有完整算例）。逐级证据三态见下表。

| 环节 | 判定 | 说明 |
|---|---|---|
| v=√(2gh)、Q=vA、1 秒杯、1:1:n 定义、0.5/1.0/1.2 速度判据、1000/500 快速规则、减速件尺寸规则 | **ENGINEERING REFERENCE**（Campbell 工程方法原文可核 ✓） | 原文逐条可查（translated.md 行锚见附录 A） |
| 临界落差数（铝 12.5/13、铁 8/10.4/10 三套） | **UNCERTAIN（原文内部不一致）** | 译本 3 处不同数值；实现须显式披露"按表 2.2 采用或按章节口径可选"，不得伪装唯一 |
| 浇注时间"选最长"无量化公式、n 的精确取值规则（4~10 由减速需求定）、过滤器后放大 3.85 vs 3、涡流未完全理解 | **UNCERTAIN / ENGINEERING REFERENCE 边界** | 书自认"规则尚不为人知/以经验+模拟验证"（13.4 尾、13.10）→ 实现为工程参考参数而非查表 |

| 铅/水静滴高度、灰铁液态硅酸盐膜历史豁免等背景 | ENGINEERING REFERENCE | — |

**方法 vs 现有 Gating 定位**：Campbell 方法**不是另一套公式，是另一种设计哲学**——明言拒绝"局部节流口 + 损失系数累加"（11 章/13.4 两处原文），而 CastingToolbox 现行方法恰是"奥赞阻流口（choke）+ fv 流速系数 + Hp 损失化公式"的企业水力学体系 → **两者在根子上不可互相换算**（§5 风险据此判定）。同时存在可对齐点：内浇口速度目标（工具 V_TARGET 球铁/铝 0.45 ≤ Campbell 0.5~1.0、灰铁 1.0 = Campbell 自用上限）方向一致、工具更保守。

## 4. 结论：Campbell 是否值得成为独立计算方法

**GO（有条件）——作为"第二套平行、独立、可解释的浇注系统设计方法"，值得正式存在。**

依据：
1. **方法完整**：资料给出从重量/时间→速率→各零件面积→减速件的全链与完整算例（30kg 钢、1:1:5），非碎片观点；
2. **通用性明确**（作者声明全金属适用）且自洽于重力浇注物理（伽利略同时间）；
3. **哲学独立性成立**（见 §3）：与现行"奥赞节流口+系数"体系在方法论根处互斥——这正是其价值：给用户第二双眼睛，而不是第二个计算器皮肤；
4. 证据可核：主要数值都能回原书（附录 A 行锚），方法本应标 **ENGINEERING REFERENCE**（作者自述假说体系），不得 VERIFIED。

NO-GO 的部分（同样明确）：
- **禁止**：并入现有 gating 作"Current/Campbell 切换"（方案 A 否决理由见 §5/§6）；
- **禁止**：因 Campbell 而改任何冻结公式/参数/默认（沿用 PHASE 59"吸收思想不移植体系"+ 冻结铁律）；
- **前置条件（实现前必须解决）**：方法内数值不一致点须显式披露与选择（临界落差三套数、70mm↔1.0/1.2 归属、12.4.7 译本断裂依赖、2.24/2.45 算例落差）——**选择即标注，不允许脑补"唯一正确值"**；"选最长浇注时间"无量化公式 → 工具给"约束下最长"建议而非公式值，或标 ENGINEERING REFERENCE 建议参数。

## 5. "方法切换/混用"风险（若并入现有 gating）

同一输入 → 两方法 → **必然不同输出**（例：46.8kg 灰铁示例，Current 奥赞给 A_choke≈XXX 与比例系统；Campbell 给"时间越长越好"+1:1:n——数值体系完全不同）。风险：
1. **无意识混搭**（最危险）：Campbell 内浇口面积 + Current 直浇道 + 企业查表浇注时间 —— 两哲学不能拼接，UI 一旦同屏出现"可切换"，用户极易逐段混取；
2. **精度误读**：用户把"另一种方法"读成"更准/更松/高级模式"（尤其 Campbell 结论往往"更小更细"——收得率导向 vs 企业保守体系）；
3. **判定语境污染**：Current 的 fv/Hp/排气 1.5~4 硬校核在 Campbell 体系下无意义（无 choke 概念），反之亦然——共用结果区 schema 会互相打脸；
4. UI 双套输入（出品率/浇注方向/Ho/ph/rh 等 Current 专属量 vs Campbell 的落差/质量流）会迫使一方输入框"失效化"，认知负担爆炸；
5. 维护：两套公式/两套参数/两套默认在同一冻结模块内 = 回归矩阵翻倍、审计口径交叉。

→ **结论：任何"同一页面方法切换"在可预见的架构下都不建议**。方法平行（§6-B/C）+ 输出强方法标识才是安全形态。产品层面必须写清："这是两种工程设计方法，不是两个精度等级；产出不可跨方法混拼。"

## 8. 风险清单（未来开发期）

1. **计算混用**（最高）：Current/Campbell 输出并排而用户逐段取用 → 产品级防护：方法徽标强制、结果区"方法体系声明"、计算器间不互链参数（连 next-steps 都不要互相引）；
2. **用户理解**：把"另一种方法"当"更高级精度/官方更认可"→ 徽标文案明确"工程参考方法（作者假说体系，非标准条文）"；推荐语不得带"更好"；
3. **数据来源**：译本/导读 8 处内部数值不一致 + 12.4.7 翻译断裂 + 符号污染（°=×、:=.、⁄=÷）→ 方法实现前逐条做"取值裁决表"（采用值+出处+披露文案），未裁决项不得进代码；Campbell 自我声明假说 → 全链 ENGINEERING REFERENCE，禁 VERIFIED；
4. **UI**：双方法同屏布局混淆 → B 方案天然隔离；未来 C 用"方法选择=整树切换"而非字段级混合；
5. **维护**：第二套方法 = 第二套公式/参数/测试/审计矩阵 → 立项时同步建方法级测试（对照 Current 回归锁）+ 冻结纪律等同 gating；
6. **知识污染**：若 evidence 不加而直接堆 Campbell 卡 → 规则卡 high+A 先例已证明会虚高 → evidence 字段上线先行于 Campbell 卡导入。

## 9. 平行结构结论（§9 问题）

**是——Campbell 计算体系应当与 Current Gating Method 完全平行**：

```
Current Gating Method        Campbell Gating Method
├── Current 计算链(冻结)     ├── Campbell 计算链(ER)
├── Current 企业参数/参考    ├── Campbell 工程参考/参数
└── Current 结果schema       └── Campbell 结果schema（独立）
       两个方法不共享输入/输出字段语义；知识库内共享基础知识，方法层用 school:/method: 隔离
```

不共享公式、参数、判定、甚至大部分输入字段（口径本质不同：出品率/平均压头 vs 质量流/落差）。共享的只有：平台 UI 壳、材料/密度基础数据（各按各自口径引用，液态密度同源）、知识库统一检索、报告导出框架。这一结构把 §5 混用风险从"用户自律"变成"架构不可能"。
