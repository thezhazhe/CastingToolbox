## 4. 浇注时间采用哪个现有算法

**`calcs/gating.js` 的 `calc_t(mat, W, wall)` —— PHASE 47 的唯一权威入口，一行都没重写。**

```
T(灰铁)  W≤450: 0.70(1.41 + t/14.59)·√W ；W>450: 0.70(1.236 + t/16.65)·∛W
T(球铁)  K₁·√W，K₁ 按壁厚 10/25mm 严格分档
T(铸钢)  (2.4335 − 0.3953·log₁₀W)·√W
T(铝/铜) f·(√W + ∛(t·W/5))·2/3
```

- `W = 产品重量`（PHASE 49 定稿：时间公式只取铸件本体，**不出品率**）
- `wall = 主体壁厚`
- 审计：`tests/phase94_test.mjs` 的 94-P **源码级**断言「不许出现 0.70 / 2.4335 / Math.cbrt / 71.47」
- 测试 95-F：14 组（5 材质 × 多重量/壁厚）**逐位相等** `=== calc_t(...)`

> 审计发现的其它历史公式（未采用）：`pourTimeTable.js` 的企业查表（C 级，明确定位为"并列参照，
> 不替代公式"）、Dietert（现在是铝/铜的 `calc_t` 分支）、Campbell（`campbellGating.js` 自述
> "独立方法，与现行浇注系统计算器互不混用"）、DISA 垂直造型（同上）。**都记下了，没动。**

## 5. 流量如何计算

```
Q = V / t
V = 浇注金属液体积 = 产品重量 ÷ 出品率 ÷ 密度       （cm³）
t = 上面的 calc_t                                    （s）
```

**⚠ 与 95.txt §六 字面的一处差异，必须写清楚：**
§六 写的是「V = 产品金属液体积」。本实现取的是**浇注金属液体积**（含出品率折算，多 1/出品率 倍）。
理由三条：

1. 内浇口速度的物理意义是"**金属液通过内浇口的平均速度**"——通过内浇口的是**全部要浇进去的金属**
   （产品 + 冒口 + 浇道自身），不是产品那一部分；
2. 项目里唯一的流速参考红线（企业 R7：封闭式 ≤1.5 / 开放式 ≤1.0 m/s）就是按这个口径定的。
   只算产品本体会把流速**系统性低估 1/出品率 倍**（灰铁 75% → 低估 25%），拿它去比 R7 会偏乐观；
3. §六 的硬要求是"复用现有经典浇注系统模型、不新造第二套"——而复用 `calc_v` 就必须用它的 G 口径。

产品金属液体积本身也照常算、照常显示（`volumeCm3`，核心结果来源行里写着）——两个数都看得见。
**改口径只改一处**：`buildPouringResult` 里 `pourVolCm3` 那一行，其余全跟着走。

## 7. 两个/多个内浇口总面积问题 —— 查清了，是真 bug

### 7.1 逐层验证（95.txt §三 的 1~8 条，全部走过）

| 检查项 | 结论 |
|---|---|
| ① 连通分量是否正确拆出 N 个 | ✅ 正确（2/3/5/20 个都数得准） |
| ② 每个 component 只算一次 | ✅ `objectsFromComponents` 逐个建子网格，无重复 |
| ③ 是否有遗漏 | ✅ 无（除非组件不闭合 → 那条纪律是故意的，见 §11） |
| ④ 是否有重复计数 | ✅ 无（`totalMm2 ≡ Σ usable area`，测试 95-B 直接断言） |
| ⑤ 每步可追溯 | ✅ 详细信息表逐单元给 类型/尺寸/面积/长度/体积/闭合/原因码 |
| ⑥ `totalArea` ≡ Σ 有效 area | ✅ 恒等式由测试锁死 |
| ⑦ **世界坐标不得影响面积** | ❌ **← 真 bug 在这里** |
| ⑧ 是不是"截面定义不同" | 部分相关：本版口径是**中段代表截面**，不是最小截面（见 §8） |

### 7.2 根因：`principalAxis` 的累加锥顶取错了

散度定理那套四面体求矩，本质是"取一个固定锥顶，把所有三角形锥化后求和"。
**锥顶取世界原点**时，单个四面体的 `|det|` 随"实体离原点的距离"立方级放大，
而它们必须互相抵消才能还原真正的二阶矩 —— 离原点越远，抵消越狠，浮点误差最终吞掉二阶矩。

实测（同一块 20×5×30 的钢块，**只改世界坐标**，`Σ|w|/|m0|` 就是"抵消倍数"）：

| 位置 | Σ\|w\|/\|m0\| | 原始坐标 λ | 截面积 |
|---|---|---|---|
| 原点附近 | 1.0 | 73.97 / 33.21 / 2.06 | 99.92 mm² |
| x+400 | 9.9 | **249.56** / 33.16 / 2.07 | **113.40 mm²** |
| +400/+300/+200 | 54.2 | **314.18** / 36.16 / 10.47 | **131.85 mm²** |

主轴被算歪 → 垂直于主轴的切片跟着歪 → 面积失真。**这就是"两个内浇口总面积与预期不一致"的直接原因**
（两个单元往往不在同一位置，离原点远的那个先中招；位置不同，失真程度也不同，所以看起来像"有时对有时不对"）。

### 7.3 修复

锥顶换成**包围盒中心**（纯数值条件数修正，公式一个字没改）。
改后上面三种位置给出**逐位相同**的结果（λ = 73.89 / 33.22 / 2.06，面积 99.92 / 99.92）。
对原点附近的实体只差 0.1%（73.97 → 73.89）—— 这 0.1% 是**原来错的那一部分**。

> 关系：PHASE 94 修的 `|det|` 符号问题是这个 bug 的**另一半**。那次修好了"原点在实体外面时符号错"，
> 这次修好了"离原点远时精度崩"。两次都必要，缺一不可。

### 7.4 回归防线

`tests/phase95_test.mjs` 的 **95-A**：同一份几何，六个位置（含负坐标）
—— 数量、每个单元面积、总面积**全部 ±0.5% 内一致**，并且总面积必须≈200（修之前远离原点会跑到 226~264）。

## 8. 当前面积比到底代表什么（95.txt §九）

- UI 名称：**「检测截面积比」**（不再叫"比例"）
- 页面里逐字写着：

> 「检测截面积比」= 按当前检测到的有效截面积算出的比值（直 : 横 : 内）。
> 它不是标准浇注比 —— 有效截面积取的是单元**中段的代表性截面**，**不是最小截面 / 阻流截面**，
> 两者的工程含义不同。

**口径（必须记住）**：有效截面积 = 垂直于**该单元自身主轴**、中段 20%~80% 的**中位**截面。
- 它是"这一段流道典型有多粗"，**不是**"阻流截面有多大"。
- 所以：**不做阻流位置判定、不做封闭/开放自动分类**（那需要最小截面，本版没确认这个工程定义）。
  浇注系统类型由**用户选**，默认"未指定"，未指定就一句判定都不给。

95.txt §9 提到的另一种口径（最小截面 / 阻流截面）**本版没做**，因为：
它需要先确认"直/横/内各自取什么位置的面积"这个工程定义，而命令文件自己也说
"在没有进一步确认工程定义之前，不要把它用于更严格的工程判断"。**留作下一阶段的第一个决策点。**

## 11. 是否存在已知限制 / 本项暂不修改的

1. **组件"不闭合"就拒绝给截面积**（PHASE 89/94 的既有纪律，本阶段**保留**）。
   表现：该单元 `areaMm2 = null` → 不计入总和 → 该类标 `partial` + 主界面 WARNING
   「⚠ N 个未计入」+ 详细信息里逐单元标 ⚠ 与原因。
   **为什么不改**：95.txt §三.8 说"不要强行修改数字"；不闭合 = 有破口 = 截面可能是缺了一块的假轮廓，
   项目铁律是"宁可留空 + WARNING，也不给一个看起来合理的数"。
   **但请用户注意**：如果实测时发现"两个内浇口总面积不对"，还有第二条可能路径是**这个**
   （不是世界坐标那个）。**判别方法**：主界面有没有出现「⚠ N 个未计入」，或详细信息里该单元
   的「截面可靠性」列写着"几何不是闭合实体"。若出现 → 是模型本身有破口或实体间相连，
   不是软件算错。（程序生成的 MC 网格很容易踩到，CAD 导出的水密 STL 基本不会。）

2. **有效截面积 = 中段代表截面，不是最小截面**（见 §8）。要改成最小截面，改一处常量即可
   （`sectionProfile` 的 `rep` → `min`），但**先要有工程定义裁决**。

3. **不做阻流位置判定**：因为面积口径是中段代表截面，拿它判"封闭式/开放式"会把
   "截面定义不同"包装成"工艺分类"。浇注系统类型由用户选。

4. **产品件数 = STL 连通实体数**，**没有**"一模几件"输入框。
   这一条沿用了 89.txt §二 的产品原则（"件数只由几何决定，不要增加件数输入框"）。
   如果用户的一模是多件、而产品 STL 只画了一件，浇注时间会偏短（T ∝ √W）。
   **本阶段不改**（改了就是推翻 89.txt 的既有决策），**请用户裁决**。

5. **顶部"产品体积"只累加闭合实体**：有实体被排除时，核心结果下面会明说
   「⚠ 缺少：…」+ 来源行，绝不让残缺的体积看起来像完整的产品体积。

6. **改工艺条件会作废上一次结论**（沿用 PHASE 93 §六 纪律："任何一边的输入变了就清空，
   逼着用户重新点一次"）。换材质/换类型/改出品率之后要重新点「开始检测」。
   这一条**故意保留**：与页面既有的交互模型一致、不会出现"结果对不上输入"。
