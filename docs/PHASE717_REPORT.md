## C. 两个板块做加法（77.txt：浇注系统 / 冒口设计要更丰富）

**③ 经典浇注系统**
- 顶部统计：浇注重量 G / 浇注时间 t / 阻流截面 A / 内浇口流速
- **浇道尺寸与总截面积**（新增）：直浇道 `⌀D → 总截面 mm²`、横浇道 `n×厚×长 → 总截面`、内浇道 `n×厚×长 → 总截面`、**排气：型式 → 总排气面积 mm²（比值）**、实际面积比 S:R:G、阻流位置、液面上升速度
- 校核块：内浇口流速（R7 上限）、排气面积比（1.5~4）、目标速度对比
- 「详细计算过程」折叠保留（奥赞/企业口径全量）

**② 冒口设计**
- 单热结：Mc 来源行 + 直径/高度/补缩效率/所需模数 + 实际模数、体积、**所需补缩金属量**、体积校核、**冒口颈（含颈模数×系数）**、**迭代倍率 f**
- 多热结：逐块给出「热结 H1 的冒口 / H2 的冒口」，标注检出 Mc 与用户修改值；结果出处行"冒口结果来自现有冒口计算器"

**内浇道推荐与联动**（77.txt 六，唯一涉及数值口径的改动）
- 推荐厚度 = `max(3, round(主体壁厚 ÷ 3))`（原固定 15 mm）；推荐个数 2（提示 2~3 个）
- 推荐值以"推荐框"呈现（含当前采用值：厚 X × N 个 + 是否含用户设定）
- 两个输入框（厚度/个数）**留空 = 用推荐值**；修改后 `runGating` 按阻流面积重算内浇道长度（5 mm 档）与总面积 → 用户可见"长度随厚度/个数变化"
- ⚠️ 该项会改变设计中心浇注系统的数值（用户明确要求：原自动厚度偏厚）

## G. 结论与注意

**GO**：77.txt 的 13 条要求全部落地；显示层以"做减法"为主（页数 6→3、重复信息消除 3 处），两个板块按"做加法"丰富了展示；计算器公式零改动，改动范围限于设计中心模块。

**需要留意**
1. **内浇道默认厚度**由 15 mm 改为「主体壁厚 ÷ 3」（下限 3 mm）——这是用户明确要求的数值口径变化，会改变设计中心浇注系统的输出；独立「浇注系统」计算器保持不变。
2. **多热结时**主结果（供 gating 的 Hp 回写与 yield 的冒口重量）取 **Mc 最大者**；冒口总重按各冒口求和。
3. **lShape.stl 在当前引擎默认参数下为 no_candidate**（PHASE 71.6 起备案的引擎侧观察项），故浏览器验收中"热结勾选/弹窗/多冒口"用注入热结数据验证（数据层写入与 `writeHotspotsToProject` 同路径）。
4. 工艺计算报告已同步多热结冒口表；报告整体版式（卡片化）未做重排，如需可作下一阶段。
