### 1.2 「D = round(6·Mc·f)」的真实位置与成立条件

| 项 | 内容 |
|---|---|
| **位置** | `calcs/riser.js:98`（`D_raw = sd.DfromM(Mr_need, hd)`）+ `:100`（`D = Math.round(D_raw)`） |
| **形状表** | `calcs/riser.js:33` `cyl.DfromM = (Mr, hd) => Mr * (2 + 4*hd) / hd` |
| **成立条件** | `hd = 1.0` 时 `DfromM = 6·Mr` ⇒ **`D = round(6 · Mc · f)` 逐字成立**。设计中心 `hd_ratio` **硬编码 1.0**（`calcManifest.js:269`）⇒ 主路径恒满足 |

| **验证** | 【实测·脚本】A1：Mc 1.0→60.0 步长 0.1 共 591 点，`D == round(6·Mc·f)` **逐点成立（591/591）** |

### 2.2 Mc 增大而最终 D/H 减小——**真实存在，且有两个互相独立的成因**

> ⚠ **这是对 V2.0-07 §4 D6 的根因更正。** D6 把非单调归因于「体积主导区 + f 网格步长 0.3·Mc」。
> 本次实测发现**还有一个完全独立、且跌幅更大 5 倍的成因，它发生在体积约束全程不参与的情况下**。

#### 成因① · 体积主导区：f 网格 × round

体积约束把 D 钉在 `D_vol ≈ 144`，最小可行 `f ≈ D_vol/(6·Mc)` 随 Mc 连续下降，
而 `f` 只能落在 `{1.10+0.05k}` 网格上、`D` 又被 `round` 吸附 ⇒ 在一个网格步长内抖动，
步长 `ΔD = 6·Mc×0.05 = 0.3·Mc`，**方向可以向下**。

【实测·脚本】Mc ∈ [5,30] 步长 0.01（2501 点）：下跌点 **49 个（2.0%）**，绝对跌幅 max **6 mm**，相对 max **4.00%**。

```
Mc 14.0 → f=1.75 → D = round(6×14×1.75) = 147
Mc 14.5 → f=1.65 → D = round(6×14.5×1.65) = 144     ← Mc 变大 0.5，D 反而小 3
```

#### 成因② · 小 Mc 模数区：`modOk` 的 0.99 取整容差与 `Math.round` 打架

**体积约束全程未参与**（`cast_wt = 0`），纯粹是模数约束自己的问题。

机理（【源码确认】+【实测·Node】）：设 `x = 6·Mc·f`，则 `D = round(x)`、`Mr_act = round(x)/6`，
判据 `Mr_act ≥ 0.99·Mr_need` 等价于

```
round(x) ≥ 0.99·x     ⇔    当 x 向下取整（小数部分 < 0.5）时，需  小数部分(x) ≤ 0.01·x
```

- `x` 向上取整 ⇒ 判据**自动通过**
- `x` 向下取整 ⇒ 只有当"被舍掉的那部分"不超过 `1%·x` 才通过

而 `f` 每加一格，`x` 只增加 `0.3·Mc`。当 `Mc` 很小时，**被舍掉的 0.5 mm 就足以让判据失败**，
于是 `f` 被一格一格顶高，**直到某一格恰好让 `x` 越过 0.5（改为向上取整）才逃出去**——
逃出去的格数完全由 `x` 的小数相位决定，**与 Mc 的大小无关** ⇒ **锯齿状跳变**。

**充分条件**：`f = 1.10` 恒通过需要 `0.5 ≤ 0.01 × 6.6·Mc` ⇒ **`Mc ≥ 7.58 mm`**。
即 **成因② 只发生在 `Mc < 7.58`**。

【实测·脚本】`cast_wt = 0`，Mc ∈ [0.5,10] 步长 0.01（951 点）：下跌点 **40 个（4.2%）**，
绝对跌幅 max **10 mm**，**相对跌幅 max 21.43%**：

| Mc → Mc+0.01 | f | D | 跌幅 |
|---|---|---|---|
| **3.37 → 3.38** | 2.30 → 1.80 | **47 → 37** | **10 mm = 21.3%** |
| 3.25 → 3.26 | 1.45 → 1.10 | 28 → 22 | 6 mm = 21.4% |
| 3.38 → 3.39 | 1.80 → 1.50 | 37 → 31 | 6 mm = 16.2% |
| 3.39 → 3.40 | 1.50 → 1.25 | 31 → 26 | 5 mm = 16.1% |

**`runRiser` 直调复核**（绕开 `calcManifest`，证明与选值逻辑无关）：

```
Mc=3.36  f=1.10  D=22   x=22.176   小数部分 0.176 ≤ 0.222 → 通过
Mc=3.37  f=2.30  D=47   x=46.506   小数部分 0.506 > 0.5   → 改为向上取整才通过（中间 24 格全部失败）
Mc=3.38  f=1.80  D=37   x=36.504   小数部分 0.504 > 0.5   → 逃出
Mc=3.39  f=1.50  D=31   x=30.510   小数部分 0.510 > 0.5   → 逃出
Mc=3.40  f=1.25  D=26   x=25.500   恰好 0.5，向上取整
```

## 6. 真实铸件验证所需的最小数据清单（119.txt §六.6）

> 目的不是"再收集一堆数据"，而是**用最少的字段去证伪一条最强的预测**。

### 6.1 那条可证伪的强预测

体积主导区存在恒等式（V2.0-01 实测确认）：

```
冒口重量 / 铸件净重  =  shrink / eff        ← 与几何、与 Mc 全都无关
球铁 + 圆柱形（设计中心默认）= 3% / 14% = 21.4%
灰铁 + 圆柱形 = 14.3% ｜ 球铁 + 球顶圆柱 = 12.0% ｜ 铸钢 + 圆柱形 = 32.1%
```

**只要拿到 1 个真实件的「铸件净重 + 冒口实际尺寸 + 材质 + 冒口形式」，就能立刻证伪或证实它。**
这是整个 P0 里**唯一一条不需要新算法、不需要新工具就能判定的命题**。

### 6.2 最小字段清单（每件 7 项，缺项可空但要标注）

| # | 字段 | 用途 | 是否必须 |
|---|---|---|---|
| 1 | **铸件净重**（kg，或 3D 体积 cm³ + 材质） | 算 `Vc`、`冒口重/净重` 的分母 | **必须** |
| 2 | **实际冒口尺寸**（D×H，或方 a×H，或球 ⌀D） | 算 `Vr`、`冒口重` 的分子 | **必须** |
| 3 | **材质牌号**（QT450-10 / HT250 / ZG270-500…） | 定 `shrink` / `eff` / `rho` | **必须** |
| 4 | **冒口形式**（明顶圆柱 / 暗侧 / 球顶柱 / 发热保温） | 定 `eff`（14/20/25/35） | **必须** |
| 5 | **是否出现缩孔缺陷**及位置 | 判断现设计是"偏大但安全"还是"其实刚好" | 强烈建议 |
| 6 | **实际出品率**（%） | 交叉核对 `yield` 模块 | 建议 |
| 7 | 浇注温度 / 浇注方式 | 影响凝固，但当前模型未用 | 可选 |

**件数**：**1~3 件即可起步**，其中至少 1 件是用户自己观察到"冒口偏大"的。
**另外强烈建议附 1 个 STL**：用于复算 `Mc`、`final_f`，并顺带检查 R2（体积是否被缠绕警告污染）。

### 6.3 拿到之后应该做什么（**只做核对，不做改动**）

1. 逐件填表：`实际 Vr`、`实际冒口重`、`冒口重/净重`、`实际 Mr = Vr/A`。
2. 用同一件跑 `runRiser`（**只读，不改代码**），记录 `Mc / Mr_need / D / H / final_f / 冒口重`。
3. **重点看三件事**：
   - `冒口重/净重` 是否落在 `shrink/eff` 附近（验证恒等式）
   - `final_f` 是否撞顶 3.55（撞顶 = 未收敛，说明该件超出了当前模型能力）
   - 实际 `D` 与算出的 `D` 相差多少、方向如何
