## 2. 当前代码中的实际体积约束定义

**以实际代码为准重新读出**（`calcs/riser.js:213-216`，V2.0-18 之后未改动）：

```js
let volOk = true;
if (cw > 0) {
  const Vc = cw * 1000000 / rhoUsed;   // 铸件体积 mm³ = 重量 kg × 1e6 / 固态密度 g·cm⁻³
  volOk = effV >= Vc * md.shrink;      // effV = Vr × eff
}
```

`calcs/riserDreq.js` 的判定函数**逐字复刻**这两行（含运算次序：先 `cw * 1000000` 再 `/ rhoUsed`，再 `* shrink`），
不重新推导、不合并同类项 —— 浮点结合次序不同会产生 ULP 级差异。

### 2.1 与模数判据的口径差异（**不可混淆**）

| | 表达式 | 松弛 |
|---|---|---|
| 模数判据 | `Mr_act >= Mr_need * 0.99` | 有 1% 松弛 |
| 体积判据 | `effV >= needVol` | **没有 0.99，也没有任何松弛** |

`calcs/riserDreq.js` 只使用**体积判据**那一行，`0.99` 一次都没出现（`F5` 有反向断言的先例，本模块源码里也无该常数）。

### 2.2 `cw ≤ 0` 是**结构性短路**，不是"约束已满足"

`cw > 0 ? … : true` 意味着 `cw = 0` 时**整个体积校核根本不执行**。
本模块因此返回 **`not_applicable`**，而**不是**返回一个"看起来满足"的小直径 —— 这是 130.txt §3.1 的硬要求。

## 5. 整数扫描的算法和终止条件

### 5.1 由整数 D 到体积：**本模块最关键的口径选择**

`calcs/riser.js` 里"由直径得到高度"有**两条**规则，它们**不是**同一个函数：

| | 位置 | 表达式 | H 的来源 |
|---|---|---|---|
| ① 主路径 | `:189-190` | `d = round(raw); h = round(raw × hdR)` | **连续** raw |
| ② 升档路径 | `:196`（PHASE V2.0-13 C′） | `d += 1; h = round(d × hdR)` | **整数** d |

**探针实测**（`tests/experiments/_probe19_geom.mjs` P4，120 个收敛样本）：
两者相差 **ΔH ∈ {−1, 0, +1}**，实测分布 `−1:12 / 0:103 / +1:5`，**从不超过 1mm**。

**本模块取 ②（`H = round(D × hd)`）**，理由三条：

1. 主路径的 H 依赖 `raw`，而 `raw = sd.DfromM(Mr, hd)` —— **依赖模数 Mc**。D_req 的定义里没有 Mc ⇒ 主路径**不可用**。
2. ② 是现有代码里**唯一**存在的"由整数直径求 H"的规则。
3. §4.2「按现有模型的**真实**高度舍入规则计算 H」—— ② 就是那条真实规则，且是项目**已经采纳**的口径
   （V2.0-13 的用意正是"当取整后的 H 不够好时，改用 `round(D×hd)`"）。

**⚠ 后果如实披露**：`runRiser` 采纳的 (D, H) 与本模块口径可能差 1mm。
本阶段实测了它的实际影响（§8.3）：384 组对照中，**runRiser 采纳的 D 在 D_req 口径下不满足体积约束的有 0 个**。

特殊形状的修正照抄 `calcs/riser.js:191-192`：
`sphere_head` 且 `H < D/2` ⇒ `H = round(D/2)`；`sphere` ⇒ `H ≡ D`（与 hd 无关）。

### 5.2 上界的**依据**（§4.3.6「不得任意设置未经说明的工程上限」）

记 `A = needVol / eff`。要找一个**已证明**满足 `V(D) ≥ A` 的 `D_hi`：

| 形状 | 用到的下界 | 前提 | `D_hi` |
|---|---|---|---|
| `sphere` | `V = πD³/6`（精确） | 无 | `⌈∛(6A/π)⌉` |
| `sphere_head` | `V ≥ 2/3·π·(D/2)³ = πD³/12` | **无条件**（`Hc ≤ 0` 时 V 恰为半球体积） | `⌈∛(12A/π)⌉` |
| `cyl` | `D·hd ≥ 0.5 ⇒ round(D·hd) ≥ 1 ⇒ V ≥ πD²/4` | `D_hi ≥ 0.5/hd`（自满足） | `max(⌈0.5/hd⌉, ⌈√(4A/π)⌉)` |
| `square` | 同上，`V = D²·round(D·hd) ≥ D²` | 同上 | `max(⌈0.5/hd⌉, ⌈√A⌉)` |

**实测验算**（探针 P3，728 个 `(形状, hd, A)` 组合，含 `hd = 1e-6` 与 `A = 1e15`）：`V(D_hi) ≥ A` **全部成立，0 例外**。

### 5.3 两条搜索路径与终止条件

```
satisfies(1)                        ⇒ D = 1（直接命中）
hi ≤ 1e6                            ⇒ scan   ：d = 1, 2, 3, … 第一个满足的就是全局最小
否则                                 ⇒ bisect ：在 [0, hi] 上二分（依赖 §6.1 的单调性）
```

- **`scan` 的最小性不依赖任何假设** —— 所有更小的 D 都被**实际检查过**且为假。
- **`bisect`** 的正确性依赖 `V(D)` 单调不减；该性质在 §6.1 有证明，在 §8.2 的 E5 有 168,000 点实测。
  走这条路径时 `assumptions` 会**显式记录**"本次使用了单调性二分"。
- **1e6 这个预算的依据**：单次 `satisfies` 是 O(1) 的几次浮点运算，1e6 次在 Node 上约 10ms 量级，
  属于交互可接受范围。⚠ 该切换**只影响速度，不影响结果** —— 两条路径都要过同一组终检。
- **终检**（无论走哪条路）：① `satisfies(D)` 为真；② `D > 1` 时 `satisfies(D−1)` 为假。
  任一不成立 ⇒ 返回 `unsupported`（**不给出结果**，而不是给出一个可能错的）。

**`no_solution` 为什么构造不出来**：上界已**证明**有解，浮点保险循环又给了 8 次放大机会。
该状态保留给"浮点异常导致上界失效"的情形，本阶段**未能**找到一个真实触发用例 —— **如实记录，不编造**。

## 6. 最小性证明方法

### 6.1 单调性证明：`V(D)` 对整数 D **单调不减**

`bisect` 路径的唯一依赖。四种形状分别论证（`H` 均已按 §5.1 的规则取整数）。

**（a）`sphere`** —— `V(D) = πD³/6`，对 D 严格增。**平凡。**

**（b）`cyl`** —— `V(D) = (π/4)·D²·round(D·hd)`。
D → D+1 时：因子 `D²` 严格增；因子 `round(D·hd)` **非减**（因 `D·hd` 非减，`Math.round` 单调）。
两个**非负非减**之积**非减**。∎

**（c）`square`** —— `V(D) = D²·round(D·hd)`，同 (b)。∎

**（d）`sphere_head`** —— `V(D) = πr²·[2r/3 + max(0, H−r)]`，`r = D/2`，`H = max(round(D·hd), round(D/2))`。
记 `r' = r + 0.5`，`H' = H(D+1)`。因 `round(D·hd)` 与 `round(D/2)` 均非减，故 `H' ≥ H`。分三种情形：

- **情形 1：`H ≤ r`。** 此时 `Hc = H − r ≤ 0`，`V(D) = 2πr³/3 = πD³/12`。
  而 `V(D+1) ≥ π(D+1)³/12`（下界无条件成立，见 §5.2）`> πD³/12 = V(D)`。✓
- **情形 2：`H > r` 且 `H' ≤ r'`。** `V(D) ≤ 2πr³/3 = πD³/12`，而 `V(D+1) = π(D+1)³/12 ≥ πD³/12 ≥ V(D)`。✓
- **情形 3：`H > r` 且 `H' > r'`。** 两处都走 `V = πr²(H − r/3)`，则
  ```
  V(D+1) − V(D)
    = π[ r'²(H' − r'/3) − r²(H − r/3) ]
    = π[ r²(H'−H) + (r+0.25)·H' − ((r+0.5)³ − r³)/3 ]
    ≥ π[ 0 + (r+0.25)·r − (1.5r² + 0.75r + 0.125)/3 ]     （用 H' ≥ H ≥ r）
    = π[ r²/2 − 1/24 ]
    ≥ 0   ⟺   r² ≥ 1/12   ⟺   r ≥ 0.2887   ⟸   D ≥ 1
  ```
  ✓

三种情形穷尽，故 `sphere_head` 的 `V(D)` 对 `D ≥ 1` 单调不减。∎

**实测佐证**（实验 `E5`）：168,000 个 `(形状, hd, D)` 点（4 形状 × 14 个 hd × D=1..3000），**0 违反**。
另有写模块之前的探针 P1：120,000 点，**0 违反**。

### 6.2 三层最小性保证（由强到弱）

1. **构造性（`scan` 路径）**：从 1 起逐个试，第一个满足的即为全局最小。
   这是**定义上**的最小性，**不含任何假设** —— 对应 §4.3.1 + §4.3.2。
2. **单调性（`bisect` 路径）**：在 §6.1 的前提下，`satisfies(D) && !satisfies(D−1)`
   **等价于**"所有更小的 D 都不满足"。
   ⚠ 这是 §4.3.5「不得仅检查 D−1 就宣称全局最小」的**反面**：只有在**证明了单调性**之后，检查 D−1 才是充分的。
3. **独立复核（测试与实验）**：`B1`/`B2`/`C3`/`C4` 与实验 `E1` 用**独立复刻**的几何
   （在 `phasev2019_test.mjs` / `phasev2019_dreq.mjs` 里**各自重写一遍** `hOf`/`vOf`/`okAt`，
   不复用模块的导出），对每个成功样本**完整回扫** `d ∈ [1, value)`。
   实测规模：**390,440 次**更小直径检查，**0 反例**。

## 7. 连续公式的适用条件和限制

`continuous = ∛(A/k)`，其中 `k` 是"H 不取整"（即 `H ≡ D·hd`）时的 `V/D³`：

| 形状 | `k` | 适用条件 |
|---|---|---|
| `cyl` | `π·hd/4` | 无附加条件 |
| `square` | `hd` | 无附加条件 |
| `sphere` | `π/6` | **精确**（`H ≡ D` 本就是整数，无取整损失） |
| `sphere_head` | `π(3hd−0.5)/12` | **仅 `hd ≥ 0.5`** |

### 7.1 `sphere_head` 在 `hd < 0.5` 时**必须**返回 `null`（探针 P2 实测）

| hd | 朴素连续式 k | 实测 `V/D³` | 相对误差 |
|---|---|---|---|
| 1e-6 | −0.1309 | 0.2618 (= π/12) | **150%** |
| 0.1 | −0.0524 | 0.2618 | **120%** |
| 0.3 | +0.1047 | 0.2618 | **60%** |
| 0.49 | +0.2539 | 0.2618 | **3.0%** |
| **0.5** | 0.2618 | 0.2618 | **0.0000%** |

原因：`hd < 0.5` 时 `H` 被抬高到 `round(D/2)`，体积退化为半球（`πD³/12`），
**连续式在该区间根本没有定义域**。
★ 注意 `hd = 0.49` 时误差**只有 3%** —— 看起来"差不多"，但它是错的。**这不构成提供近似值的理由。**

### 7.2 「连续解向上取整」**不是**可靠做法（§4.1 的直接证据）

实测 120 组：`ceil(continuous) == D_req` 的 **115 组（95.8%）**，**4 组偏大、1 组偏小**。

- 偏大的样本：`D_req < continuous`（`gap` 最小 **−0.316**）—— 取整反而**多要了一档**。
- 偏小的样本：`D_req = ceil(continuous) + 1`（`gap` 最大 **1.081**）—— 取整**少要一档**，那个 D **不满足**约束。

⭐ 这正是 §4.1「不得仅凭连续公式计算结果后向上取整，就认定得到了正确的最小整数直径」的**实测证据**，
两个方向都会错。`gap` 字段就是用来暴露这个差距的。

### 8.3 ★ E3 的完整数据：D_req 与 runRiser 推荐尺寸的关系

384 组对照（4 形状 × 4 hd × 6 cw × 4 Mc），按 `runRiser` 的 `bind` 归因分组：

| bind | 组数 | `D_req ≤ D_runRiser` | 平均差 | 最大正差 |
|---|---|---|---|---|
| `start`（f 起点即满足 ⇒ 模数主导） | 79 | 79 / 79（100%） | **−58.42mm** | 0 |
| `volume`（体积约束把它顶上去） | 93 | 93 / 93（100%） | **−1.29mm** | 0 |
| `limit`（50 轮未收敛） | 212 | **0 / 212（0%）** | **+119.23mm** | **+397mm** |

**三条读法：**

1. **`bind='start'` 平均差 −58mm** —— 模数主导时体积约束**远未用尽**，`runRiser` 的尺寸是模数顶上来的。
   ⇒ `D_req` 与"推荐尺寸"**不是同一个量**，任何把两者混为一谈的表述都是错的。
2. **`bind='volume'` 平均差 −1.29mm** —— 体积主导时两者非常接近，差值来自 f 的 0.05 离散步长。
   ⇒ 这是**口径自洽性**的强证据：本模块的 `H = round(D×hd)` 口径与 runRiser 在该情形下几乎重合。
   ⇒ **也是将来做真实件验证时最容易判断"谁对"的一组。**
3. **`bind='limit'` 平均差 +119mm（最大 397mm）** —— ★ **本阶段的重大副产品**。
   V2.0-17 已判定 limit 的真根因是"100% 仅体积不过"，且 `f_req ∝ 1/Mc` ⇒ 抬 f 上限方向是错的。
   `D_req` 现在把这个缺口**量化成了毫米数**：未收敛时 `runRiser` 给出的尺寸，
   比体积约束真正需要的平均小 **119mm**。
   ⚠ 但这**没有修**这个缺陷 —— 它是既有的、独立的，本阶段只提供了一把量它的尺子。

**口径差异的实际影响**：384 组中，`runRiser` 采纳的 D 在 D_req 口径（`H = round(D×hd)`）下
**不满足**体积约束的有 **0 个**（0.0%）。
⇒ §5.1 披露的 ΔH ∈ {−1,0,+1} 差异，在本阶段的样本里**没有造成实质后果** —— 但这条结论**只在这 384 组上成立**。

### 11.2 未覆盖输入与工程局限

- **R-4** `hd → 0` 时 `D_req` 爆炸（`hd=1e-9 ⇒ 5×10⁸ mm`）。这是**既有口径**的必然结果
  （`H = round(D·hd)` 在 D 小时为 0，必须等到 `D ≥ 0.5/hd` 才有 H ≥ 1），**不是**本模块新增的行为。
  与 V2.0-18 的 U-1 同源。**要不要设工程上界仍是产品决策**，本阶段按 §八 未擅自设阈值。
- **R-5** 大 D（> 2⁵³ 区域）时 `D³` 的浮点精度下降。上界检查已挡住 `hi > MAX_SAFE_INTEGER`，
  但**没有**挡住"解本身极大但上界尚可表示"的中间地带。实测未触发。
- **R-6** `sphere_head` 的 `H = round(D/2)` 对**奇数 D** 会引入 +50% 的半球体积
  （`D=3` 时 k 偏离 π/12 达 +50%）。本模块用整数扫描如实处理；连续解在 `hd<0.5` 时**已返回 null**。
- ★★ **R-7（最大的一条，还是业务上的）**：`data/riser-benchmark/cases.csv` **仍为 0 行**。
  `D_req` 现在能算了、能自证最小性了，但**没有任何真实铸件告诉过我们这个数对不对**。
  **这条不解决，后面所有"再精确一点"的工作都是在放大一个未经验证的前提。**

