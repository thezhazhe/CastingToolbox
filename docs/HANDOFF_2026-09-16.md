### 1.1 工作区有未提交的改动，别弄丢了

```

 M js/search.js    ← loadKnowledge 并发化（FETCH_CONCURRENCY=16 + 进行中 promise 守卫）

```

**这两处改的是什么**：挂 GitHub Pages 时发现，网页版知识库 172 个 JSON 是**串行** `await fetch`。
本地磁盘 0.4s 无感，**挂到网上实测 67 秒**（每次往返约 390ms × 172 次）。受影响：
首页搜索下拉、缺陷查找、工艺向导首屏。计算器与设计中心不受影响。

改成并发抓取 + 首屏后预取后，模拟 390ms 延迟实测：冷加载 67s → 11.6s，用户输入→下拉出结果 **217ms**。
**语义刻意没变**：仍是"单条失败即跳过"，返回顺序仍与 `DATA_INDEX` 清单一致（已验证 `orderPreserved: true`）。

**状态：改好了，验证过了，但没提交、没推送。** 线上跑的还是旧版。
新窗口先决定：是要提交推送（用户一直没明确说"推"），还是先做别的。**别 `git checkout` 掉。**

## 5. 环境事实与坑（都是踩过的）

1. **本机没有 Chrome，只有 Edge**。所有浏览器脚本走 `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe` + CDP。
2. **github.com 的 git 传输被阻断**，`git push` 会失败。**只有 `api.github.com` 可达**。
   → 发版走 `node scripts/publish_via_api.mjs`（按 GitHub API 推当前树）。
   → 因此**远端 main 是一个快照提交，没有真实历史**；本地也没有 `origin/main` 引用（`git branch -a` 只有 `main`）。
   → 大 body 必须走 `--message-file`（stdin 管道会被 GitHub 判 malformed）。
3. **Excel COM 是检验表项目的坑**，与本项目无关；但同一台机器同一套记忆，别搞混。
4. **大件测试夹具不入库**（合计约 2.2GB，超 GitHub 单文件 100MB 上限），存在时跑、缺时**跳过而非失败**。
   见 `tests/FIXTURES.md`。本机 `tests/engineering-generated/models/` 与 `tests/golden/*.stl` **是存在的**。
5. **`tests/real-stl/` 是作者真实产品几何，不适合公开**（README 里也写了）。做任何截图/演示材料别用。
6. **程序生成的测试件网格都不干净**（本窗口实测 5 个全有缠绕方向/退化三角形警告）。
   这是测试件的问题不是软件的问题，但**做演示材料时会露出来**——真实 CAD 导出件通常没这问题。
7. **CDP `Page.captureScreenshot` 的 `clip` 用的是页面坐标不是视口坐标**。
   页面滚过之后必须把 `scrollY` 加回去，否则截到的是文档顶部（空白）。本窗口在这上面栽过两次。
8. **Android 从未做过真机验收**（本机无设备/AVD）。Release 说明里已如实标注，**任何材料都不许声称 PASS**。
