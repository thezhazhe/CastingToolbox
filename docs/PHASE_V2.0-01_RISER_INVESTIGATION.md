## 1. 本阶段目的

### 1.1 为什么现在调查冒口

用户报告：**在「工艺设计中心」导入真实产品 STL 后，按热点算出来的冒口偏大，有些明显超出工程合理尺寸。**

处理这类问题最自然的冲动是"把系数调小一点"（1.10 → 1.05，效率 14% → 20%，体积校核打个折）。
**本阶段明确禁止这样做**，原因有二：

1. **不知道偏大发生在哪一段。** 从"热点模数"到"最终推荐尺寸"之间隔着：安全系数 f、目标模数、
   体积校核、几何反算、取整五道环节。任何一道都可能放大，也可能是**几道同时放大**。
   在不知道是哪一道的情况下调系数，等于用一个错误去抵消另一个错误。
2. **本链有"用户参数被静默改掉"的前科**（PHASE 97 查出 `applyMaterialDefaults` 无条件覆盖用户出品率），
   也有多处**自述未校准的工程假设**。不先建立可追溯链路，任何修改都不可验证。

### 1.2 这份报告如何服务 V2.0-02

V2.0-02 要做的是「冒口算法优化」。本报告提供三件它必需的东西：

| 交付 | 用途 |
|---|---|
| **完整可追溯计算链**（§4/§5/§6） | V2.0-02 改任何一处，都能立刻知道影响哪一段 |
| **全部放大系数清单**（§7），标出哪些真正放大了结果 | 避免"改了一个不起作用的系数"或"漏掉真正起作用的那个" |
| **实测量化归因**（§9/§10） | 把"偏大"拆成可验证的独立假设，而不是一个笼统的感受 |

**本报告不含任何修改方案**（99.txt §十四 明令禁止）。

### 4.2 Mc 的选源矩阵（`calcManifest.js:180-232`）

按优先级（**实际代码**，与"有热结就用热结"的直觉不完全一致）：

```
① 用户在「冒口参数」勾选了热结（process.hsPick 非空）
     → userMc = true,  mc = max(勾选热结的 mc)
② 否则 有热结（hotspots.items 非空）
     → mc = process.mcHotspot（= hotspots[0].mc，V3 结果已按 peakModulus 降序 → 即最大热结）
       · 若用户显式改过 mcHotspot（USER_OVERRIDE/USER_INPUT）→ userMc = true
③ 否则 用户显式改过 wallHot → mc = wallHot
④ 否则 用户显式改过 mcHotspot → mc = mcHotspot
⑤ 否则 门禁：
     hotspots.status = INSUFFICIENT_RESOLUTION → return {blocked:true}（不自动建议）
     hotspots.status = LOW_CONFIDENCE        → return {blocked:true}（不自动建议）
     hotspots.status = ok 且有热结            → mc = process.mcHotspot
     其余（NO_HOTSPOT / 手动模式）            → mc = process.wallHot（= 主体壁厚 ÷ 2）
```

**`process.hsPick` 默认值为 `[]`（空）** → **默认路径只算 1 个冒口**（最大热结）。
多冒口需要用户在参数区**手动勾选**热结。

## 5. STL → 热点 → 模数 → 冒口尺寸 完整计算链

### 5.1 A. STL（`js/engine/stl.js`）

| 项 | 实际实现 | 备注 |
|---|---|---|
| 读取 | `parseSTL(buf)`，二进制/ASCII | 项目自述"STL 无单位，解析层不换算" |
| 单位假设 | **无假设也无换算**。导入时 `state.unit = 'mm'` **硬编码** | 用户可在参数区改 mm/cm/m/inch（`UNIT_SCALE = {mm:1, cm:10, m:1000, inch:25.4}`） |
| 自动缩放 | **不存在**（grep `autoScale`/`rescale` 零命中） | 模型尺度即 STL 原始坐标尺度 |
| 体积 | `computeVolume = \|Σ 有符号四面体体积\| / 6`（散度定理） | 对**闭合且缠绕一致**的网格精确 |
| 面积 | `computeArea = Σ \|(v1−v0)×(v2−v0)\| / 2` | 与缠绕方向**无关**（恒正确） |
| 包围盒 | `computeBounds` 逐顶点 min/max | 正确 |
| 有效性 | `validateMesh` → issues（error/warning 分级）+ `deriveGeomStatus → VALID/WARNING/INVALID` | 非流形/缠绕不一致是 **warning**，不阻止分析 |

**体积口径的实测风险**（见 §9.5）：`computeVolume` 依赖缠绕一致性；实测把三角面缠绕翻转
50% 会使体积掉到 **8.93%**。而 `tests/real-stl/HR4012…stl` 恰好带 `INCONSISTENT_WINDING` 警告。

**重量链**：`geometry.volumeCm3 = volume/1000` → `refreshWeight()`：
`netWeightKg = volumeCm3 × solidDensity / 1000`；`blankWeightKg` 默认同步净重。
**冒口的体积校核用的是净重**（受上述体积口径影响）。

### 5.2 B. 热点（`js/engine/v3/hotspotV3.js`）

| 项 | 实际实现 |
|---|---|
| 输入 | `mesh` + `geometry`（含 BVH）+ `opts`（覆盖 `V3_DEFAULTS`） |
| 算法依据 | 局部热模数场 M(p) = V_local / A_local（Chvorinov 几何近似） |
| 是否用局部几何 | **是**。窗口 = 以采样点为中心、半宽 `R = k × char(p)` 的**体素块**，`char = 2 × 到表面距离`；`k ∈ {0.5, 1.0, 2.0}` 用于多尺度验证；**主用 k = 1.0** |
| 输出 | `hotspots[] = {hotspotId, position, peakModulus, normalizedModulus, regionVolume, regionArea, confidence, …}` |
| 判定 | 严格 6 邻域局部极大 → 环带显著性 `prominence ≥ 0.35` → NMS → 多尺度验证 → region ≥ 100 mm³ → region 占比判据 → 置信度 ≥ 0.5 |
| 简化假设 | ① **窗口是体素块（立方）**，非等温面；② `char` 由到表面距离定义；③ **M 有物理封顶**（见 §5.3） |

### 5.3 C. 模数（★ 本段有一个**未被任何断言覆盖**的关键常数）

**两把尺子**（PHASE 24 起就存在）：

```
峰值 M（= 上报的 mc）:  m = min( V/A ,  modulusCeilRatio × d )      d = 到最近表面距离
region 生长阈值:         用未封顶的原始 V/A                          （peakRegion.js:127-128）
```

`configV3.js:45`：

```js
modulusCeilRatio: 1 / 3,   // 物理上界：M ≤ (1/3)×d
//   半球解析 (2/3)d 对"表面嵌入半球"成立，但真实团块延伸到内部（散热面更大 → M 更低）。
//   实测校准：(2/3)d 使 cube 表面层 26.7 > 中心 16.7（伪峰）；
//             (1/3)d → 表面层 13.3 < 中心 16.7 ✓ 无峰；
//   工程假设 UNKNOWN（两个解析候选实验选定），待真实 STL 校准
```

**配置文件自己写明这是"工程假设 UNKNOWN，待真实 STL 校准"。**
本次调查第一次把它校准了（§9.4 受控实验）：**该封顶使上报的热点模数系统性偏低，中位为解析真值的 0.836。**

单位链路：`V` 用 `vs³`（mm³）、`A` 用 `vs²`（mm²）→ **M 单位 = mm**。
`peakModulus` 经 `v3ViewAdapter.js:36` 原样映射为 `mc`（**不缩放、不修正**）。
设计中心的 Mc 输入框再 `Math.round(mc*10)/10` 保留 1 位小数。

### 5.4 D. 目标冒口模数（`calcs/riser.js:92-114`）

```js
let f = 1.10;                                  // 起点
for (let iter = 0; iter < 50; iter++) {        // 上限 50 轮
  Mr_need = Mc * f;
  D = sd.DfromM(Mr_need, hd);   H = Math.round(D * hd);   D = Math.round(D);
  Mr_act = sd.M(D, H);          Vr = sd.V(D, H);          effV = Vr * eff;
  final_f = f;
  const modOk = Mr_act >= Mr_need * 0.99;
  let volOk = true;
  if (cw > 0) { const Vc = cw * 1e6 / rhoUsed;  volOk = effV >= Vc * md.shrink; }
  if (modOk && volOk) break;
  f += 0.05;
}
```

**这是全链唯一"放大"的地方，而且是两个约束的联立**：

| 约束 | 表达式 | 依赖 |
|---|---|---|
| 模数约束 | `Mr_act ≥ Mc × f × 0.99` | 只依赖 Mc 与形状 |
| **体积约束** | `Vr × eff ≥ Vc × shrink`，`Vc = 铸件净重 × 1e6 / ρ` | **只依赖铸件重量与材料，完全不依赖 Mc** |

→ **体积约束一旦主导，冒口尺寸与热点模数脱钩**，完全由"铸件有多重"决定。

### 5.5 E. 冒口尺寸（几何反算）

| 形状 | M(D,H) | DfromM(Mr, hd) | 体积 V(D,H) | effKey / 默认效率 |
|---|---|---|---|---|
| `cyl` 圆柱形 | `D·H / (2D+4H)` | `Mr·(2+4hd)/hd`（解析） | `π D² H / 4` | `eff_open` / **14%** |
| `square` 正方柱 | `a·H / (2a+4H)` | 同 cyl | `a² H` | `eff_open` / 14% |
| `sphere` 球形 | `D / 6` | `Mr·6`（解析） | `4/3 π (D/2)³` | `eff_blind` / 20% |
| `sphere_head` 球顶圆柱 | V/A 数值式 | 初值 `Mr(2+4hd)/hd/0.92` 后**不动点迭代 20 次** | 半球 + 柱 | `eff_sph` / **25%** |

**设计中心实际参数**（`calcManifest.js:244-247`）：
- `shape` = `process.riserShape`，**默认 `'cyl'`**（效率最低的 14%）
- **`hd_ratio` 硬编码 `1.0`**
- `eff` 传 `undefined` → 用表默认值

**在 hd = 1.0 下，`cyl` 与 `sphere_head` 的模数公式完全等价（都化为 M = D/6）**，
所以**形状在设计中心不改变直径，只通过补缩效率改变体积校核与迭代倍率 f**
（`tests/phase78_test.mjs:133` 已把这个现象写成断言）。

**"工作高度"未实现**（grep 零命中）：代码用"整个冒口体积 × 效率"，工作高度由效率系数吸收。

## 6. 所有关键公式（照抄实际代码）

| 环节 | 代码位置 | 公式 |
|---|---|---|
| 体积 | `stl.js:93-104` | `V = \|Σ (v0 · (v1×v2))\| / 6` |
| 表面积 | `stl.js:107-119` | `A = Σ \|(v1−v0)×(v2−v0)\| / 2` |
| 局部模数场 | `modulusField.js:64` | `M = V_window / A_window` |
| **模数封顶** | `modulusField.js:72` | `M = min(M, (1/3) × d)`，d = 到表面距离 |
| 窗口半径 | `modulusField.js:58` | `R = clamp(k × char, charFloor, windowCapRatio × mdim)`，`char = 2d`，k = 1.0 |
| 环带显著性 | `peakRegion.js:69` | `prominence = (M_peak − median(M_ring)) / M_peak`，环带 = 1R~2R 壳 |
| region 生长 | `peakRegion.js:128` | `threshold = max(封顶M_peak, 原始V/A_peak) × 0.8` |
| region 面积 | `peakRegion.js:169` | `regionArea = regionVolume / meanM`（由 M=V/A 反推） |
| 置信度 | `peakRegion.js:191` | `0.4·normM + 0.25·prominence + 0.15·volNorm + 0.2·stability` |
| **目标模数** | `riser.js:94` | `Mr_need = Mc × f`，f 从 1.10 起 +0.05/轮 |
| **体积需求** | `riser.js:109,122` | `Vc = cw × 1e6 / ρ`；`needVol = Vc × shrink` |
| **有效补缩** | `riser.js:104` | `effV = Vr × eff` |
| **体积校核** | `riser.js:110,125` | `volOk = effV ≥ needVol` |

## 9. 当前发现的问题（按 99.txt §六 四分类）

### A. 程序 Bug

**A-1 —— `computeVolume` 对缠绕不一致不鲁棒**（`js/engine/stl.js:93-104`）
散度定理求出的是**有符号和**，最后才取绝对值。若只有**部分**三角面缠绕反向，贡献会相互抵消。
实测（把三角面按确定性伪随机翻转）：

|---|---|---|---|---|
| cube50 | — | — | 83.3% | 50.0% |

| HR4012（真实件） | 98.2% | 82.8% | 50.1% | **8.9%** |

（面积为 `Σ|叉积|`，**不受影响**，恒 100%。）
`validateMesh` 把 `INCONSISTENT_WINDING` 报为 **warning**，不阻止分析；
`tests/real-stl/HR4012塑料模具v4最早大板.stl` **实测就带这个警告**。

**影响方向**：抵消使体积**偏小** → 重量偏小 → 冒口偏小（**不是**"偏大"的原因，但是数据准确性问题）。
**当前无法确定**：该真实件的实际体积误差有多大（缺独立真值复算）。

`f` 上限 50 轮（f ≤ 3.55）。实测确实会撞上限：

|---|---|

### B. 算法逻辑问题

**B-1 ★★ 体积校核用「整件铸件体积」，且与 Mc 无关**（`calcs/riser.js:109-110, 122-123`）
`Vc = 铸件净重 × 1e6 / ρ` —— **整个铸件**，不是该冒口负责的补缩区。
`effV = Vr × eff ≥ Vc × shrink`。

> 该条**已被 PHASE 28 审计记录为 P1-9「热结区域体积未用于体积校核（用整件体积）」，状态 CONFIRMED，至今未修**。
> 本次调查的**新贡献是把它量化了**（§10 P0-1）。

**B-2 ★★ 多热结时每个冒口都按整件校核**（`calcManifest.js:245-254`）
`runOne` 闭包捕获的是**同一个** `castWt`；`pickedHot.map(p => runOne(p.mc))` 逐个调用。
代码注释自认：「**V1 不做 feed-zone 分区补缩，各冒口独立校核**」。
→ N 个冒口时，总补缩能力按 **N × 整件缩量** 设计。

**B-3 缺 feed-zone 概念**
热节区域体积 `regionVolumeCm3` **已经算出来了**并写进了 `hotspots.items`，
但**没有接入体积校核**。（PHASE 27-A 起就列为 P1，未实施。）

**B-4 `f` 的语义与「模数法 1:1.1:1.2」脱钩**
`f` 名义是"安全系数"，实际是"为满足体积条件被迫放大的倍数"。实测可达 **2.10 ~ 3.55**。

**B-5 ★ 热点模数系统性偏低（中位 0.836× 解析真值）** —— 见 §9.4。
**方向与"冒口偏大"相反**（使按模数定的尺寸偏小），但它意味着
**"按模数定尺寸"这一支当前不可信**，任何在 Mc 之上再调系数的做法都建立在偏移的基准上。

## 10. 可能导致冒口偏大的因素（按**调查优先级**排序）

> 99.txt §十五 明确：**这里的 P0/P1/P2 是"调查优先级"，不是 V2.0 产品开发优先级。**

### P0 —— 已实测确认主导，且机理清楚

#### P0-1 ★★★ 体积校核以「整个铸件净重」为对象

**机理**：`needVol = (铸件净重 × 1e6 / ρ) × shrink`，与 Mc 无关。

**实测（球铁 / 圆柱形 / eff 14% / shrink 3% / Mc = 10mm）**：

| 铸件净重 | 仅模数要求 D | 体积要求 D | 实际 D | final_f | 冒口重 / 铸件净重 | 主导约束 |
|---|---|---|---|---|---|---|
| 1 kg | 66.0 | 33.7 | 66 | 1.10 | 160.3% | 模数 |
| 5 kg | 66.0 | 57.7 | 66 | 1.10 | 32.1% | 模数 |
| **10 kg** | 66.0 | 72.7 | **75** | **1.25** | 23.5% | **体积（交叉点）** |
| 20 kg | 66.0 | 91.6 | 93 | 1.55 | 22.4% | 体积 |
| 50 kg | 66.0 | 124.3 | 126 | 2.10 | 22.3% | 体积 |
| 100 kg | 66.0 | 156.6 | 159 | 2.65 | 22.4% | 体积 |
| 200 kg | 66.0 | 197.3 | 198 | 3.30 | 21.6% | 体积 |
| 500 kg | 66.0 | 267.8 | **213** | **3.55（撞顶）** | 10.8% | 体积，**未收敛** |
| 1000 kg | 66.0 | 337.5 | **213** | **3.55（撞顶）** | 5.4% | 体积，**未收敛** |

**↑ 这张表就是"冒口偏大"的核心机制。** 关键推论：

- **交叉点约在 7.5 kg（球铁/圆柱/Mc=10mm）**；超过它，**冒口尺寸与热点模数完全脱钩**，
  只由"铸件有多重"决定。
- 在体积主导区，存在一个**恒等式**：
  `冒口重量 / 铸件净重 = shrink / eff`
  （球铁+圆柱 = 3%/14% = **21.4%**；球铁+球顶柱 = 12%；灰铁+圆柱 = 14.3%；铸钢+圆柱 = 32.1%）
  —— **与铸件几何、与热点模数、与铸件大小全都无关，是一个常数。**
- 因此无论导入什么产品，只要超过交叉重量，**冒口永远占净重的 21.4%**。
  这个"不动点"行为很容易被工程师判定为"明显不合理"。

**实测真实件复现（HR4012 大板，77.56 kg，球铁，圆柱形）**：

```
热点 Mc = 11.43 mm
仅模数要求 D = 75.4 mm
体积要求   D = 143.9 mm     ← 相差 1.9 倍
实际输出：D = 144 mm, H = 144 mm
          Mr_act = 24.00 mm（= 热点模数的 2.10 倍）
          final_f = 2.10
          冒口体积 2345 cm³ → 冒口重 16.65 kg = 铸件净重的 21.5%
```

**对照（ALR2510 v1_1，7.37 kg，球铁，仍在模数主导区）**：

```
热点 Mc = 10.02 mm → D = 66 mm，final_f = 1.10，冒口重 1.58 kg = 21.4%
```

## 【当前结论】

### 目前从代码层面看，为什么冒口可能偏大？

**有明确答案，且已实测复现。核心机制不在热点算法，而在热点之后的"体积校核"一段。**

**主因（P0-1）**：`runRiser` 除模数条件外还有一条**独立的体积条件**
`Vr × eff ≥ (铸件净重 × 1e6 / ρ) × shrink`。
这条条件**以整个铸件为对象，且完全不依赖热点模数**。
只要铸件超过约 **7.5 kg**（球铁 / 圆柱形 / Mc≈10mm），体积条件就取代模数条件成为主导，
此后**冒口尺寸与热点算得准不准再无关系**，只由铸件重量决定。

在体积主导区存在恒等式 **`冒口重量 / 铸件净重 = shrink / eff`**：

- 球铁 + 圆柱形（设计中心默认）= 3% / 14% = **21.4%**
- 球铁 + 球顶圆柱 = 12%
- 灰铁 + 圆柱形 = 14.3%
- 铸钢 + 圆柱形 = 32.1%

**即：无论导入什么产品，只要够重，冒口永远是铸件净重的 21.4%（或对应常数）。**
这不是一个随几何变化的"计算结果"，而是一个**常数** —— 这最符合用户描述的"明显超出合理尺寸"。

实测复现（HR4012 真实件，77.56 kg 球铁）：
`仅模数要求 D=75.4mm` → `实际输出 D=144mm`（**1.9 倍**），
`final_f = 2.10`（即实际模数是热点模数的 **2.10 倍**，而名义安全系数只有 1.10），
冒口重 16.65 kg = 净重 21.5%。

**放大因子（P0-2）**：若用户勾选了多个热结，**每一个冒口都按"补缩整个铸件"校核**
（代码注释自认「V1 不做 feed-zone 分区补缩」）。
实测三热结全选 → 冒口总重 **50.30 kg = 铸件净重的 64.9%**。

**加重因素**：设计中心默认形状是 `cyl`（补缩效率 14%，四档中最低），
而 PHASE 78 的报告自述这一改动会使「冒口体积更大」。

### 同时必须说明的反向证据（避免 V2.0-02 走错方向）

**热点模数不是偏大，而是系统性偏小。** 用真值套件里从未被断言过的解析真值 `vaRatioTheory` 实测：
20 个模型、44 个命中热点，**检出/真值 中位 0.828**（34 个偏低、仅 2 个偏高）。
受控实验定位到根因：`configV3.js` 的 `modulusCeilRatio = 1/3`
（该参数自述"工程假设 UNKNOWN，待真实 STL 校准"）—— 换成 1/2 后中位比变为 1.031。

**因此：**
- **"冒口偏大"不能用"调小安全系数"解决** —— 模数这一支本来就是偏小的，调小它只会更偏小。
- **调 `f`（1.10）也不是主因** —— 实测中它在体积主导区被迭代到 2.10~3.55，
  把它改成 1.05 对体积主导的大件几乎不起作用。
- **真正的岔路口是"体积校核的对象与量级"**，而这是**工艺定义问题**，不是代码问题。

### 与 PHASE 28 历史审计的关系

本报告的 P0-1 与 PHASE 28 审计的 **P1-9「热结区域体积未用于体积校核（用整件体积）」**
（`docs/PHASE28_ISSUE_TRACKER.md:31`）**是同一件事**，状态为 **CONFIRMED（未修）**。
本阶段的新贡献是**第一次量化了它的量级**（交叉重量 7.5 kg、恒等式 `shrink/eff`、真实件 1.9 倍差距），
并提供了可证伪的预测。

### 目前无法确定的部分（诚实标注）

- **"合理尺寸"的基准本身未经真实工程数据验证** —— 上述 21.4% 是否"过大"，
  取决于企业实际做法，**本报告不能替企业下这个判断**。
- 若采用"铸铁净需求≈0"（Campbell 观点，项目已存档），**P0-1 的量级会大幅改变**。**该假设未决。**
- 真实件 HR4012 的体积是否被 `INCONSISTENT_WINDING` 污染，**目前无法确定**。
