# PHASE V2.0-P1-R4 · 工作台第三轮优化（146.txt）

> 基线：`docs/PHASE_V2.0-P1-R3_WORKBENCH2.md`（145.txt）

## 0. 一句话结论

上一轮把「取消**无 STL 的独立手动模式**」误读成「删除**全部**参数输入」，
把 STL 模式下必要的参数查看/输入/修改/确认/保存能力一起删了。
本轮**恢复参数窗口**（3 模块 20 个可编辑字段），同时**只保留 STL 模式**；
并修掉两个用户直接可见的缺陷：**标准视图按钮全部失效**、**点击热结自动放大**。

## 1. 两个功能缺陷：复现 → 根因 → 修复

### 1.1 §5 前后左右视图按钮无法生效

**根因（实测事件日志，非推断）**：

```
DOC:pointerdown on BUTTON.        ← pointerdown 命中了按钮
pointerdown@663,820 T
mousedown@663,820 T
DOC:click on DIV.dc-view3d-box    ← click 的目标变成了容器，不是按钮
```

`.dc-view-controls`（含 7 个视角按钮）与 `#dc_viewReset` 在 R3 被移进了 `#dc_view3dBox`
——**而那正是传给 `new OrbitControls(camera, container)` 的 domElement**。
`vendor/controls/OrbitControls.js:1000` 在 pointerdown 时执行
`scope.domElement.setPointerCapture(event.pointerId)`，此后该指针的 `pointerup` 被重定向到容器，
而 `click` 的目标 = pointerdown/pointerup 目标的**最近公共祖先** = 容器
⇒ 按钮自己的 click 处理器**永远不会被调用**。

> `v1.1.0`（HEAD `da1c822`）里这两块控件是 `#dc_view3dBox` 的**兄弟节点**，
> 所以旧版没有这个病 —— 正是 §5 所说的"工作台重构引入的影响"。

**修复**：控件移回 `#dc_view3d` 下（容器之外），保持视口浮层外观。
**验证**：CDP `Input.dispatchMouseEvent`（真实命中测试 + 真实指针捕获）逐个点击 7 个视图 +
重置视角，读 `window.__view3d.camera.position` 断言**每个视图机位都不同**、方向正确。

> ⚠ 这条断言**必须用真实鼠标输入**：`.click()` 合成事件绕过指针捕获，**测不出**该缺陷
> —— 它潜伏一整轮，正是因为既有浏览器测试只用 `.click()`。

### 1.2 §6 点击热结自动放大 / 移动相机

**根因**：`ModelView3D.selectHotspot(i, focus = true)` **默认聚焦**（相机移到热点上方、
`controls.target` 改成热点坐标、距离按模型尺寸缩放）。两处调用（3D 内 marker 拾取 `pick()`、
左栏热结列表点击）都没传第二参 ⇒ 每点一次视角就被拽走一次。

**修复**：`focus` 默认改为 `false`；`pick()` 显式传 `false`；列表点击显式传 `false`。
聚焦能力保留为**显式 opt-in**（`inspectionCenter` 的"定位到该热结"、截图脚本仍传 `true`）。
**验证**：点列表 H1 前后逐位比对 `camera.position` 与 `controls.target`，必须完全相同；
同时断言 `.on` 高亮确实生效、`controls.enabled !== false`（用户仍可主动旋转/缩放）。

### 1.3 顺带修掉的两个真缺陷（本轮实测发现）

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 返回按钮失效 | 点过任一**类别页签**后，「⤡ 返回三维工作台」点了毫无反应 | `renderResultsCenter` 用 `innerHTML` 整块重建结果区，而 `#dc_again` 的监听只在 `designCenter.renderResults` 里绑过一次 ⇒ 重建后是**没有监听的新元素**（只有中间恰好触发过重算才"偶尔"能用） | 绑定移到 `resultsCenter`（与 `[data-nav]` 同一层次，重建一次绑一次），新增 `opts.onBack` |
| 场景联动静默丢失 | 首页/顶栏「生产场景」填好的材料·造型线·铸造方法不再带进设计中心 | 145 删参数区时把 `syncFromContext()` 的**唯一调用点**一并带走（函数成了死代码） | 在 `importFile`（导入后）与 `restore`（重进视图）各补一次调用，时机与原实现一致 |

另有一处**保存按钮判定错口径**：`paramIssues()` 只看项目、不看草稿 ⇒ 用户刚把必填项
（材料大类）填上，按钮仍禁用，**根本存不下去**。现在分两个口径：
状态 chip / 主按钮看**已保存**（否则就是 §3.4 禁止的"UI 说已确认、计算仍用旧值"），
窗口内的保存按钮看**草稿**。

## 2. §3 参数窗口：字段清单与数据来源

窗口 = 顶部工具栏「⚙️ 分析条件与工艺参数」→ 浮层对话框（挂在 `.dc-body` 内，
顶部工具栏与底部状态栏始终可见可点）。三个模块，**20 个可编辑字段**。

### A · 分析条件

| 字段 | 参数路径 | 当前值来源 | 必需 | 可编辑 | 下游消费点 |
|---|---|---|---|---|---|
| 材料大类 | `material.family` | 无 STL 来源 / 无可靠默认值（或生产场景） | **是** | ✔ | 全部计算器的材料分支；带出密度与出品率区间 |
| 模型单位 | `geometry.unit` | 用户（STL 不带单位） | 是 | ✔ | 重写 `geometry.*` 全部派生量 |
| 主体壁厚 | `process.wallUsed` | STL 自动（`bodyWallOf`→`bodyRefOf` 回写） | 否 | ✔ | gating 浇注时间；无热结时 `wallHot` 基准 |
| 毛坯重量 | `geometry.blankWeightKg` | 派生（体积 × 固态密度） | **是** | ✔ | gating（G）/ yield / charge / shakeout |
| （只读）外形尺寸 / 体积 / 最大壁厚 / 净重 / 热结数量 | — | STL 自动 | — | ✘ | 纯展示 |

### B · 冒口设计

| 字段 | 参数路径 | 来源 | 可编辑 | 下游 |
|---|---|---|---|---|
| 热节模数 Mc | `process.mcHotspot` | STL 自动（最大热结 Mc） | ✔ | riser 的 Mc（门禁读它） |
| 热结选择 | `process.hsPick` | 用户 | ✔ | riser 多热结分别设计 |
| 冒口形状 | `process.riserShape` | 默认 `cyl` | ✔ | riser（RISER_SHAPES 4 种） |
| 冒口高度 RH | `process.riserHeight` | riser 结果回写 | ✔ | gating 的 Hp 方案 A（C = ph + rh） |

### C · 浇注系统（含生产条件）

| 字段 | 参数路径 | 来源 | 可编辑 | 下游 |
|---|---|---|---|---|
| 浇注位置 | `process.pourPos` | 默认顶注 | ✔ | gating P 值 |
| Ho / ph | `process.Ho` / `process.ph` | 默认 150 / 100 | ✔ | gating C = ph + rh |
| 浇注系统比例 | `process.ratioKey` | 空 = 自动推荐 | ✔ | gating S:R:G |
| 内浇道厚度 / 个数 | `process.gateThk` / `production.ingateN` | 默认推荐 | ✔ | gating（改厚度 → 长度重算） |
| 横浇道厚度 / 条数 | `process.runnerThk` / `production.runnerN` | 默认 25 / 2 | ✔ | gating 面积比与阻流位置 |
| 排气孔直径 | `process.ventD` | 默认 ⌀3 | ✔ | gating 排气面积与孔数 |
| 型腔数 | `production.cavities` | 默认 1 | ✔ | gating 的 W_c |
| 预估出品率 | `material.yieldSug` | 材料默认 | ✔ | gating 的 yr |
| 造型线 | `production.line` | 默认不指定 | ✔ | yield 参考区间 |
| 铸造方法 | `production.method` | 默认砂型机器造型 | ✔ | machining 等级 |

**逐字段核实方法**：以 `calcs/calcManifest.js` 各 `calculate` 的实际读取点为唯一依据
（清单见本文件 §2 各表"下游"列），**不是**按旧版 UI 有什么就恢复什么。
只读项只有纯几何量（由可靠数据链自动确定、没有必要人工覆盖）。

### 2.1 保存语义（§3.4 逐条落地）

| 要求 | 实现 |
|---|---|
| 保存后更新有效参数状态 | `proj.set()` 落盘 → `syncFlowChrome()` 重算状态 chip |
| 只有有效参数才能用于分析 | `runAnalysis` 开头 `paramIssues()`，缺则 `blocked()` **并自动打开窗口定位到缺的那一项** |
| 参数影响结果后旧结果标过期 | `markChangedStale(paths)`：按 `PARAM_OWNERS` 精确标记；有参数无登记归属（如单位）时**保守地全部标记** |
| 重新分析用当前已确认参数 | 计算器一律从 `CastingProject` 取值，无第二条取值路径 |
| 取消/关闭不静默丢失 | `requestCloseParamDlg()`：草稿非空 → `confirm` 明确询问 |
| 状态与主工作台同步 | 状态 chip / 主按钮 / 左栏共用同一 `computeState()` |
| 不出现"显示已确认、实际用旧值" | 草稿**只活**在 `state.paramDraft`，窗口内输入一律不写项目（有断言钉住） |

**草稿不是第二套状态系统**：`state.paramDraft` 只是一个 `{path: value}` 的局部对象，
不存在于持久化、不参与任何计算，窗口一关即弃。

## 3. §4 左侧栏：两个主体区域

```
① 分析结果概览（模型信息枢纽；未分析时不显示伪造结果）
② 热结列表（点击 = 只选择/高亮；勾选「参与冒口」写项目并触发重算）
```

删除：独立的「设计步骤」内容块（§4.1）、左栏「分析条件」表单（§4.2）。
流程引导改由**顶部唯一主按钮 + 底部状态 chip** 承担，按钮文案与动作由真实状态决定：

| 状态 | 主按钮 |
|---|---|
| A 未导入 STL | 📥 选择 STL 文件 |
| B 已导入 · 参数待确认 | ⚙️ 确认工艺参数（打开窗口并定位缺失项） |
| B 已导入 · 参数有效 | ▶ 开始工艺分析 |
| C 分析中 | ⏳ 正在分析…（禁用） |
| D 分析完成 | 📋 查看分析结果（结果视图内 = 🔁 重新分析） |
| E 分析失败 / 条件不足 | 🔁 重新分析 / ⚙️ 修正工艺参数 |

> 「参数是否满足」只看 `paramIssues()`（逐条对应真实计算依赖），**不看任何 UI 标记**。

## 5. §8 结果页：核心结论 + 详细信息

```
类别标题 → 核心结论卡（每张只回答一个主要问题）→ 关键数值与单位 → 「🔎 详细信息」折叠
```

* **删除顶部「本页结论速览」**（§8.3：同一批字段在速览/主卡/表格里展示了三遍）。
  顶部只留**类别导航**（三页签）。
* 冒口设计：核心卡 = `冒口规格`（引擎 `RISER_SHAPES[k].label()` 的标准写法，含 R / 边长）
  / `Mr_actual`（带 ≥ 目标模数判定）/ `可补缩量 = Vr × 补缩效率` —— **三种概念明确分开**；
  详细信息里给出 D/H/R、Vr、eff、Mr_target、冒口颈等完整数值。
* 浇注系统：核心卡 = 浇注重量 G / 浇注时间 t / 阻流截面 A / 内浇口流速（带 R7 判定）；
  可编辑的浇道参数**不进折叠区**（它们是设计入口，不是"详细信息"）；
  校核、建议、完整计算过程折进详细信息。
* 铸件工艺性：核心卡取各详卡的**第一条实质结论**（原样取自已算出的行，不编造区间）；
  其余解释行、备注、关联工艺参数、材料提示折进详细信息。

⚠ 详细信息里出现的**每一个数都来自现有计算结果对象**，UI 层不做任何工程计算，
不编造数据来源 / 公式 / 适用范围。
