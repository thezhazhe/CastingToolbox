## 2. 新旧算法的具体差异

| | 旧（V2.0-21 及以前） | 新（V2.0-22） |
|---|---|---|
| 尺寸来源 | `for (f = 1.10; f ≤ 3.55; f += 0.05)` 迭代到"模数 **且** 体积"双通过 | `Mr_target = Mc × 1.2` 一次反求 |
| 模数判据 | `Mr_act ≥ Mr_need × 0.99`（1% 松弛） | `Mr_act ≥ Mr_target`（**严格下限**） |
| 体积约束角色 | **决定尺寸**（不通过就推进 f） | **只做诊断**，不参与任何尺寸计算 |
| 未收敛 | `bind='limit'`（撞 f 上限）可能发生 | 不存在（无迭代） |
| H 的取整规则 | **两条**：主路径 `round(raw×hd)`、升档路径 `round(d×hd)`，实测 ΔH∈{−1,0,+1} | **一条**：`H = round(D×hd)`（与 `riserDreq.js` 同口径） |
| 最小性 | 只上探（混合口径下 **440/14720 点虚增 1mm**） | 上探 + **下探**（0 点虚增） |
| `bind` | `start`/`modulus`/`volume`/`both`/`limit` | 恒 `'modulus'` |
| `converged` | 两条同时通过 | 尺寸达到目标模数（构造保证） |
| `final_f` | 迭代停止时的 f | 恒 `1.2`（兼容字段） |
| `Mr_need` | 末次迭代要求 | **`Mr_target` 的兼容别名** |
| `dModOnly` | 硬编码 `Mc × 1.10` 的连续解取整 | 同一个 `Mr_target` 的连续解取整（不再各写一份系数） |

### 2.1 一处实现缺陷的顺带修复（如实记录）

改用目标模数后，尺寸搜索只剩"由 `Mr` 求整数 D"这一步。实测发现旧口径**不是最小解**：

```
4 形状 × hd∈{0.5,0.6,0.8,1,1.2,1.5,2,3} × Mc∈[0.3,60] 步长 0.13 = 14,720 点
混用两条 H 口径时：D 非最小档 = 440 点（3%，集中在 hd=0.5 一带）
统一为 H = round(D×hd) + 下探后：非最小档 = 0 点，Mr_act ≥ Mr_target 违反 = 0 点
```

该性质是 **V2.0-16 已裁决过的**（"D = 最小可行整数"），故本阶段保持，不是新增要求。

## 3. 球铁案例对比（138.txt §八.3 指定）

**球铁 / 铸件净重 77.56 kg / Mc = 11.43 mm / 圆柱形 / hd = 1.0**

| 项 | 旧 | 新 |
|---|---|---|
| 目标模数 `Mr_target` | —（无此字段） | **13.716 mm** |
| 实际模数 `Mr_actual` | 24.00 mm | **13.833 mm** |
| 实际模数比 `Mr_act / Mc` | 2.10 | **1.2103** |
| 直径 `D` | **⌀144 mm** | **⌀83 mm** |
| 高度 `H` | 144 mm | **83 mm** |
| 冒口体积 `Vr` | 2345.2 cm³ | **449.1 cm³** |
| `bind` | `volume` | `modulus` |
| `converged` | true | true |
| `final_f` | 2.10 | 1.2 |
| `dModOnly` | 75 mm | 82 mm（连续解取整，升档前） |
| 旧体积诊断 `volOk` | true（判据） | **false（仅诊断）** |
| 冒口颈 `d_neck` | ⌀46 mm | ⌀46 mm（**未变**，仍由 Mc 决定） |

**这个尺寸是怎么来的**：`Mr_target = 11.43 × 1.2 = 13.716` → 连续解 `6 × Mr = 82.296` →
取整 82 → `M(82,82) = 13.667 < 13.716`（差 0.05）→ **升一档** ⌀83 → `M(83,83) = 13.833 ≥ 13.716` ✓

**旧体积诊断现在说什么**（页面上以"非设计判据"呈现）：
按整件净重折算的收缩需求 327.72 cm³，本冒口有效补缩量 62.87 cm³。
该口径假设**整个铸件的收缩量由这一个冒口单独承担**，尚无工程依据。

## 11. 声明（138.txt §八.11）

**本阶段完成的是"模数设计规则与程序行为的一致性改动"，不是实际补缩能力的生产验证。**
`Mr_actual ≥ Mr_target` 只说明"尺寸达到了自定的目标模数"，**不说明真实铸件不会缩孔**。
原因：① 目标模数规则本身未经生产验证；② `Mc` 的来源（STL 热节识别）未经生产验证；
③ 旧体积模型被降级是**因为缺乏依据**，不是因为它被证明错误。
