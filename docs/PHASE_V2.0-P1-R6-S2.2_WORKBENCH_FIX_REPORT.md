## 3. 冒口形状反馈：修复前后

### 3.1 修复前（S2.1 诊断实测）

- ③ B 改形状后，下拉值已变，但「当前形状公式 / 补缩效率」仍显示旧形状，直到点保存重渲染。
- 草稿态没有“尚未保存”的提示。
- 结果页把“为什么换形状不改 D/H”的解释放在「详细信息」折叠区内，默认看不到。
- 默认可见的核心卡是「规格 / Mr_actual / 可补缩量」，真正随形状变化的 `Vr / 补缩效率` 不够显眼。

### 3.2 修复后

1. **面板即时刷新**：`[data-pf]` 处理器在形状字段变化时就地重写 `[data-shape-note]`，不重渲染整面板（焦点、滚动位置不动）。
2. **文案来源唯一**：公式与效率仍来自 `RISER_SHAPES` / `RISER_EFF`（冻结模块），没有在 UI 复制第二份公式表。
3. **草稿态正确**：帮助按 `dlgValue()` 的草稿值渲染；当草稿 ≠ 已保存形状时，额外显示“草稿尚未保存：结果仍按已保存的「X」计算，点「保存并分析」后才按「Y」更新”。
4. **切换不丢**：B/C 页签、②/③ 步骤来回切换后，帮助仍按草稿形状显示（真实浏览器断言）。
5. **结果页默认可见**：`shapeDiffNote` 移出 `<details>`，紧跟核心卡；写明当前 `hd = H/D` 的实际值，并限定“只适用于当前模型与当前 hd 口径，不代表不同形状工程等效”。
6. **真正变化的量可见**：新增第四张核心卡「冒口体积 Vr」，状态行同时给出补缩效率百分比。
7. **结果页内联下拉**：切换时先就地刷新公式说明，再写项目、标过期、防抖重算。

### 3.3 实测（`cube50.stl` / 球铁 / NO_HOTSPOT / Mc=25）

四形状 `D/H/Mr_target/Mr_act/冒口颈` 逐位相同；`Vr/eff` 不同 —— 与 S2.1 诊断一致，属于 `hd=1 ⇒ M≡D/6` 的引擎事实，**不是缺陷**。S2.2 没有修改任何计算。

## 4. 热结选择与草稿语义

### 4.1 修复前

- 左栏热结列表的「参与冒口」勾选**立即写项目并重算**；③ B 的勾选写草稿。同一参数两套保存语义。
- ③ B 连续勾选多个热结时，后一次勾选以**项目里的旧数组**为基重算草稿 ⇒ 前一次勾选被静默丢掉（本轮实测复现：H1+H2 一起勾，保存后只剩 H2）。

### 4.2 修复后

| 入口 | 语义 |
|---|---|
| 三维视图 / 左栏热结行 | **只查看/定位**：点击选中并高亮 3D，相机不动，不写任何参数 |
| 左栏「参与冒口」徽标 | **只读状态**：显示当前已保存的选择，不提供勾选入口 |
| ③ → B 冒口设计 | **唯一编辑入口**：勾选、取消、逐热结 Mc 都写同一份草稿 `process.hsPick`；保存并分析后落盘 |

- 草稿的基值改为 `currentPicks()`：优先读当前草稿，没有再读项目。连续勾选/逐项改 Mc 不再互相覆盖。
- 取消/关闭：同一套确认逻辑；确认后草稿丢弃、项目不变、面板关闭。
- B/C 页签切换与重渲染：草稿保留（真实浏览器断言）。

## 5. RH（冒口高度）关联展示

### 5.1 修改前

`process.riserHeight` 在 ③ B 是一个普通数字输入框（可写 `USER_OVERRIDE`），但它的第一性来源是冒口计算输出（`CALC_RESULT`）。这与“它是关联值”的事实不符。

### 5.2 修改后

- **B 不再提供 RH 输入框**；RH 移到 C 浇注系统顶部，作为**只读关联值**展示。
- 显示：数值 + 来源徽标（`来自冒口计算` / `用户覆盖（既有值）` / `尚未回写`）。
- 说明：该值参与 `C = ph + rh` 与平均静压头 `Hp`，不是独立的浇注输入。
- 提供「→ 去冒口设计」入口：`openParamAt('process.riserShape')`，直接定位到真正决定 RH 的冒口设计字段。
- 继续使用唯一的 `process.riserHeight`，没有建立第二份存储；没有新增 `USER_OVERRIDE` 写入逻辑。
- 既有用户覆盖如实显示、不静默清除；旧存档中“非 0 但无计算来源标记”的值按实际值说明（不会误写成“按 0 计算”）。
- 实测：浇注结果 `runner.result.rh` 与项目中的 RH 逐位相同；切形状不改变 RH（hd=1）。

## 7. 「保存并分析」状态语义

| 状态 | 实际行为（S2.2） |
|---|---|
| 首次分析 | 保存成功后**直接触发**一次分析（旧实现只保存，要用户再点主按钮） |
| 必填项缺失 | 页脚保存按钮禁用；缺什么由 `paramIssues(true)` 判定；点击保存不会绕过门禁 |
| 参数未保存 | 页脚显示 `有 n 项修改尚未保存`；主按钮会引导回未保存字段 |
| 保存成功、分析开始 | Toast 只说“已保存 N 项”；分析成功/失败另有独立结局提示 |
| 保存失败 | 显式提示；**不清草稿、不触发分析**；提示可能已部分写入（无法自动回滚） |
| 分析失败（门禁） | `lastRun={ok:false}`；旧结果保留但标记过期；横幅给原因与重算入口 |
| 分析失败（计算异常/空结果） | 不把不完整结果当成当前结果；**回滚本轮已写回的 `risers.items / process.riserHeight / runner.result / yield.result`**；旧结果标记过期；返回 `false`；防抖链不再提示“已重新计算” |
| 分析成功 | 清除过期标记；`lastRun={ok:true}`；结果与当前参数一致 |
| 分析中重复点击 | `state.busy` 守卫；手动分析会取消尚未触发的 600ms 防抖；同步链路不会留下“分析中”卡死 |
| 结果失效 | 保存与结果页内联改动都会**立即**标记过期（不等防抖重算） |
| 失败后查看旧结果 | 旧结果仍可打开，但状态 chip / 横幅明确写“分析未完成 + 旧结果已过期”，不冒充最新 |

> “保存失败”分支在正常 UI 中无法构造（`proj.set` 是同步内存写入）；本轮加了兜底与明确提示，但未做注入式自动化测试。
