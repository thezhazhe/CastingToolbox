## 5. 布局推荐：方案 D

（你提的方案 C 的三处精确化）

```
┌──────────┬──────────────────────────────────────────────┬────────────┐
│ 应用导航  │  [① 导入模型] → [② 分析条件] → [③ 冒口] →    │  按需面板   │
│  236px   │  [④ 浇注系统] → [⑤ 查看结果]      ← 流程条    │  360px     │
│          ├──────────────────────────────────────────────┤  （默认收起）│
│          │                                              │            │
│          │              三 维 模 型                       │ 模型信息/   │
│          │                                              │ 分析条件/   │
│          │                                              │ 冒口/浇注   │
│          ├──────────────────────────────────────────────┤            │
│          │ 单位 · 模型 · 热结 · ✓ 结果与当前参数一致        │ [保存并重算]│
└──────────┴──────────────────────────────────────────────┴────────────┘
```

三处精确化，每条都有理由：

1. **面板放右边**，不放左边。应用导航已经占了左边，再来一个左栏就是两根左柱子，视线每次要横跨两栏才回到模型。右边还有个好处：符合 CAD/CAE 工具的习惯（属性面板在右）。
2. **面板默认收起**。收起时三维拿满 1106px（比现在 **+39%**）；展开时才付出宽度，而展开的时候你正在填参数，不需要转模型。
3. **面板内容跟着流程条走，参数不再用弹窗**。一处解决三个问题：长表单读不完（拆成 4 步，最长的一步 9 个字段）、反复开关弹窗、新用户不知道下一步该干嘛。

**一个便宜可以捡**：现在 **<960px 时左栏本来就已经是一个抽屉了**（`.dc-rail` 平移 + `.rail-open` 展开）。方案 D 在手机上跟它是同一套机制，改一改就行。

## 6. 从导入到看结果的流程

| 步 | 你看到什么 | 你要做什么 | 系统自动做什么 |
|---|---|---|---|
| **① 导入** | 中央一个导入区，**没有左栏也没有面板**，页面只有这一件事 | 拖文件 / 点选 | 解析 → 网格校验 → 距离场 → 热结分析，进度条按 9 段真实阶段走 |
| **② 模型信息** | 三维出现（**不自动进下一步**）；面板自动展开：5 个关键数 + 热结列表 + 折叠的「模型诊断」 | 转模型；点热结（**只选中高亮，相机不动**）；勾选参与冒口的热结 | 把 STL 结果写进项目并标来源"STL 自动" |
| **③ 分析条件** | 面板切到分析条件，**三维还在**（能一边看模型一边填） | 选材料大类（**必填**）+ 单位（如果 STL 不是按 mm 建模） | 材料选定后带出密度、收缩率、出品率区间、加工余量等级，**并用提示条告诉你"这些值会立即随动"** |
| **④ 冒口设计** | 面板切到冒口：Mc（带来源徽章 + 可展开的"Mc 怎么估"）→ 热结勾选 → 形状（带公式）→ 冒口高度 | 确认或改 Mc；换形状 | Mc 默认取 STL 最大热结；RH 在算完后回写 |
| **⑤ 浇注系统** | 面板切到浇注：浇注位置（**下面紧贴示意图**）→ Ho / ph（**图的尺寸线正好解释这两个量**）→ 比例（7 条适用条件 + ⓘ）→ 内浇道/横浇道/排气 → 收起的「生产条件」 | 一般不用改，但**要一眼看出"这是默认值、可以改"** | 比例留空 = 按材料与重量自动推荐 |
| **⑥ 查必填和状态** | 流程条状态点 + 底部状态条 + 面板底部保存条 | — | 面板内改的是**草稿**（不写项目、不参与计算）；点保存才落盘 → 精确标记受影响的模块过期 → 600ms 防抖重算 |
| **⑦ 开始分析** | 按钮变「⏳ 正在分析…」 | 点一下 | 按固定顺序跑：线收缩率 → 加工余量 → 冒口 → 浇注 → 出品率。**跑完不自动跳结果页**（这是 146 的既定决定，保留），改成按钮亮 6 秒 + 流程条 ⑤ 变可点 |
| **⑧ 看结果** | 独立结果页（三维不销毁，还在后台） | 切类别、展开详细信息、快速调整 | — |
| **⑨ 回来改、重算** | 「⤡ 返回三维工作台」**只切视图，不清空任何东西** | 改参数 | 旧结果**不隐藏不清空**，只出现过期横幅 + 重新分析按钮 |
| **⑩ 失败/条件不足** | 三类失败给三条不同的出路 | — | 参数缺失→逐条列出缺什么、为什么要它、一键跳过去；几何不可信→说明"网格本身不可信，人工填 Mc 也替代不了这些输入"并指出具体是哪条网格问题；算法没给可靠结果→说明是哪一种（无热结/置信度不足/采样欠解析） |

> **一个原则**：不要逼用户重复确认已经可靠确定的量。

### A · 分析条件

```
② 分析条件                            材料 / 单位 / 模型与重量
材料大类 [必填] [用户输入]  [ 请选择材料大类            ▾ ]
   STL 只能给出几何，识别不出材料。未指定时无法计算密度/重量，分析会被阻止。
   ▸ 展开：各材料族工艺要点（复用 data/scenarios.js，5 族现成）

 ┌ 📎 当前联动：密度 固7.0/液7.0 g/cm³ · 出品率参考 65~85% · 加工余量等级 RMAG B
 │    —— 改上面的材料/造型线/铸造方法，这些值会立即随动        ← 恢复
 └──────────────────────────────────────────────────────

模型单位 [用户输入]   [ mm                                    ▾ ]
   STL 文件不带单位。若不是按 mm 建模，在这里改——保存后尺寸/重量/工艺结果按新单位重算。

主体壁厚（浇注时间用） [STL 自动]   [ 68 ] mm
   自动 = STL 可信主体壁厚（V3 采样链）；也可按工艺判断改为代表壁厚。

   自动 = 净重（体积 × 固态密度）；有加工余量时按实际毛坯上调。浇注重量/出品率/加料均据此。

▸ 模型信息（只读 · 来自 STL）     ← 与面板①同源，不再出现第二处
   外形尺寸 400×200×68 mm ｜ 体积 1229.2 cm³ ｜ 最大壁厚 66.7 mm
   ｜ 净重 8.6 kg ｜ 热结数量 1 个
```

### B · 冒口设计

```
③ 冒口设计                            热节模数 / 热结 / 形状 / 高度
热节模数 Mc（冒口设计依据） [STL 自动]   [ 10.3 ] mm  [↺]
   自动 = STL 检出的最大热结模数（热结列表 H1）。检出多个热结时可分别勾选、分别设计。
   ▸ 展开「Mc 怎么估？」—— 复用独立计算器的四种方式：
       · 直接输入 Mc（被补缩热节处的 V/散热面积）
       · 输入热节圆直径 d（Mc = d/2）
       · 输入壁厚 t（板状 Mc = t/2）
       · 输入热节处 V 和 A
       通俗版：若不知热节，用壁厚估算即可（板状热节 Mc ≈ 壁厚/2）。

   ⚠️ 走兜底路径时**必须显式提示**（不得静默）：
      未检测到可靠热点，本次冒口 Mc 采用壁厚/结构参考值（主体壁厚 ÷ 2）进行初步估算
      —— 不是 STL 识别出的热点，建议结合工艺经验复核。

热结选择（多热结分别设计）
   ┌ ☐ H1 · Mc 10.3 mm · 区域 604.3 cm³ · 置信度 95% ┐   ← 行内可加 [✎ 改 Mc]
   └────────────────────────────────────────────────┘
   当前为自动模式：按主热结 H1 设计冒口。勾选热结可为选中的每一个分别设计冒口。

冒口形状 [系统默认]   [ 圆柱形                                ▾ ]
   四种形状的模数式在 hd = H/D = 1 口径下均化简为 M = D/6 ⇒ 换形状不改 D/H，
   改变的是体积与补缩效率。
   当前形状公式：M = D×H / (2D+4H)（《铸造工艺学》标准公式）

冒口高度 RH（冒口设计后自动回写，可改） [系统默认]   [ 未填 ] mm
   浇注系统按 Hp 方案 A 读取该值（C = ph + rh）。冒口重算会回写；用户改过则不再覆盖。
```

## 10. 不能碰的东西

### 10.1 三条技术红线（重构最容易再踩）

1. **视口上的浮层按钮不能放进 `#dc_view3dBox`**。它是三维控件（OrbitControls）的容器，按下时会捕获指针，按钮的 click 永远收不到——146 轮"标准视图全部失效"就是这个原因。而且 **`.click()` 这种模拟点击测不出来，必须用真实鼠标事件**。
2. **`paramIssues()` 的两个口径不能合并**：状态条/主按钮看"已保存"，保存按钮看"草稿"。混了就会出现"界面说已确认、计算还在用旧值"。
3. **`[hidden]` 会被 `.btn`/`.chip` 这类样式顶掉**，新组件要么挂在 `.dc-ws` 下，要么自己加守卫。

### 10.2 要原样保留的

固定视口（页面不滚，只允许面板/结果/详细信息内部滚动）· 三维 7 个标准视图 + 重置 · 热结点击只选中不改相机 · ResizeObserver 与渲染生命周期 · 结果页返回工作台只切视图不清结果 · 参数草稿→保存→标过期→重算 · 明暗主题 · 6 项快速调整 · 生成报告 / 打开独立计算器。

### 10.3 兼容要求

* **主题**：新组件只用现有 CSS 变量，不新增颜色常量。
* **响应式**：≥1440 面板 360px 双列 ｜ 1180~1440 面板 340px 单列 ｜ 960~1180 面板 320px、流程条只留序号+状态点 ｜ **<960 面板变全宽覆盖层**（复用现有抽屉机制）｜ <768 流程条横向滚动、触控目标 ≥28px。**不得用缩小字号或 `overflow:hidden` 解决排版**。
* **i18n**：中文原文即 key，新文案逐条补英文（约 60~80 条，其中不少是把已译好的旧词条接回来）。⚠ `campbellGatingView.js` / `verticalGatingView.js` **完全没接 i18n**，指南若要引用它们的工程原则文字，得先补翻译。
* **数据状态**：7 态来源（STL 自动/派生/用户输入/用户修改/生产场景/系统默认/计算结果）语义一条都不能弱化——**绝不把默认值伪装成 STL 值**、**绝不猜材料**、"已保存"与"草稿"不混用、参数变更必须让受影响的结果显式标过期。
