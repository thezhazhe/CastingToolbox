### 1.4 ★★ 裁决依据：D−1 到底为什么不行（本阶段新增的证据）

V2.0-13/14 只证明了"修复后两条都通过"，**没有证明"D−1 不通过"**。
本阶段补上这一半 —— 没有它，"这两个案例在边界上"就只是一句断言。

| 案例 | `D−1` 处的 `Mr_act` | 阈值 `0.99·Mr_need` | `modOk` | `D−1` 处的 `effV` | 阈值 `needVol` | `volOk` |
|---|---|---|---|---|---|---|
| A1 `mc=1.24 cyl` | 4.333333 | 4.357980 | **false**（−0.566%） | 1932.5821 | 2112.6761 | **false**（−8.524%） |
| A2 `mc=1.10 sphere_head` | 3.833333 | 3.865950 | **false**（−0.844%） | 1990.8207 | 2112.6761 | **false**（−5.768%） |

**两条在 `D−1` 处都是"模数与体积同时不过"。** 且 `D−1` 的复算值与本阶段从 CSV 实读的修复前值
**逐位吻合**（`Mr_act` 误差 ≤1e-9、`effV` 误差 ≤1e-6）—— 即：**修复前的 26 / 23 正是"D−1 那一档"**。

**再进一步：`D` 是不是"同时满足两条的最小整数直径"？**（从 D=1 向上扫，H 按生产规则取整）

```
A1：最小可行整数 = 27，生产给出 27  ✓
A2：最小可行整数 = 24，生产给出 24  ✓
```

**⇒ 当前 D 就是最小可行整数，`D−1` 不是可行解。**

### 1.5 裁决结果

> **裁决：接受这两个案例的 +1 mm。**
>
> **理由**：`D` 是同时满足模数与体积两条约束的**最小整数直径**，`D−1` 在两条上**都不过**。
> 因而是"修复前少 1 mm 导致两条都差一点"被 C′ 的取整补偿纠正，**不是把尺寸放松了**。
> 这是**严格改善**：从"未收敛且两条都不过"变为"收敛且两条都过"。

**裁决的适用边界（127.txt §三 明令必须写明）：**

| ❌ 这不代表 | 依据 |
|---|---|
| 这些尺寸已通过**真实铸件验证** | 本阶段**没有任何真实铸件数据**（模板 0 条记录，§4）。裁决对象是**算法行为**，不是铸造结果 |
| 已证明**实际补缩能力** | `modOk`/`volOk` 是算法内部约束。`RISER_EFF`（14%/20%/25%/35%）是否对应真实补缩效率，**代码里没有任何实测标定** |
| 这两条是"安全"或"宽裕"的 | 体积裕度仅 **+2.442%**（A1）/ **+7.065%**（A2）—— **薄裕度**，见 §1.6 |
| `Mc=1.24` / `Mc=1.10` 附近都可靠 | 裁决只针对这**两个具体点**；邻近 `Mc` 的行为见 V2.0-14 §2（非单调残留） |

**性质重申**：这是对**现有算法行为**的裁决（"这个数值结果是算法自洽的"），
**不是对工程结果的裁决**（"这个冒口真能补缩"）。两者不可互换。

### 1.6 附带记录：两条的裕度都很薄

| 案例 | 模数裕度 | 体积裕度 |
|---|---|---|
| A1 | `4.5 / 4.357980 − 1 = +3.259%` | `2164.2589 / 2112.6761 − 1 = +2.442%` |
| A2 | `4.0 / 3.865950 − 1 = +3.467%` | `2261.9467 / 2112.6761 − 1 = +7.065%` |

**"通过"是刚好过线**。这与 V2.0-14 §4「limit 的缺口中位数 0.132（差一个数量级）」是同一枚硬币的两面：
**边界附近，D 改 1 mm 就能翻转约束状态** —— 这也是 `dd` 类取整问题的敏感带。
**不得据此认为这两条是"有余量的设计"。** 该裕度已写进测试断言（`V2.0-16-A4`，锁定 0%~10% 区间）。

## §2 任务 A 附：对 V2.0-14 报告一处错误的更正

**发现于本阶段的反事实复核。** 按 127.txt §二.11「发现问题时先报告证据」，不擅自扩大修改范围 ——
**本文只记录更正，V2.0-14 报告原文未改动**（历史报告不改写）。

### 2.1 原文

`docs/PHASE_V2.0-14_RISER_AUDIT.md` §3.1 末：

> **独立复核**【实测·脚本】：`M(27,27) = 4.500000 ≥ 0.99 × 4.401999… = 4.357980` ✓；
> `M(26,26) = 4.333333` **也满足** ⇒ D 不是最小可行整数（§2.11 的既有松弛）。

§3.2 末：

> **独立复核**：`M(24,24) = 4.000000 ≥ 3.865950` ✓；`M(23,23) = 3.833333` 也满足 ⇒ 同 §3.1。

### 2.2 错在哪

阈值本身写对了（`4.357980` / `3.865950`），但**结论下反了**：

```
0.99 × 4.402 = 4.357980   vs   M(26,26) = 4.333333   ⇒ 4.333333 < 4.357980  ⇒ **不满足**
0.99 × 3.905 = 3.865950   vs   M(23,23) = 3.833333   ⇒ 3.833333 < 3.865950  ⇒ **不满足**
```

**"`M(26,26)` 也满足"是错的** —— 它恰是修复前 `modOk=false` 的那一档（基线 CSV 同行为 `modOk=false`，
两者互相印证）。**⇒ D=27 / D=24 就是最小可行整数，这两个案例上不存在"取整松弛"。**

### 2.3 影响范围（重要：**只影响这一处附注，不影响 §2.11 的结论**）

| 条目 | 是否受影响 |
|---|---|
| V2.0-14 §3.1/§3.2 的**主表**（修复前后逐字段对照） | ❌ 不受影响 —— 数据全部正确 |
| V2.0-14 §3.3「严格改善」的定性 | ❌ 不受影响 |
| **V2.0-14 §2.11**（收敛点 14,316 个中 3,926 个可再小 1 档） | ❌ **不受影响** —— 那是**另一个总体**的独立测量，本阶段复算未推翻 |
| V2.0-14 §3.1/§3.2 末**把 §2.11 的结论附加到这两个案例上** | ✅ **错误，予以更正**。§2.11 说的是"总体中有 27.4% 的点可再小 1 档"，**与这两个边界案例无关** |

**结论**：一处**错误引用**，非数据错误。V2.0-14 关于 `limit` 根因、`f_req ∝ 1/Mc`、
非单调残留等主要结论**均未动摇**。
**本阶段已用测试钉住正确结论**（`V2.0-16-A3`：`D` 必须等于最小可行整数 —— 若将来有人"修"回

### 5.1 当前体积约束的完整公式（127.txt §五.1/§五.2/§五.3）【源码】

逐项对照 `calcs/riser.js`，并用生产返回值验证：

| 量 | 公式 | 位置 | 单位 | 验证 |
|---|---|---|---|---|
| `Vc` | `cw × 1e6 / rhoUsed` | `riser.js:190` | **mm³** | ✅ 实测 `77.56×1e6/7.1 = 10923943.662` |
| `needVol` | `Vc × md.shrink` | `:191` | mm³ | ✅ `= 327718.310` |
| `eff` | `RISER_EFF[sd.effKey] / 100` | `:93` | 无量纲 | ✅ cyl ⇒ `14/100 = 0.14` |
| `Vr` | `sd.V(D,H)` | `:133` | mm³ | ✅ |
| `effV` | `Vr × eff` | `:134` | mm³ | ✅ |
| `volOk` | `cw > 0 ⇒ effV ≥ needVol`；`cw = 0 ⇒` 恒 `true` | `:138-141` | 布尔 | ✅ |

> **`cw` 的单位是 kg，`rho` 是 g/cm³，`× 1e6` 是 kg→mm³ 的换算**（`1 kg / (1 g/cm³) = 1e6 mm³`）。
> `shrink` 是**体收缩率**（球铁 0.03），无量纲。

### 5.2 `D_req` 的推导过程（127.txt §五.4）【解析】

```
目标：求使 effV ≥ needVol 的最小直径 D_req
  effV = Vr(D,H) × eff
  H    = D × hd                    （hd = H/D 的定义）
⇒ 冒口体积是 D 的三次齐次式： Vr = k(形状, hd) × D³
⇒ eff × k × D³ ≥ needVol   ⟺   D ≥ ∛(needVol / (eff × k)) =: D_req
```

**各形状的 `k`（`Vr = k·D³`）—— 已用公开 `sd.V` 在 4 形状 × 5 hd × 5 直径上验证（相对偏差 ≤3e-16）：**

| 形状 | `k` | 备注 |
|---|---|---|
| `cyl` 圆柱形 | `π·hd/4` | |
| `square` 正方柱 | `hd` | |
| `sphere` 球形 | `π/6` | **`H` 恒 `= D`，与 `hd` 无关**（`riser.js:117`）|
| `sphere_head` 球顶圆柱 | `π(3·hd − 0.5)/12` | 仅 **`hd ≥ 0.5`**；`hd < 0.5` 退化为半球 `k = π/12` |

### 5.3 已知夹具 143.91 mm 的来历（127.txt §五.5）【解析 + 实测】

```
夹具：cyl, hd=1, 球铁(rho=7.1, shrink=0.03), cw=77.56 kg, eff=14%
  Vc      = 77.56 × 1e6 / 7.1 = 10923943.662 mm³
  needVol = 10923943.662 × 0.03 = 327718.310 mm³
  k       = π × 1 / 4 = 0.785398163
  D_req   = ∛(327718.310 / (0.14 × 0.785398163)) = 143.9111 mm   ✅ 复算 143.91
```

**独立交叉验证**【实测·脚本】：用生产的 `eff` / `needVol` 扫 `effV(D,D) ≥ needVol` 的翻转点，
得 **143.9120**，与解析式 **143.9111** 相差 **9e-4 mm**（步长精度内）✓。

### 5.4 公式成立所依赖的假设（127.txt §五.6）

| # | 假设 | 是否在代码中成立 |
|---|---|---|
| 1 | `H = D × hd` 是**精确**关系 | ❌ **不成立** —— 生产用 `H = round(D·hd)`（`riser.js:115`）。`D_req` 忽略了这层取整 |
| 2 | `Vr ∝ D³`（三次齐次） | ✅ 成立（§5.2 已验）|
| 3 | 冒口内部体积**全部**计入 `Vr`（无缩孔损失） | ⚠️ 是模型约定；`RISER_EFF` 承担了"折扣"角色 |
| 4 | 补缩需求 = 铸件总体积 × **体收缩率** | ⚠️ **模型简化**。实际补缩量与热节位置、凝固顺序相关，不是铸件总收缩量的线性函数 |
| 5 | `eff` 与尺寸、形状**无关** | ⚠️ 是查表常数；真实补缩效率与冒口形状/保温条件相关 |
| 6 | `sphere_head` 的 `H ≥ r` 修正不触发 | ❌ **`hd < 0.5` 时触发** ⇒ 解析式失效（§5.6）|

### 5.5 `D_req` 与现有 `D`、`H`、`f` 的关系（127.txt §五.7）

**`D_req` 与 `Mc` 完全无关**（§5.2：只依赖 `needVol`、`eff`、形状、`hd`）——
**已实测**：固定 `cw=0.5` 扫 `Mc ∈ {0.5,1,2,5,20,99}`，`D_req` **逐位不变** ✓。

而模数路径（`cyl, hd=1`：`DfromM(Mr) = 6·Mr`）给出 `D ≈ 6·Mc·f`。两条同时满足要求：

```
6·Mc·f ≥ D_req   ⇒   f_req = D_req / (6·Mc)   ∝ 1/Mc
```

| `Mc` | `f_req`（夹具 cw=77.56） | 需要的档数 N | 生产上限 N=50（f≤3.55） |
|---|---|---|---|
| 0.5 | **47.970** | 939 | ★ **不可达** |
| 1 | 23.985 | 459 | ★ 不可达 |
| 2 | 11.993 | 219 | ★ 不可达 |
| 5 | 4.797 | 75 | ★ 不可达 |
| 10 | 2.399 | 27 | 可达 |
| 30 | 0.800 | — | 可达 |

**⇒ 独立复现并确认 V2.0-14 §5.3 的结论：`f_req` 在 `Mc → 0` 时发散，抬高 `f` 上限的方向是错的。**
本阶段**未做任何修改**，仅确认。

### 5.6 对不同形状 / `hd` / 取整规则的适用性（127.txt §五.8）

**（a）解析 `D_req` vs "含取整口径的最小可行整数"** —— 4 形状 × 4 `hd` × 4 `cw` = 64 组：

| 结果 | 组数 |
|---|---|
| `取整口径最小整数 == ceil(D_req)` | **62 / 64** |
| 比 `ceil(D_req)` **小 1 mm** | **2 / 64** |
| 比 `ceil(D_req)` **大** | **0 / 64** |

两处 −1 mm 的**原因相同**：`H = round(D·hd)` **向上取整**，实际体积大于 `D·hd` 的理想值：

- `cyl hd=0.8 cw=5`：`D_req=62.160 → ceil=63`，但 `D=62` 时 `H=round(49.6)=50`（↑），体积够用；
- `square hd=1.5 cw=200`：`D_req=159.059 → ceil=160`，但 `D=159` 时 `H=round(238.5)=239`（↑），体积够用。

**⇒ `D_req` 是连续解，取整方向可上可下 ⇒ 它只能作"下界参考"，不是"该用多大"的最终答案。**
（偏差上界实测 **≤1 mm**。）

**（b）`sphere` 与 `hd` 无关** ✅ —— `riser.js:117` 强制 `h = d`，所以 4 个 `hd` 的值完全相同（表中 4 行同值）。

**（c）`sphere_head` 在 `hd < 0.5` 时解析式失效** ★ ——
`hd=0.2` 实测：`D=70, H=35`，**实际 `hd = 0.500`**（`H` 被抬到 `≥ r`）。
此时 `k` 应为 `π/12 = 0.261799`，而公式 `π(3·0.2−0.5)/12 = π/120 = 0.026180` ——
**偏小 10 倍**，会**严重高估** `D_req`（并随 `hd→1/6` 趋于 0 甚至变号）。

### 5.7 无解 / 极端值 / 非法输入 / 数值精度（127.txt §五.9）【实测·脚本】

| 情形 | 结论 |
|---|---|
| `cw = 0`（未填铸件重量） | `needVol = 0` ⇒ **体积约束不存在**，`volOk` 恒 `true` ⇒ **`D_req` 无定义（应为 0 或 `null`，不是数字）** |
| `Mc = 0` 或 `< 0` | `runRiser` 返回 `null` ⇒ 无尺寸可言 |
| 未知 `shape` | 返回 `null`（**不是抛异常** —— V2.0-15 修的契约，本阶段**只读复核通过**）|
| `hd < 0.5`（`sphere_head`） | 解析式**失效**（§5.6c）。**实现 `D_req` 时必须特判** |
| 极大 `cw`（如 1000 t） | `D_req = 3375 mm` —— **数值不发散**（三次根），但**工程上不可实现**。应给上界提示而非硬算 |
| 数值精度 | `needVol` 跨 **15 个数量级**（1e-6 ~ 1e9）时三次根往返最大相对误差 **4.24e-16** ⇒ **无精度问题** |
| `eff` 显式覆盖 | 生效。`eff=35%` 时夹具 `D_req` 由 **143.91 → 106.03 mm**（发热保温冒口） |

### 5.8 ★★ `D_req` 能说明什么 / 不能说明什么（127.txt §五.10）

**必须明确区分四件事 —— 本阶段逐一给出状态：**

| 层次 | 状态 | 依据 |
|---|---|---|
| ① **数学推导成立** | ✅ **成立** | §5.2；`k` 表在 4×5×5 点上验证，相对偏差 ≤3e-16 |
| ② **与当前程序公式一致** | ✅ **一致** | §5.1 逐项对照 `riser.js`；§5.3 翻转点实测与解析重合（9e-4 mm）|
| ③ **当前程序能稳定计算** | ✅ **能** | §5.7 精度跨 15 个数量级无损失；退化输入均有明确行为（`null` / 恒 `true`）|
| ④ **真实铸件已经验证** | ❌ **完全没有** | **没有任何真实铸件数据**（§4 模板 0 条记录）。①②③ **都不蕴含 ④** |

**能说明的：**
- 在"`effV ≥ needVol` 且 `Vr = k·D³`"这套模型内，体积约束**有唯一解**，且**解与 `Mc` 无关**；
- 撞 `f` 上限时，当前 `D` 距"体积上够用的直径"差多少 ⇒ 用户可判断"加大冒口是否现实"；
- `f_req ∝ 1/Mc` ⇒ **单纯抬高 `f` 上限不是正确方向**（方向性结论）。

**不能说明的（不得写进用户界面）：**
- ❌ `D_req` 是否等于"**真实**能补缩的直径" —— 取决于 `RISER_EFF`（14/20/25/35%）这套经验值
  与真实冒口的对应关系，**代码里没有任何实测标定**；
- ❌ 缩孔是否真的不会发生 —— 体积守恒只是**必要条件**，不含温度梯度、冒口位置、浇注温度、
  砂型/金属型、冷铁等真实因素；
- ❌ `needVol = Vc × shrink` 用体收缩率近似"整件补缩量"是否成立 —— 实际补缩量与热节位置、
  凝固顺序有关，不是铸件总收缩量的线性函数。

**⇒ 下一阶段实现 `D_req` 时的措辞底线**：只能表述为
**"满足当前算法体积约束所需的直径"**，**不得**表述为"保证不缩孔的直径"。
