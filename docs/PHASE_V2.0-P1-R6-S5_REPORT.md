## 4. 分析/结果合并后的完整交互流程

### 4.1 顶部结构与入口

- 流程条由 5 步变为 **4 步**：① 模型 / ② 分析条件 / ③ 工艺设计 / ④ 分析并查看结果。
- 删除独立的 ⑤「结果」节点与顶部 `#dc_rerun` 按钮；顶部只保留一个主操作按钮。
- 主按钮文案随真实状态：
  - 未导入 STL：选择 STL 文件；
  - 参数未齐：确认工艺参数；
  - 分析中：正在分析…（禁用）；
  - 有有效结果且在模型视图：**分析并查看结果**（点击直接查看，不重跑）；
  - 结果过期：**重新分析并查看结果**；
  - 已在结果视图且结果有效：**重新分析**（显式重跑）。

### 4.2 点击后的真实流程

```text
点击 ④ / 主按钮
  ├─ state.busy → 直接返回（防并发）
  ├─ 结果有效（lastRun.ok && stale=0）且无草稿 → 直接切结果视图（不重复分析）
  ├─ 有未保存草稿 → 明确确认
  │    ├─ 取消 → 打开参数面板定位第一处修改；不分析、不跳转、草稿保留
  │    └─ 确定 → 先保存，再分析
  ├─ 参数门禁 paramIssues() 非空 → 打开对应字段；不分析
  └─ runAnalysis()
       ├─ 成功 → 更新 state.results、清 stale、自动 setWorkspaceView('results')
       └─ 失败 → 保留旧结果、markAllStale、lastRun.ok=false、留在当前页面
```

### 4.3 保持不变的保护

- `state.busy` 并发保护；
- 250ms 重复点击去重；
- 空保存不会把所有结果误标过期；
- 保存只写参数、不分析；
- 结果页内联参数仍保留 600ms 自动重算（本阶段未改，见 §11）。

## 6. H/D 选择的实现方式与计算规则核查

### 6.1 实现

1. `CastingProject.process.hdRatio`：默认 `1.0`、`editable`；旧项目由 `mergeDeep(defaultProject(), saved)` 自动补齐。
2. `calcManifest` riser 调用：
   ```js
   const hdNum = Number(proj.getV('process.hdRatio'));
   const hdRatio = Number.isFinite(hdNum) && hdNum > 0 ? hdNum : 1.0;
   // runRiser({ ..., hd_ratio: hdRatio, ... })
   ```
   旧项目/非法值回退 1.0，保证既有结果逐位不变。
3. 参数面板：H/D 四档 `0.8 / 1.0 / 1.2 / 1.5`，与独立冒口计算器一致；数值下拉按 number 比较，避免 `'1.0'` 与 `1` 不匹配导致默认显示 0.8（本阶段实测并修正）。
4. 球形：隐藏 H/D 字段，显示 `H ≡ D` 说明；已保存的 hd 值保留但不参与几何，切回柱/方/球顶柱后仍可使用。
5. 结果页/报告：显示**实际** `H / D`（由最终整数尺寸计算）；与名义值不同时括号标名义值；球形写 `H ≡ D`。

### 6.2 计算规则核查

- `calcs/riser.js` **一行未改**：它已经接受任意正 `hd_ratio`，`H = round(D × hd)`，球顶柱 `H ≥ R`，球形 `H ≡ D`。
- `Mr_target = Mc × 1.2` 未改；H/D 只改变几何尺寸分配，不改变目标模数。
- 默认 1.0 时，设计中心结果与直接 `runRiser(hd=1.0)` 逐位一致（S5 Node 用例 1）。
- 四形状 × 四比例 × 三个 Mc 水平的 Node 用例验证：`H` 由整数 D 导出、球形 H≡D、球顶柱 H≥R、D 为最小可行整数档、`Mr_act ≥ Mr_target`。
- 浏览器实测（cube50 / Mc=25）：H/D 1.0 → D=180/H=180；H/D 1.5 → D=160/H=240；`Mr_target` 不变。
- **49 个历史 riser 用例**：它们是 V2.0-22 已重基线的历史期望，测试直接调用 `runRiser` 且显式 `hd_ratio: 1.0`；本方案默认路径仍为 1.0。**预期重基线 0 例**；全量回归用于证明，不允许改期望制造通过。详见 `docs/PHASE_V2.0_HDRATIO_PLAN.md` §5。
- 冻结授权：S5-05 命令明确要求开放 H/D；唯一必要改动是 `calcManifest` 的调用点读取，未改 `riser.js` 算法。改动前已在 `PHASE_V2.0_HDRATIO_PLAN.md` 报告证据与最小方案。

### 8.1 保温冒口：40% 的来历与适用条件

**书中原文（`translated.md:9211`）**：

> “一个圆柱形绝热冒口的直径仅为 0.63D，而砂型冒口的直径为 D。因此，这种特殊的绝热冒口体积仅为砂型冒口的 40%。”

**确认的工程含义**：

- 这是**当前可达到效果的参考值**，不是通用设计系数；
- 0.63D 与 D 是**同高度圆柱冒口**的直径对比；体积比 ≈ 0.63² = 0.397 ≈ 40%；
- 书中紧接着要求：使用保温/发热材料确定最小冒口尺寸时，**应查阅制造商产品目录**；产品在不断开发；
- 该结论的前提是保温套/发热套确实提高了冒口的有效模数；换成其他合金、其他冒口形状、其他保温材料，比例不保证成立；
- 书中没有说“所有保温冒口都可以把普通冒口体积乘以 0.4”，也没有给出与 `Mr_target = 1.2 × Mc` 的直接换算。

**与当前代码的关系**：

- 当前 `calcs/riser.js` 只有按形状的补缩效率 `RISER_EFF`，没有保温套类型/制造商参数；
- 当前设计中心没有“保温冒口”选项；
- 直接写入 `Vr × 0.4` 会把一个**特定产品/特定条件下的经验参考**变成通用规则，违反“未知工程参数不编造”。

**建议的后续方案（不在本阶段实现）**：

1. 把保温冒口作为**独立冒口类型/保温套选项**，而不是修改普通冒口算法；
2. 必要输入：保温套类型/制造商、合金、铸件模数/热节、冒口形状与 H/D、浇注温度、接触/颈结构；
3. 计算口径优先采用**制造商给出的有效模数增益或等效补缩效率**；若只有体积缩减系数，必须注明来源、适用条件，并显示“估算值，需向供应商确认”；
4. 默认关闭；没有来源数据时显示“暂不能可靠给出”，不显示 40%；
5. 不改变普通冒口的 `Mr_target = 1.2 × Mc` 与现有尺寸反求。

### 8.2 冒口颈：当前实现与可复用资料

**当前代码现状**：

- `calcs/riser.js:11-15`：材料表 `neck_k` = 灰铁 0.75、球铁 1.0、铸钢 1.1、铝合金 1.0、铜合金 1.0；
- `calcs/riser.js:292-294`：`M_neck = Mc × neck_k`；`d_neck = round(M_neck × 4)`（圆颈 `M = d/4`）；
- 独立计算器给出“颈长建议 ≈0.5~1.0 倍颈径”（`riserView.js:274`），但**没有颈长输入**，也没有连接形式/热节校核；
- 没有“铸件-颈-冒口”模数比 1.0:1.1:1.2 的显式校核（当前只算颈径）。

**书中可复用依据**：

- `translated.md:9351`：冒口通常通过冒口颈连接，颈模数介于铸件与冒口之间；铸件:颈:冒口模数比常取 **1.0:1.1:1.2**（Beeley 1972）；
- 同一段：由于热节效应与相邻铸件/冒口的热传导，颈可以小于该表面下限；Sciama（1975）：
  - 钢：颈径可减小到 **0.5D**，前提是颈长 ≤ **0.1D**；
  - 铜基/铝基：颈长可增加近一倍而不出现问题；
  - 外推：钢 **0.25D** 时颈长 ≤ **0.03D**；铜/铝 0.25D 时颈长 ≤ **0.06D**；
  - Washburn 砂芯典型尺寸：厚 0.1D、中心孔 0.4D（Wlodawer/Beeley）；
- 这些是**特定实验条件**（材料、冒口模数接近铸件 1.5 倍、长度限制）下的结果；书中明确提醒 Sciama 的结果可能偏乐观，实际铸造环境应保守。

**建议的后续方案（不在本阶段实现）**：

1. 保留当前“颈模数/颈径”作为默认输出，不擅自改成 0.25D/0.5D；
2. 未来增加**可选颈长 + 连接形式**输入，输出“颈长/颈径比是否落在已验证范围”的提示；
3. 必要输入：材料、冒口 D、`M_neck`、颈长、连接圆角/座结构、是否用 Washburn 芯；
4. 只在有明确适用范围时给出参考，不能把 Sciama 的外推值当通用规则；
5. 不改变现有 `neck_k` 材料表，除非有新的工程依据和回归基线。

### 8.3 补缩长度：当前系统是否具备可靠计算条件

**当前代码现状**：

- 没有补缩长度/补缩距离模型；`calcs/riser.js` 的旧体积校核按**整件净重**折算，不是 feeding zone（`docs/PHASE_V2.0-02_VOLUME_CHECK_AUDIT.md` 已明确 region ≠ feeding zone，且当前没有温度场、凝固时间、补缩距离、凝固方向、冷铁耦合）；
- 没有合金凝固区间、温度梯度、铸型/冷铁条件、允许疏松水平等输入；
- 因此**不能**用热点区域体积或整件净重替代补缩长度计算。

**书中可复用依据**：

- `translated.md:9375-9423`：Pellini 等人在湿砂型碳钢板上得到补缩距离 `L = 4.5T`，其中 2.5T 来自铸件边缘激冷，2.0T 来自冒口；加冷铁可使补缩距离增加固定 50 mm；增大冒口超过最佳尺寸对致密性无益；
- Johnson & Loper（1969）对 12.5 mm 以上截面：平板 `L = 72√m − 140`，棒材 `L = 80√m − 84`（m 为截面模数，mm）；
- 数据主要适用于**湿砂型、低碳钢**；Pellini 原始数据仅 50–200 mm 厚截面；
- 非铁合金需极谨慎：Al/Cu 因高导热/低强度/固态补缩可有很长甚至“几乎无限”的补缩距离；宽凝固区间合金（如锡青铜）行为可能相反；
- 补缩距离的定义对可检测/可容忍的疏松水平敏感；金属洁净度（双氧化膜、气体）会显著影响；
- 超过补缩距离后，致密长度可能远小于公式预测值。

**建议的后续方案（不在本阶段实现）**：

1. **不做通用补缩长度计算**；当前输入不足以支撑对任意合金/任意铸型的可靠数字；
2. 若未来要做，先做**钢件参考模块**：
   - 明确限定：湿砂型、低碳钢、平板/棒材、截面模数/厚度范围、无/有冷铁；
   - 输出 `L = 4.5T` 或 Johnson–Loper 参考值，并显示“参考值，不是致密性保证”；
   - 对超出适用范围的材料/铸型显示“暂无法可靠估算”；
3. 最低输入要求：合金及凝固区间类别、截面厚度/模数、铸型材料、冷铁、浇注温度、允许疏松水平、金属洁净度（至少定性）；
4. 先用真实件基准（`data/riser-benchmark/cases.csv`）验证，再考虑进入正式计算；当前 cases.csv 仍 0 条。

### 8.4 本阶段结论

- 三项都**没有**新增正式工程计算；
- 保温冒口的 40% 是**特定保温套/同高度圆柱**的经验参考，不能直接写成通用系数；
- 冒口颈已有可解释的模数法，但缺少颈长/连接校核；Sciama/Beeley 数据可作为未来可选模块的依据，不能直接硬编码；
- 补缩长度在当前数据条件下**无法可靠计算**；应保持“暂不能可靠估算”，而不是编造数字。
